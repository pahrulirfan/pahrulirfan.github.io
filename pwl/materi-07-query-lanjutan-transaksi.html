1. Kueri Lanjutan: Paginasi, Filter, Pengurutan Indikator 4.5

Kita lanjutkan api-mahasiswa dari Pertemuan 6 yang sudah tersambung ke MySQL. Saat ini GET /mahasiswa mengembalikan semua data sekaligus. Untuk ribuan data itu tidak realistis: klien menunggu lama dan boros bandwidth. Kita lengkapi bertahap, dan setiap tahap langsung diuji di Postman: paginasi, filter, lalu pengurutan.

1.1 Siapkan Data yang Lebih Banyak

Paginasi baru terasa kalau datanya banyak. Struktur tabel mahasiswa tidak berubah dari Pertemuan 6; yang kita tambah hanya barisnya, dari 3 menjadi 25. Buka phpMyAdmin, pilih database api_mahasiswa, tab SQL, lalu jalankan:

1.2 Paginasi

Paginasi artinya membagi data menjadi halaman. Klien menyebut halaman berapa dan berapa data per halaman; server menerjemahkannya menjadi skip (lompati) dan take (ambil):

Query stringskiptakeHasil
?halaman=1&ukuran=505data ke-1 sampai ke-5
?halaman=2&ukuran=555data ke-6 sampai ke-10
?halaman=3&ukuran=5105data ke-11 sampai ke-15

Rumusnya skip = (halaman - 1) * ukuran. Klien juga perlu tahu jumlah seluruh data supaya bisa menampilkan “halaman 2 dari 5”, jadi kita ambil data dan hitung total sekaligus.

Langkah 1 — Lapis data

Di src/data/mahasiswa.data.js, ganti fungsi semua() dengan dua fungsi baru. Fungsi lain tidak berubah.

import { prisma } from '../lib/prisma.js';

export function daftar({ where, orderBy, skip, take }) {
    return prisma.mahasiswa.findMany({ where, orderBy, skip, take });
}

export function hitung(where) {
    return prisma.mahasiswa.count({ where });
}

export function cariById(id) {
    return prisma.mahasiswa.findUnique({ where: { id } });
}

export function cariByNim(nim) {
    return prisma.mahasiswa.findUnique({ where: { nim } });
}

export function simpan(input) {
    return prisma.mahasiswa.create({ data: input });
}

Langkah 2 — Lapis service

Ganti fungsi daftarMahasiswa (fungsi detailMahasiswa dan buatMahasiswa tetap):

// src/services/mahasiswa.service.js — fungsi daftarMahasiswa
export async function daftarMahasiswa(query) {
    const halaman = Math.max(Number(query.halaman) || 1, 1);
    const ukuran = Math.min(Math.max(Number(query.ukuran) || 10, 1), 100);

    const [hasil, total] = await Promise.all([
        data.daftar({ skip: (halaman - 1) * ukuran, take: ukuran }),
        data.hitung(),
    ]);

    return {
        data: hasil,
        meta: { halaman, ukuran, total, totalHalaman: Math.ceil(total / ukuran) },
    };
}
  • Math.max(...) dan Math.min(...) merapikan masukan yang tidak masuk akal: ?halaman=abc menjadi halaman 1, ?ukuran=999 dibatasi 100.
  • findMany dan count tidak saling bergantung, jadi dijalankan serentak dengan Promise.all (Pertemuan 3).

Langkah 3 — Lapis controller

Service sekarang sudah mengembalikan { data, meta }, jadi controller tinggal meneruskannya:

// src/controllers/mahasiswa.controller.js
export async function daftar(req, res) {
    res.json(await service.daftarMahasiswa(req.query));
}

1.3 Filter

Filter menyaring data dengan syarat. Di Prisma, syaratnya ditulis di where. Beberapa operator yang sering dipakai:

Operator PrismaArtinyaPadanan SQL
{ semester: 6 }sama dengansemester = 6
gte / ltelebih besar sama / lebih kecil sama>= / <=
gt / ltlebih besar / lebih kecil> / <
containsmengandung teksLIKE '%...%'
in: [...]salah satu dari daftarIN (...)

Kita dukung tiga filter: semester, ipkMin, dan cari (nama). Di daftarMahasiswa, tambahkan where dan teruskan ke kedua pemanggilan data, supaya total ikut terfilter:

// src/services/mahasiswa.service.js — di dalam daftarMahasiswa, tambahkan where
const { semester, ipkMin, cari } = query;

const where = {
    ...(semester && { semester: Number(semester) }),
    ...(ipkMin && { ipk: { gte: Number(ipkMin) } }),
    ...(cari && { nama: { contains: cari } }),
};

const [hasil, total] = await Promise.all([
    data.daftar({ where, skip: (halaman - 1) * ukuran, take: ukuran }),
    data.hitung(where),                                  // hitung dengan filter yang sama
]);

Pola ...(kondisi && { field }) adalah spread bersyarat (Pertemuan 2): kalau parameter tidak dikirim, yang disebar adalah nilai kosong sehingga field itu tidak ikut masuk ke where. Dengan begitu tidak perlu banyak if.

Huruf besar atau kecil? Di MySQL, pencarian teks dengan collation bawaan (utf8mb4_unicode_ci) sudah tidak membedakan huruf besar/kecil, jadi ?cari=AN dan ?cari=an sama saja. Opsi mode: 'insensitive' yang ada di banyak tutorial hanya untuk PostgreSQL dan tidak dipakai di MySQL.

1.4 Pengurutan

Pengurutan memakai orderBy: nama kolom dan arahnya (asc naik, desc turun). Klien menyebut kolom lewat ?urutkan=ipk&arah=desc.

Ada satu hal yang perlu diwaspadai: nama kolom datang dari pengguna. Kalau langsung dipakai, ?urutkan=password atau salah ketik akan membuat Prisma melempar error aneh (500). Karena itu kita hanya mengizinkan kolom dari daftar yang kita tentukan. Berikut bentuk akhir bagian atas service (menggabungkan paginasi, filter, dan pengurutan):

// src/services/mahasiswa.service.js — bagian atas file (sisanya tidak berubah)
import * as data from '../data/mahasiswa.data.js';
import { AppError } from '../utils/AppError.js';

const KOLOM_URUT = ['nama', 'nim', 'ipk', 'semester', 'createdAt'];

export async function daftarMahasiswa(query) {
    const { semester, ipkMin, cari, urutkan = 'nama', arah = 'asc' } = query;
    const halaman = Math.max(Number(query.halaman) || 1, 1);
    const ukuran = Math.min(Math.max(Number(query.ukuran) || 10, 1), 100);

    if (!KOLOM_URUT.includes(urutkan)) {
        throw new AppError(400, `urutkan harus salah satu dari: ${KOLOM_URUT.join(', ')}`, 'QUERY_TIDAK_VALID');
    }

    const where = {
        ...(semester && { semester: Number(semester) }),
        ...(ipkMin && { ipk: { gte: Number(ipkMin) } }),
        ...(cari && { nama: { contains: cari } }),
    };

    const [hasil, total] = await Promise.all([
        data.daftar({
            where,
            orderBy: { [urutkan]: arah === 'desc' ? 'desc' : 'asc' },
            skip: (halaman - 1) * ukuran,
            take: ukuran,
        }),
        data.hitung(where),
    ]);

    return {
        data: hasil,
        meta: { halaman, ukuran, total, totalHalaman: Math.ceil(total / ukuran) },
    };
}

2.2 Tulis Skema dan Jalankan Migrasi

Di prisma/schema.prisma, tambahkan satu baris pada model Mahasiswa dan dua model baru:

"keyword">model Mahasiswa {
  // ...field yang sudah ada tidak berubah, tambahkan SATU baris ini:
  pendaftaran Pendaftaran[]

  @@map("mahasiswa")
}

"keyword">model Kelas {
  id    Int    @id @default(autoincrement())
  nama  String
  kuota Int    @default(30)

  pendaftaran Pendaftaran[]

  @@map("kelas")
}

"keyword">model Pendaftaran {
  id            Int      @id @default(autoincrement())
  mahasiswaId   Int
  kelasId       Int
  tanggalDaftar DateTime @default(now())

  mahasiswa Mahasiswa @relation(fields: [mahasiswaId], references: [id])
  kelas     Kelas     @relation(fields: [kelasId], references: [id])

  @@unique([mahasiswaId, kelasId])
  @@map("pendaftaran")
}

@relation(fields: [mahasiswaId], references: [id]) artinya “kolom mahasiswaId menunjuk ke id di tabel mahasiswa” (foreign key). Baris pendaftaran Pendaftaran[] di sisi lain hanyalah penanda “satu mahasiswa punya banyak pendaftaran”; ia tidak membuat kolom baru. @@unique([mahasiswaId, kelasId]) adalah aturan pasangan unik tadi.

2.4 Menampilkan Pendaftaran Beserta Mahasiswa dan Kelasnya (JOIN)

Tabel pendaftaran sendiri hanya berisi angka (mahasiswaId: 1, kelasId: 1), tidak enak dibaca. Untuk menampilkan nama mahasiswa dan nama kelas, data tiga tabel perlu digabung. Operasi itu bernama JOIN. Di SQL mentah ditulis begini:

SELECT p.id, m.nama AS mahasiswa, k.nama AS kelas
FROM pendaftaran p
JOIN mahasiswa m ON m.id = p.mahasiswaId
JOIN kelas k ON k.id = p.kelasId;

Di Prisma kita tidak menulis JOIN. Cukup menyebut relasi mana yang ikut dibawa lewat include. Buat empat file kecil (pola yang sama dengan mahasiswa):

import { prisma } from '../lib/prisma.js';

export function semua() {
    return prisma.pendaftaran.findMany({
        include: { mahasiswa: true, kelas: true },
    });
}
// src/services/pendaftaran.service.js
import * as data from '../data/pendaftaran.data.js';

export async function daftarPendaftaran() {
    return data.semua();
}
// src/controllers/pendaftaran.controller.js
import * as service from '../services/pendaftaran.service.js';

export async function daftar(req, res) {
    const hasil = await service.daftarPendaftaran();
    res.json({ data: hasil });
}
// src/routes/pendaftaran.routes.js
import express from 'express';
import * as ctrl from '../controllers/pendaftaran.controller.js';

const router = express.Router();

router.get('/', ctrl.daftar);

export default router;

Lalu pasang router di index.js, di bawah router mahasiswa:

// index.js
import pendaftaranRoutes from './src/routes/pendaftaran.routes.js';

app.use('/mahasiswa', mahasiswaRoutes);
app.use('/pendaftaran', pendaftaranRoutes);   // ← baru

Berapa kueri yang dijalankan?

Kita bisa melihat SQL yang dikirim Prisma. Sementara, ubah src/lib/prisma.js menjadi new PrismaClient({ adapter, log: ['query'] }), kirim ulang GET /pendaftaran, lalu lihat terminal server (ditulis ringkas):

prisma:query SELECT ... FROM `pendaftaran` WHERE 1=1 prisma:query SELECT ... FROM `kelas` WHERE `kelas`.`id` IN (?,?) prisma:query SELECT ... FROM `mahasiswa` WHERE `mahasiswa`.`id` IN (?,?) GET /pendaftaran -> 200 (79 ms)

Tiga kueri: satu untuk pendaftaran, satu untuk semua kelas yang terkait, satu untuk semua mahasiswa yang terkait. Jumlahnya tetap tiga berapa pun banyak pendaftarannya. Bandingkan dengan cara yang sering dilakukan pemula:

// ❌ 1 kueri untuk daftar, lalu 1 kueri LAGI untuk setiap pendaftaran
const daftar = await prisma.pendaftaran.findMany();
for (const p of daftar) {
    p.mahasiswa = await prisma.mahasiswa.findUnique({ where: { id: p.mahasiswaId } });
}
// 100 pendaftaran → 101 kueri ke database

// ✅ Tetap 3 kueri, berapa pun jumlah barisnya
const daftar2 = await prisma.pendaftaran.findMany({
    include: { mahasiswa: true, kelas: true },
});

Versi pertama disebut masalah N+1: satu kueri untuk daftar, ditambah satu kueri untuk setiap barisnya. Dengan 10 baris terasa sama cepat, tetapi dengan ribuan baris endpoint bisa menunggu berdetik-detik. Gejalanya khas: await prisma... di dalam for atau map. Begitu melihatnya, cari cara membawanya keluar dengan include atau select. Kembalikan src/lib/prisma.js seperti semula setelah selesai melihat log.

Checkpoint: tabel kelas dan pendaftaran ada dan berisi data, dan GET /pendaftaran menampilkan nama mahasiswa dan nama kelas dalam satu respons.

3. Transaksi Basis Data Indikator 4.6

Sekarang kita buat endpoint untuk mendaftar kelas. Satu pendaftaran berarti dua langkah: (1) buat baris di tabel pendaftaran, (2) kurangi kuota kelas sebanyak 1. Kalau langkah kedua gagal setelah langkah pertama berhasil, data jadi tidak konsisten: mahasiswa tercatat mendaftar, tetapi kuota tidak berkurang.

3.1 Tanpa Transaksi dan Dengan Transaksi

1
INSERT INTO pendaftaran ... — berhasil
2
UPDATE kelas SET kuota = kuota - 1 ... — gagal (koneksi putus)
❌ Tanpa transaksi: mahasiswa tercatat daftar, tapi kuota TIDAK berkurang. Data tidak konsisten
1
BEGIN TRANSACTION
2
INSERT INTO pendaftaran ... — berhasil
3
UPDATE kelas SET kuota = kuota - 1 ... — gagal
✅ Dengan transaksi: SELURUH transaksi di-ROLLBACK. Langkah 2 ikut dibatalkan, database kembali seperti semula

Aturan sederhananya: setiap kali operasi menyentuh lebih dari satu tabel dan semuanya harus berhasil bersama-sama (atau gagal bersama-sama), bungkus dengan transaksi. Di Prisma namanya $transaction.

3.2 Praktik: Endpoint Mendaftar Kelas

Endpoint-nya POST /pendaftaran dengan body { "mahasiswaId": 3, "kelasId": 1 }. Urutan kerja di dalam transaksi:

  1. Pastikan mahasiswanya ada (kalau tidak: 404).
  2. Pastikan kelasnya ada (kalau tidak: 404) dan kuotanya masih lebih dari 0 (kalau tidak: 409).
  3. Buat baris pendaftaran.
  4. Kurangi kuota kelas 1.

Langkah 1 — Validasi masukan

Bentuk body diperiksa Joi, seperti di Pertemuan 5:

import Joi from 'joi';

export const skemaPendaftaran = Joi.object({
    mahasiswaId: Joi.number().integer().positive().required(),
    kelasId:     Joi.number().integer().positive().required()
});

Langkah 2 — Service dengan transaksi

Ubah src/services/pendaftaran.service.js (fungsi daftarPendaftaran tetap, tambahkan daftarKelas):

import { prisma } from '../lib/prisma.js';
import * as data from '../data/pendaftaran.data.js';
import { AppError } from '../utils/AppError.js';

export async function daftarPendaftaran() {
    return data.semua();
}

export async function daftarKelas(mahasiswaId, kelasId) {
    try {
        return await prisma.$transaction(async (tx) => {
            const mahasiswa = await tx.mahasiswa.findUnique({ where: { id: mahasiswaId } });
            if (!mahasiswa) throw new AppError(404, 'Mahasiswa tidak ditemukan', 'MAHASISWA_NOT_FOUND');

            const kelas = await tx.kelas.findUnique({ where: { id: kelasId } });
            if (!kelas) throw new AppError(404, 'Kelas tidak ditemukan', 'KELAS_NOT_FOUND');
            if (kelas.kuota <= 0) throw new AppError(409, 'Kuota kelas sudah penuh', 'KUOTA_PENUH');

            const pendaftaran = await tx.pendaftaran.create({
                data: { mahasiswaId, kelasId },
            });

            await tx.kelas.update({
                where: { id: kelasId },
                data: { kuota: { decrement: 1 } },
            });

            return pendaftaran;
        });
    } catch (err) {
        if (err.code === 'P2002') {   // UNIQUE (mahasiswaId, kelasId) dilanggar
            throw new AppError(409, 'Mahasiswa sudah terdaftar di kelas ini', 'SUDAH_TERDAFTAR');
        }
        throw err;
    }
}
  • Semua operasi di dalam transaksi memakai tx.namaModel, bukan prisma.namaModel. tx adalah “prisma versi transaksi” yang dioper ke callback.
  • Kalau ada satu saja yang throw, seluruh transaksi dibatalkan otomatis (rollback), dan errornya diteruskan keluar.
  • { decrement: 1 } berarti “kurangi nilai yang ada di database sebanyak 1”.
  • Bagian catch menerjemahkan error P2002 (pasangan mahasiswa-kelas sudah ada, dari @@unique) menjadi 409, seperti yang kita lakukan untuk NIM kembar di Pertemuan 6.

3.4 Membuktikan Rollback Bekerja

Mari buktikan bahwa langkah yang “sempat berhasil” benar-benar dibatalkan. Buat file coba-rollback.js di akar proyek:

import { prisma } from './src/lib/prisma.js';

const sebelum = await prisma.pendaftaran.count();

try {
    await prisma.$transaction(async (tx) => {
        await tx.pendaftaran.create({ data: { mahasiswaId: 4, kelasId: 1 } });
        console.log('di dalam transaksi :', await tx.pendaftaran.count(), 'pendaftaran');
        throw new Error('Sengaja gagal untuk membuktikan rollback');
    });
} catch (err) {
    console.log('error              :', err.message);
}

const sesudah = await prisma.pendaftaran.count();
console.log(`sebelum: ${sebelum}, sesudah: ${sesudah}`);
await prisma.$disconnect();
$ node coba-rollback.js di dalam transaksi : 5 pendaftaran error : Sengaja gagal untuk membuktikan rollback sebelum: 4, sesudah: 4

Di dalam transaksi, jumlah pendaftaran sempat menjadi 5 (baris baru berhasil dibuat), tetapi setelah error dilempar jumlahnya kembali 4. Cek juga di phpMyAdmin: tidak ada baris untuk mahasiswa 4 di kelas 1. Hapus file coba-rollback.js setelah dicoba.

4. Data Awal (Seed) yang Dapat Diulang Indikator 4.7

Sampai sekarang kita mengisi data lewat phpMyAdmin. Itu cukup untuk satu orang di satu komputer. Tetapi anggota kelompok lain butuh data contoh yang sama persis di database masing-masing, dan kalian sendiri mungkin ingin mengembalikan data ke kondisi awal setelah banyak percobaan. Seed adalah skrip yang mengisi data awal itu sekali jalan (padanan php artisan db:seed di Laravel).

4.1 Praktik: Buat Seed

Seed ini membuat ulang data yang tadi kita isi: 25 mahasiswa, 2 kelas, 2 pendaftaran. Buat prisma/seed.js:

import { prisma } from '../src/lib/prisma.js';

const NAMA = ['Andi', 'Budi', 'Citra', 'Dewi', 'Eko', 'Fitri', 'Gilang', 'Hana'];

async function main() {
    // Kosongkan dulu (tabel anak sebelum tabel induk) supaya seed aman dijalankan ULANG
    await prisma.pendaftaran.deleteMany();
    await prisma.mahasiswa.deleteMany();
    await prisma.kelas.deleteMany();

    await prisma.mahasiswa.createMany({
        data: [
            { id: 1, nim: 'F1D021001', nama: 'Andi', ipk: 3.75, semester: 6 },
            { id: 2, nim: 'F1D021002', nama: 'Budi', ipk: 3.2, semester: 6 },
            { id: 3, nim: 'F1D021003', nama: 'Citra', ipk: 3.9, semester: 4 },
            // id 4-25: dibuat dengan perulangan
            ...Array.from({ length: 22 }, (_, k) => {
                const i = k + 4;
                return {
                    id: i,
                    nim: `F1D0210${String(i).padStart(2, '0')}`,
                    nama: `${NAMA[i % 8]} ${i}`,
                    ipk: Math.round((2 + (i % 20) / 10) * 100) / 100,
                    semester: 1 + (i % 8),
                };
            }),
        ],
    });

    await prisma.kelas.createMany({
        data: [
            { id: 1, nama: 'Pemrograman Web Lanjut', kuota: 28 },
            { id: 2, nama: 'Basis Data', kuota: 1 },
        ],
    });

    await prisma.pendaftaran.createMany({
        data: [
            { id: 1, mahasiswaId: 1, kelasId: 1 },
            { id: 2, mahasiswaId: 2, kelasId: 1 },
        ],
    });

    console.log('Seed selesai');
}

main()
    .catch((err) => { console.error(err); process.exitCode = 1; })
    .finally(() => prisma.$disconnect());
  • Kosongkan dulu di awal (deleteMany), dengan urutan tabel anak sebelum induk (pendaftaran baru mahasiswa dan kelas), karena foreign key tidak membolehkan induk dihapus selagi masih ada anaknya. Inilah yang membuat seed dapat diulang.
  • id ditulis eksplisit supaya id data sama di semua komputer. Tanpa itu, id akan terus naik setiap seed dijalankan ulang.
  • 22 mahasiswa terakhir dibuat dengan perulangan, aturannya sama dengan perintah SQL di 1.1.
  • createMany menyimpan banyak baris dalam satu perintah.

4.2 Daftarkan dan Jalankan

Di Prisma 7, perintah seed didaftarkan di prisma.config.ts, di bawah migrations:

import 'dotenv/config';
import { defineConfig } from 'prisma/config';

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    seed: 'node prisma/seed.js',
  },
  datasource: {
    url: process.env.DATABASE_URL,
  },
});
$ npx prisma db seed Running seed command `node prisma/seed.js` ... Seed selesai 🌱 The seed command has been executed.

Jalankan sekali lagi: hasilnya tetap sama dan tidak ada error, tidak ada data dobel. Buka phpMyAdmin untuk memastikan: tabel mahasiswa berisi 25 baris, kelas 2 baris dengan kuota 28 dan 1, pendaftaran 2 baris. Kuota yang tadi berubah karena percobaan di Section 3 kembali ke kondisi awal.

Hati-hati: seed menghapus data. Jalankan hanya di database pengembangan milik sendiri. Untuk memulai dari kondisi benar-benar bersih (semua tabel dihapus dan dibuat ulang dari migrasi), ada npx prisma migrate reset; perintah ini menghapus semua data, jadi setelahnya jalankan npx prisma db seed lagi.
“Dapat diulang” adalah kata kuncinya: seed yang baik boleh dijalankan berkali-kali tanpa error dan tanpa data dobel. Bagi kelompok, cukup npx prisma migrate dev lalu npx prisma db seed untuk mendapatkan database yang sama dengan milik rekan.

5. Dokumentasi Endpoint Indikator 4.8

Endpoint yang tidak didokumentasikan menyulitkan siapa pun yang memakainya: diri kalian sendiri tiga minggu kemudian, dan rekan kelompok yang membangun antarmuka React di Pertemuan 11–12. Cukup satu file API.md di akar repositori; tidak perlu Swagger/OpenAPI penuh.

5.1 Format Minimal yang Wajib Ada

Untuk setiap endpoint: method dan path, parameter atau body, dan contoh respons berhasil serta gagal. Berikut contoh untuk dua endpoint yang baru kita bangun (nilai-nilainya diambil dari hasil Postman tadi):

# API Mahasiswa

## GET /mahasiswa
Daftar mahasiswa dengan paginasi, filter, dan pengurutan.

**Query params:**

| Parameter | Tipe   | Default | Keterangan                                   |
|-----------|--------|---------|----------------------------------------------|
| halaman   | number | 1       | Nomor halaman                                |
| ukuran    | number | 10      | Jumlah data per halaman (maksimal 100)       |
| semester  | number | -       | Saring berdasarkan semester                  |
| ipkMin    | number | -       | Hanya IPK >= nilai ini                       |
| cari      | string | -       | Nama mengandung teks ini                     |
| urutkan   | string | nama    | nama, nim, ipk, semester, atau createdAt     |
| arah      | string | asc     | asc atau desc                                |

**Respons 200:**

```json
{
  "data": [{ "id": 1, "nim": "F1D021001", "nama": "Andi", "ipk": 3.75, "semester": 6 }],
  "meta": { "halaman": 1, "ukuran": 10, "total": 25, "totalHalaman": 3 }
}
```

**Respons 400:** nilai `urutkan` tidak diizinkan (`QUERY_TIDAK_VALID`)

## POST /pendaftaran
Mendaftarkan mahasiswa ke kelas (mengurangi kuota).

**Header:** `x-api-key`

**Body:**

| Field       | Tipe   | Wajib | Keterangan |
|-------------|--------|-------|------------|
| mahasiswaId | number | ya    | id mahasiswa |
| kelasId     | number | ya    | id kelas     |

**Respons 201:** data pendaftaran yang baru dibuat
**Respons 401:** API key salah
**Respons 404:** mahasiswa atau kelas tidak ditemukan
**Respons 409:** sudah terdaftar, atau kuota penuh
**Respons 422:** body tidak valid
Cara cepat: jalankan endpoint di Postman, lalu salin contoh respons dari sana ke API.md. Dengan begitu dokumentasi pasti sesuai dengan perilaku API yang sebenarnya, dan file requests.http (Pertemuan 5) serta pengujian otomatis (Pertemuan 13) bisa merujuk ke dokumen yang sama.

6. Latihan Mandiri Latihan

Selesai kalau: GET /mahasiswa mendukung paginasi, filter, dan pengurutan; POST /pendaftaran menambah pendaftaran dan mengurangi kuota secara atomik; seed bisa dijalankan berulang tanpa error; dan API.md mendokumentasikan semua endpoint yang ada.

Latihan

  1. Tambahkan GET /kelas/:id yang menyertakan daftar mahasiswa terdaftar (pakai include lewat relasi pendaftaran).
  2. Tambahkan DELETE /pendaftaran/:id yang membatalkan pendaftaran dan mengembalikan kuota (increment). Wajib memakai transaksi juga. Buktikan di phpMyAdmin bahwa baris terhapus dan kuota bertambah.
  3. Tambahkan paginasi dan filter (Section 1) ke endpoint GET /pendaftaran, misalnya ?kelasId=1.
  4. Perluas prisma/seed.js dengan kelas ketiga, jalankan seed dua kali, lalu pastikan jumlah barisnya tidak berlipat.
