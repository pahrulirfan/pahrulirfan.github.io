1. Modul: Memecah Program Jadi Banyak File Indikator 2.1

Mengapa Perlu Modul?

Di Pertemuan 1–2, semua kode masih muat dalam satu file. Begitu proyek bertambah besar, cara itu berhenti bekerja: file jadi ribuan baris, nama fungsi bentrok, dan tidak ada yang tahu bagian mana yang boleh diubah tanpa merusak yang lain.

Modul adalah cara memecah program menjadi beberapa file, di mana setiap file hanya membuka sebagian isinya untuk dipakai file lain. Konsep ini sudah kalian kenal di PHP lewat require, include, dan autoload Composer — hanya sintaks dan aturannya yang berbeda.

Apa yang berubah dibanding PHP:
  • Di PHP, include menempelkan seluruh isi file. Di JavaScript, kalian memilih apa saja yang boleh keluar (export) dan apa yang mau diambil (import).
  • Semua yang tidak di-export bersifat privat bagi file itu — tidak bisa disentuh dari luar.
  • Satu modul hanya dijalankan sekali, walaupun di-import dari banyak tempat.

1.1 Dua Sistem Modul di Node.js

Node.js mendukung dua sistem modul. Kalian akan menemui keduanya di internet, jadi harus bisa membedakannya.

Aspek CommonJS (CJS) — gaya lama ES Modules (ESM) — standar resmi
Mengambil const x = require('./a') import x from './a.js'
Mengeluarkan module.exports = x export default x
Cara mengaktifkan Bawaan Node (tanpa konfigurasi) "type": "module" di package.json
Ekstensi file Boleh dihilangkan Wajib ditulis (./util.js)
Waktu dimuat Saat baris require dijalankan Sebelum kode berjalan (statis)
Top-level await ❌ Tidak bisa ✅ Bisa
Berlaku di browser ❌ Tidak ✅ Ya — sintaks yang sama
Di mata kuliah ini kita memakai ESM. Alasannya: ESM adalah standar resmi JavaScript, sintaksnya sama persis dengan yang nanti dipakai di React (Minggu 11), dan mendukung top-level await. CommonJS tetap dibahas karena banyak tutorial dan paket lama memakainya — kalian harus bisa mengenalinya, bukan memakainya.

1.2 Mengaktifkan ESM

Kita mulai dari proyek kosong. Proyek ini akan dipakai terus sampai akhir bagian 1, jadi buat satu kali saja. Langkahnya sama dengan Pertemuan 1:

$ mkdir latihan-modul $ cd latihan-modul $ npm init -y Wrote to .../latihan-modul/package.json

Sekarang buat file index.js (lewat editor atau terminal) yang langsung memakai sintaks import (node:os adalah modul bawaan Node, tidak perlu dipasang):

// index.js
import { platform } from 'node:os';

console.log('ESM aktif, berjalan di', platform());

Jalankan. Error di sini memang disengaja, supaya kalian mengenali gejalanya:

$ node index.js SyntaxError: Cannot use import statement outside a module

Penyebabnya: hasil npm init -y belum menyatakan sistem modul yang dipakai, sehingga Node menganggap semua file .js sebagai CommonJS, dan CommonJS tidak mengenal import. Buka package.json lalu tambahkan (atau ubah) kunci "type" menjadi "module":

// package.json
{
  "name": "latihan-modul",
  "version": "1.0.0",
  "type": "module",      // ← baris ini yang menentukan
  "main": "index.js"
}

Kalau lebih suka lewat terminal, satu perintah ini setara dengan mengedit filenya:

$ npm pkg set type=module

Jalankan lagi:

$ node index.js ESM aktif, berjalan di darwin

Kata terakhir bergantung komputer kalian: darwin (macOS), win32 (Windows), atau linux. Yang penting tidak ada error lagi.

Catatan: versi Node yang sangat baru kadang menebak sendiri bahwa sebuah file memakai ESM, sehingga error di atas tidak muncul. Jangan mengandalkan tebakan itu. Selalu tulis "type": "module" agar proyek berjalan sama di semua komputer dan server.

Dua bagian berikutnya memakai proyek latihan-modul ini: file-file baru (hitung.js, mahasiswa.js) dibuat di folder yang sama dengan index.js.

1.3 Named Export — Mengeluarkan Banyak Hal

console.log(subtotal(3, 25000));            // 75000
console.log(denganPajak(75000));            // 83250

// Mengambil semua sekaligus sebagai satu object

1.4 Default Export — Satu Hal Utama

// mahasiswa.js
export default class Mahasiswa {
    constructor(nim, nama) {
        this.nim = nim;
        this.nama = nama;
    }
}

// Boleh dicampur dengan named export
export const JURUSAN = 'Teknik Informatika';
// index.js — default diambil TANPA kurung kurawal
import Mahasiswa, { JURUSAN } from './mahasiswa.js';

const m = new Mahasiswa('F1D021001', 'Andi');
console.log(m.nama, JURUSAN);
Kesalahan paling sering: tertukar antara ada dan tidak adanya kurung kurawal.
  • import { x } from './a.js' → mengambil named export bernama x
  • import x from './a.js' → mengambil default export, namanya bebas
  • Kalau salah, nilainya jadi undefined tanpa pesan error yang jelas

2. Sinkron vs Asinkron Indikator 2.5

Ini adalah konsep paling penting di seluruh pertemuan ini, dan yang paling berbeda dari PHP. Kalau bagian ini dipahami, sisanya hanya soal sintaks.

  • Sinkron — setiap baris kode menunggu baris sebelumnya selesai dulu sebelum lanjut. Kalau ada satu baris yang lambat (misalnya menunggu jawaban database), semua baris sesudahnya ikut tertahan.
  • Asinkron — sebuah pekerjaan yang lambat dititipkan untuk dikerjakan di "belakang layar", dan kode tidak menunggu di situ — ia langsung lanjut ke baris berikutnya. Hasil pekerjaan yang dititipkan tadi baru diambil belakangan, ketika sudah siap.

Perbedaan ini paling terasa saat dibandingkan langsung: PHP (yang sudah kalian kenal) memilih jalan sinkron, Node.js memilih jalan asinkron. Alasannya bukan soal selera, melainkan cara keduanya melayani banyak pengunjung sekaligus:

2.1 Cara PHP Bekerja

Saat kalian menulis kode PHP seperti ini:

// PHP
$data = file_get_contents('data.json');   // tunggu sampai selesai
$hasil = $db->query('SELECT * FROM users'); // tunggu sampai selesai
echo "Selesai";

Setiap baris menunggu baris sebelumnya benar-benar selesai. Selama menunggu database, proses PHP itu diam — tidak melakukan apa pun. Ini tidak masalah, karena web server menyediakan satu proses terpisah untuk setiap pengunjung. Pengunjung lain dilayani proses lain.

2.2 Cara Node.js Bekerja

Node.js hanya punya satu thread untuk menjalankan kode kalian, dan thread itu melayani semua pengunjung sekaligus. Kalau thread tersebut ikut diam menunggu database, seluruh aplikasi berhenti untuk semua orang.

Karena itu Node memakai pendekatan berbeda: pekerjaan yang butuh menunggu dititipkan ke sistem, lalu kode lanjut jalan. Ketika hasilnya siap, Node kembali mengerjakannya.

Analogi warung kopi:
  • Cara sinkron (PHP) — barista menerima pesanan, menyeduh kopi sampai selesai, menyerahkannya, baru melayani pelanggan berikutnya. Antrean di belakang menunggu, walaupun mereka hanya mau memesan air putih.
  • Cara asinkron (Node.js) — barista menerima pesanan, menyalakan mesin kopi, lalu langsung melayani pelanggan berikutnya. Saat mesin berbunyi, ia kembali mengambil kopi itu dan menyerahkannya.
Baristanya tetap satu orang. Yang berubah adalah ia tidak berdiri diam saat menunggu mesin.

2.3 Apa Saja yang Asinkron?

Asinkron (menunggu sesuatu di luar) Sinkron (murni hitungan)
Membaca / menulis file map, filter, reduce
Kueri ke basis data JSON.parse, JSON.stringify
Memanggil API lain (fetch) Perhitungan matematika
Timer (setTimeout) Manipulasi string
Menerima permintaan HTTP Percabangan & perulangan biasa

Polanya sederhana: kalau harus menunggu sesuatu di luar proses Node — disk, jaringan, basis data — operasinya asinkron.

2.4 Praktik: Menghitung vs Memanggil API

Teorinya sudah cukup. Sekarang kita buktikan sendiri perbedaan sinkron dan asinkron lewat dua pekerjaan nyata: menghitung (murni kerja CPU, sinkron) dan memanggil API dari luar (menunggu jaringan, asinkron). Kita buat proyek baru bernama latihan-sinkron.

Langkah 0: Buat proyek

$ mkdir latihan-sinkron $ cd latihan-sinkron $ npm init -y $ npm pkg set type=module

Baris terakhir mengaktifkan ESM (lihat 1.2). Tidak ada paket yang perlu dipasang: fetch sudah bawaan Node.js (versi 18 ke atas), dan API yang dipanggil adalah jsonplaceholder.typicode.com, layanan contoh gratis yang mengembalikan data pengguna palsu. Kalian butuh koneksi internet untuk langkah 2 sampai 4.

Langkah 1: Menghitung (sinkron)

Buat file hitung-sinkron.js. Fungsi fibonacci sengaja ditulis dengan cara lambat supaya terasa berat di CPU:

// hitung-sinkron.js
function fibonacci(n) {
    return n < 2 ? n : fibonacci(n - 1) + fibonacci(n - 2);
}

console.log('1. Mulai menghitung...');
const mulai = Date.now();

const hasil = fibonacci(40);   // baris ini MENAHAN program sampai selesai

console.log('2. Hasil:', hasil);
console.log(`3. Selesai dalam ${Date.now() - mulai} ms`);
$ node hitung-sinkron.js 1. Mulai menghitung... 2. Hasil: 102334155 3. Selesai dalam 818 ms

Lamanya berbeda di tiap komputer, tetapi urutannya pasti sama: baris 2 dan 3 tidak akan tercetak sebelum fibonacci(40) selesai. Itulah sinkron: kode menunggu, dan selama menunggu tidak ada pekerjaan lain yang berjalan. Menghitung memakai CPU itu sendiri, jadi tidak ada yang bisa "dititipkan" ke pihak lain.

Langkah 2: Memanggil API tanpa menunggu

Buat file api-tanpa-await.js. Kita sengaja lupa menunggu hasil fetch:

// api-tanpa-await.js
const hasil = fetch('https://jsonplaceholder.typicode.com/users/1');

console.log(hasil);
console.log('Baris setelah fetch sudah jalan');
$ node api-tanpa-await.js Promise { <pending> } Baris setelah fetch sudah jalan

Yang tercetak bukan data pengguna, melainkan Promise { <pending> } — semacam "struk pesanan": permintaan sudah dikirim, tetapi jawabannya belum datang. Perhatikan juga baris berikutnya langsung berjalan tanpa menunggu API. Itulah asinkron: pekerjaan lambat dititipkan, kode terus lanjut.

Langkah 3: Memanggil API dengan menunggu hasilnya

Buat file api-asinkron.js. Kali ini kita tambahkan await agar baris berikutnya menunggu jawaban API:

// api-asinkron.js
console.log('1. Mulai memanggil API...');
const mulai = Date.now();

const respons = await fetch('https://jsonplaceholder.typicode.com/users/1');
const user = await respons.json();

console.log('2. Nama pengguna:', user.name);
console.log(`3. Selesai dalam ${Date.now() - mulai} ms`);
$ node api-asinkron.js 1. Mulai memanggil API... 2. Nama pengguna: Leanne Graham 3. Selesai dalam 1005 ms

Hasilnya sekarang data asli. Cara kerja await dibahas lengkap di bagian 5; untuk sekarang cukup ingat bahwa await artinya "tunggu hasil ini sebelum lanjut di fungsi ini", tetapi Node sendiri tidak diam selama menunggu. Buktinya ada di langkah berikut.

Langkah 4: Bukti siapa yang membuat program macet

Buat file denyut.js. Program ini menyalakan "denyut jantung": sebuah timer yang mencetak tik setiap 200 ms selama program hidup. Lalu ia memanggil API (asinkron) dan sesudahnya menghitung (sinkron). Kalau denyutnya berhenti, berarti Node sedang macet.

// denyut.js
function fibonacci(n) {
    return n < 2 ? n : fibonacci(n - 1) + fibonacci(n - 2);
}

const mulai = Date.now();
const lewat = () => `${Date.now() - mulai} ms`;

// "Denyut jantung": mencetak tanda setiap 200 ms selama program hidup
const denyut = setInterval(() => console.log(`   tik  (${lewat()})`), 200);

console.log('A. Panggil API (asinkron)...');
const respons = await fetch('https://jsonplaceholder.typicode.com/users/1');
const user = await respons.json();
console.log(`B. API selesai: ${user.name}`);

console.log('C. Mulai menghitung (sinkron)...');
const hasil = fibonacci(40);
console.log(`D. Hitungan selesai: ${hasil}`);

setTimeout(() => clearInterval(denyut), 450);   // beri waktu untuk tik terakhir
$ node denyut.js A. Panggil API (asinkron)... tik (200 ms) tik (402 ms) tik (603 ms) tik (804 ms) tik (1008 ms) tik (1210 ms) B. API selesai: Leanne Graham C. Mulai menghitung (sinkron)... D. Hitungan selesai: 102334155 tik (2126 ms) tik (2326 ms) tik (2528 ms)

Baca outputnya dari atas:

  • A → B (menunggu API): denyut tetap berjalan, tik muncul terus tiap 200 ms. Node tidak macet; ia bebas mengerjakan hal lain sambil menunggu jaringan.
  • C → D (menghitung): denyut berhenti total. Antara tik (1210 ms) dan tik (2126 ms) ada jeda hampir satu detik tanpa satu pun tik, padahal timernya dijadwalkan tiap 200 ms. Selama fibonacci berjalan, event loop terblokir.
  • Begitu hitungan selesai, barulah tik yang tertunda bisa berjalan lagi.
Menghitung (fibonacci) Memanggil API (fetch)
Jenis Sinkron Asinkron
Waktu habis untuk Bekerja (CPU sibuk) Menunggu (jaringan)
Saat berjalan Node macet, tidak bisa melayani yang lain Node bebas, bisa mengerjakan yang lain
Hasil tersedia Langsung di baris berikutnya Nanti, lewat Promise (await)
Kesalahan umum: mengira async / await bisa mempercepat perhitungan berat. Tidak bisa. await hanya membantu ketika pekerjaannya menunggu sesuatu di luar (API, basis data, file). Kalau pekerjaannya menghitung, CPU tetap sibuk dan server tetap macet. Di server sungguhan, itu berarti semua pengunjung ikut tertahan selama hitungan berjalan.

2.5 Urutan Eksekusi yang Mengejutkan

Contoh klasik yang wajib bisa kalian jelaskan:

console.log('1. Mulai');

setTimeout(() => {
    console.log('2. Timer 0 detik');
}, 0);

Promise.resolve().then(() => {
    console.log('3. Promise');
});

console.log('4. Selesai');

Yang tercetak:

1. Mulai 4. Selesai 3. Promise 2. Timer 0 detik
Mengapa urutannya begitu? Node menjalankan seluruh kode sinkron sampai habis dulu (1 dan 4). Baru setelah itu ia memeriksa antrean pekerjaan tertunda. Antrean microtask (Promise) diperiksa lebih dulu daripada antrean macrotask (timer) — itu sebabnya 3 mendahului 2, walaupun timernya 0 detik.

2.6 Event Loop

Mekanisme yang mengatur giliran itu disebut event loop. Gambaran sederhananya:

1. Call Stack
Jalankan semua kode sinkron sampai habis
↓ stack kosong?
2. Microtask Queue
Promise, async/await — kerjakan SEMUA sampai antrean habis
↓
3. Macrotask Queue
setTimeout, I/O — ambil SATU, lalu kembali ke langkah 1
↻ ulangi selamanya, kembali ke langkah 1
Konsekuensi penting: kalau kalian menulis perulangan berat yang berjalan 5 detik, seluruh server berhenti melayani siapa pun selama 5 detik itu — event loop terblokir. Di PHP hal ini tidak terjadi karena tiap request punya prosesnya sendiri. Inilah alasan Node melarang operasi berat yang sinkron di jalur permintaan.

3. Callback dan Callback Hell Indikator 2.3

Sebelum ada Promise, satu-satunya cara menangani hasil asinkron adalah callback: menitipkan sebuah fungsi yang akan dipanggil nanti, ketika hasilnya siap. Kalian sudah punya bekalnya — di Pertemuan 1 sudah dibahas bahwa fungsi adalah nilai yang bisa dioper.

3.1 Bentuk Dasar Callback

import fs from 'node:fs';

// Pola "error-first callback" — khas Node.js
fs.readFile('data.json', 'utf-8', (err, isi) => {
    if (err) {
        console.error('Gagal:', err.message);
        return;
    }
    console.log(isi);
});

console.log('Baris ini jalan LEBIH DULU');   // ← perhatikan!
Konvensi "error-first": argumen pertama callback selalu error (null kalau tidak ada masalah), argumen kedua barulah hasilnya. Pola ini dipakai konsisten di seluruh API lama Node.js.
Coba di latihan-async. Proyek ini dipakai berulang di Section 3 sampai 7, jadi buat sekali saja.

3.2 Masalahnya: Callback Hell

Selama hanya satu operasi, callback masih nyaman. Masalah muncul ketika operasinya berurutan — hasil satu dipakai untuk yang berikutnya:

// Ambil user → ambil pesanannya → ambil detail tiap pesanan
ambilUser(1, (err, user) => {
    if (err) return tangani(err);

    ambilPesanan(user.id, (err, pesanan) => {
        if (err) return tangani(err);

        ambilDetail(pesanan[0].id, (err, detail) => {
            if (err) return tangani(err);

            hitungTotal(detail, (err, total) => {
                if (err) return tangani(err);

                console.log(total);      // ← akhirnya sampai juga
            });
        });
    });
});

Bentuk menjorok ke kanan seperti ini disebut callback hell atau pyramid of doom. Masalahnya nyata, bukan sekadar soal estetika:

Masalah Akibatnya
Sulit dibaca Alur logika terkubur di dalam kurung berlapis
Penanganan error berulang if (err) harus ditulis di setiap tingkat
Tidak bisa dibungkus try/catch Error di dalam callback tidak tertangkap oleh try di luarnya
Sulit dijalankan serentak Menjalankan tiga operasi paralel butuh penghitung manual
Kabar baiknya: kalian tidak perlu menulis kode seperti itu. Semua yang kita pakai di mata kuliah ini — fs/promises, fetch, Prisma — sudah berbasis Promise. Callback dibahas agar kalian bisa membaca kode lama dan memahami mengapa Promise diciptakan.

3.3 Praktik: Callback Hell dengan File Nyata

Contoh ambilUser di 3.2 hanya gambaran. Sekarang kita buktikan dengan operasi file sungguhan, di proyek latihan-async dan memakai data.json yang sudah kalian buat di 3.1. Tugasnya empat langkah, dan setiap langkah butuh yang sebelumnya selesai:

  1. Baca data.json, lalu hitung total penjualannya.
  2. Tulis total itu ke file baru laporan.txt.
  3. Baca kembali laporan.txt untuk memastikan isinya tersimpan.
  4. Catat hasilnya ke log.txt.

Langkah 1: Versi callback — 32-callback-hell.js

// 32-callback-hell.js
import fs from 'node:fs';

// Tugas: baca data.json → hitung total → tulis laporan.txt

4. Promise Indikator 2.2

Di Section 3 kita melihat callback membuat kode bersarang dan sulit ditangani error-nya. Promise adalah cara yang lebih rapi untuk pekerjaan yang sama.

Apa itu Promise, singkatnya: sebuah Promise adalah "janji hasil". Saat kita menjalankan pekerjaan yang lambat (membaca file, memanggil API), Node tidak memberikan hasilnya langsung, melainkan sebuah Promise: objek yang berarti "hasilnya belum ada, tapi pasti kukabari nanti, entah berhasil entah gagal". Kita tinggal memberi tahu apa yang harus dilakukan untuk masing-masing kemungkinan:
  • .then(...) → kalau berhasil, lakukan ini.
  • .catch(...) → kalau gagal, lakukan ini.
Itu saja inti Promise. Sekarang kita coba langsung; penjelasan lengkapnya (tiga keadaan Promise, analogi, dan cara kerjanya) ada di 4.2 setelah kalian melihat hasilnya.

4.2 Jadi, Apa Itu Promise?

Sekarang istilahnya jadi mudah. Promise adalah objek yang mewakili hasil yang belum ada sekarang, tetapi akan ada nanti, entah berhasil entah gagal. Itu yang dikembalikan readFile tadi.

Analogi nomor antrean: saat memesan di restoran cepat saji, kalian tidak langsung menerima makanan, melainkan nomor antrean. Nomor itu bukan makanan, tetapi janji bahwa makanan akan datang. Kalian bisa duduk dan mengerjakan hal lain. Nanti nomor itu dipanggil: membawa makanan (berhasil) atau kabar bahwa stok habis (gagal).

Sebuah Promise selalu berada di salah satu dari tiga keadaan:

Keadaan Artinya Pada percobaan tadi Ditangani oleh
pending Masih diproses, hasil belum ada Saat Baris ini jalan lebih dulu tercetak —
fulfilled Selesai, ada nilainya File data.json berhasil dibaca .then() / await
rejected Gagal, ada alasannya File tidak-ada.json tidak ditemukan .catch() / try...catch

Sekali berpindah dari pending, keadaan Promise tidak bisa berubah lagi.

4.3 Menyambung Beberapa Langkah

4.5 Membuat Promise Sendiri

Sebagian besar waktu kalian hanya memakai Promise yang sudah disediakan pustaka (seperti fs/promises dan fetch). Membuat sendiri diperlukan saat ada API lama yang hanya mendukung callback.

Contoh 1: Membungkus callback — 45-bungkus-callback.js

// 45-bungkus-callback.js
import fs from 'node:fs';

// Membungkus API callback lama menjadi Promise
function bacaFile(nama) {
    return new Promise((resolve, reject) => {
        fs.readFile(nama, 'utf-8', (err, isi) => {
            if (err) {
                reject(err);        // gagal → promise rejected
            } else {
                resolve(isi);       // berhasil → promise fulfilled
            }
        });
    });
}

5. async / await Indikator 2.3

async/await adalah cara menulis Promise yang terlihat seperti kode biasa, baris demi baris. Di baliknya tetap Promise, hanya sintaksnya jauh lebih mudah dibaca. Ini gaya yang akan kita pakai sepanjang semester.

Apa itu async/await, singkatnya:
  • async → ditulis di depan fungsi sebagai tanda "isi fungsi ini punya pekerjaan asinkron". Fungsi itu selalu mengembalikan Promise.
  • await → ditulis di depan pekerjaan asinkron sebagai perintah "tunggu hasilnya di sini, baru lanjut ke baris berikutnya".
Ingat selalu bedanya sinkron dan asinkron:
  • Sinkron — hasil langsung ada di baris berikutnya. Contoh: 2 + 3, JSON.parse, map. Tidak butuh await.
  • Asinkron — hasil datang nanti, yang kita terima dulu hanya Promise. Contoh: fetch, readFile, kueri basis data. Butuh await.
Pertanyaan pengujinya: "Apakah pekerjaan ini menunggu sesuatu di luar Node (jaringan, disk, basis data)?" Ya → asinkron → pakai await. Tidak → sinkron → tanpa await.
Cara mengingat: async = titip, await = ambil hasilnya.

5.2 Jadi, Apa Itu async/await?

Setelah melihat hasilnya, dua aturannya jadi mudah:

Kata kunci Aturannya Di percobaan tadi
async Ditulis di depan fungsi. Fungsi itu selalu mengembalikan Promise, apa pun isinya async function ambilUser
await Menunggu Promise selesai lalu mengambil nilainya. Hanya boleh di dalam fungsi async, atau di baris paling luar file ESM (top-level await) await ambilUser(1)
await menunggu, tetapi Node tidak diam. Kode di dalam fungsi async berhenti sejenak di baris await, sementara Node bebas melayani pekerjaan lain (ingat percobaan denyut.js di Section 2.4: tik tetap berjalan saat menunggu API). Itu yang membedakan await dari kode sinkron yang benar-benar membuat semuanya macet.

Fungsi async selalu membungkus return-nya dalam Promise, itu sebabnya ambilUser(1) tanpa await tadi menghasilkan Promise:

async function angka() {
    return 42;                    // terlihat seperti angka biasa
}

console.log(angka());              // Promise { 42 }  ← bukan 42!
console.log(await angka());        // 42              ← harus di-await

    return ambilJson(`${BASE}/posts/${id}`)

// Arrow function

5.5 Jebakan: await di Dalam Perulangan

map(), filter(), dan forEach() tidak menunggu fungsi async di dalamnya. Buat 55-perulangan.js untuk melihatnya sendiri:

// 55-perulangan.js
const BASE = 'https://jsonplaceholder.typicode.com';

async function ambilNama(id) {
    const respons = await fetch(`${BASE}/users/${id}`);
    const user = await respons.json();
    return user.name;
}

const daftarId = [1, 2, 3];

// ❌ SALAH: forEach tidak menunggu
const hasilSalah = [];
daftarId.forEach(async (id) => {
    hasilSalah.push(await ambilNama(id));
});
console.log('forEach     :', hasilSalah);

// ✅ BENAR (berurutan): for...of
const hasilUrut = [];
for (const id of daftarId) {
    hasilUrut.push(await ambilNama(id));
}
console.log('for...of    :', hasilUrut);

// ✅ BENAR (serentak): Promise.all + map
const hasilSerentak = await Promise.all(daftarId.map(ambilNama));
console.log('Promise.all :', hasilSerentak);

  • for...of menunggu tiap iterasi, jadi berurutan (satu per satu).
  • Promise.all + map memulai semuanya sekaligus lalu menunggu semuanya, jadi serentak.

Kapan memilih yang mana dibahas tuntas di Section 8.

Yang perlu diingat dari Section 5:
  • Sinkron = hasil langsung ada, tanpa await. Asinkron = hasil datang nanti (Promise), pakai await.
  • async = titip (fungsi selalu mengembalikan Promise). await = ambil hasilnya.
  • Lupa await → yang tercetak Promise { <pending> }.
  • Error ditangani dengan try/catch biasa.
  • forEach tidak menunggu; pakai for...of (berurutan) atau Promise.all (serentak).

6. fetch dan Pemanggilan Layanan Luar Indikator 2.2

fetch() adalah fungsi bawaan untuk melakukan permintaan HTTP ke server lain. Sejak Node.js 18 ia tersedia langsung tanpa memasang pustaka apa pun, dan sintaksnya sama persis di Node.js maupun di browser, jadi yang kalian pelajari sekarang akan langsung terpakai lagi di Minggu 11 saat membangun antarmuka React.

Apa itu fetch, singkatnya: fetch(url) berarti "tolong ambilkan data dari alamat ini". Karena harus menunggu jaringan, ia asinkron: yang dikembalikan bukan datanya, melainkan sebuah Promise. Pengambilan datanya dua tahap:
  1. fetch(url) → Promise yang berisi respons (status dan header tiba lebih dulu).
  2. respons.json() → Promise yang berisi datanya (isi tanggapan dibaca dan diurai menjadi object).
Keduanya asinkron, jadi masing-masing butuh await (atau .then()). Sekarang kita coba langsung.

6.3 Memeriksa Status — Jangan Dilewati

Ini perilaku fetch yang paling sering mengejutkan: fetch tidak menganggap status 404 atau 500 sebagai kegagalan. Promise-nya tetap fulfilled. Yang membuatnya rejected hanya kegagalan jaringan: server tidak terjangkau, DNS gagal, koneksi putus. Buktikan sendiri dengan 63-cek-status.js:

// 63-cek-status.js

// Kasus 1: server menjawab, tetapi "tidak ditemukan" (404)
const respons = await fetch(`${BASE}/users/99999`);
console.log('ok     :', respons.ok);
console.log('status :', respons.status);

// Kasus 2: server tidak terjangkau sama sekali
try {
    await fetch('https://domain-ini-tidak-ada.invalid/');
} catch (err) {
    console.log('Jaringan gagal:', err.message);
}
$ node 63-cek-status.js ok : false status : 404 Jaringan gagal: fetch failed
  • Kasus 1: server menjawab "tidak ditemukan". Tidak ada error yang dilempar; kita hanya mendapat ok: false dan status: 404. Kalau tidak diperiksa, program lanjut seolah-olah tidak terjadi apa-apa.
  • Kasus 2: servernya tidak ada sama sekali. Barulah fetch benar-benar melempar error (fetch failed).

if (!respons.ok) {

const data = await respons.json();

}

7. Penanganan Error Asinkron Indikator 2.4

Kode asinkron yang tidak menangani error adalah sumber masalah paling umum pada aplikasi Node.js. Satu Promise yang gagal tanpa penangkap bisa menjatuhkan seluruh proses server — dan bersamanya, semua pengguna yang sedang dilayani.

7.1 try/catch Bekerja dengan await

(Masih memakai data.json yang sama dari Section 3.1. Coba panggil bacaData() dengan nama file yang tidak ada untuk melihat jalur catch-nya.)

async function bacaData() {
    try {
        const isi = await readFile('data.json', 'utf-8');
        return JSON.parse(isi);      // error parse juga tertangkap
    } catch (err) {
        console.error('Gagal membaca:', err.message);
        return [];                       // nilai cadangan yang aman
    } finally {
        console.log('Selesai — blok ini SELALU jalan');
    }
}
Yang tidak bekerja: try/catch tidak menangkap error dari callback. Kode berikut tetap membuat proses mati: 
try {
    fs.readFile('x.json', (err, isi) => {
        throw err;         // ❌ TIDAK tertangkap di bawah
    });
} catch (e) {
    console.log('tidak pernah sampai sini');
}
Alasannya: saat callback dipanggil, blok try sudah lama selesai dijalankan. Ini salah satu alasan kuat memakai Promise dan async/await.

7.2 Membedakan Jenis Error

Tidak semua kegagalan sama, dan penanganannya berbeda. Bedakan sejak awal:

Jenis Contoh Terdeteksi lewat Penanganan
Error jaringan Server mati, DNS gagal fetch ditolak → masuk catch Coba lagi, atau tampilkan pesan gangguan
Error HTTP 4xx 404, 401, 422 respons.ok === false Salah dari sisi klien — perbaiki permintaan
Error HTTP 5xx 500, 503 respons.ok === false Salah dari sisi server — coba lagi nanti
Error penguraian Jawaban bukan JSON yang sah .json() melempar error Periksa Content-Type
Error logika Data ada, tetapi tidak masuk akal Validasi kalian sendiri Lempar error kustom

7.3 Error Kustom

Membuat kelas error sendiri membuat penanganan di lapisan atas jauh lebih rapi. Pola ini akan langsung terpakai di Minggu 4 untuk penanganan error terpusat Express:

// src/galat.js
export class GalatHttp extends Error {
    constructor(status, pesan, url) {
        super(pesan);
        this.name = 'GalatHttp';
        this.status = status;
        this.url = url;
    }
}

// Pemakaian
try {
    const data = await ambilJson(url);
} catch (err) {
    if (err instanceof GalatHttp && err.status === 404) {
        console.log('Data tidak ditemukan, memakai data kosong');
    } else {
        throw err;                 // yang tidak dikenali diteruskan ke atas
    }
}

7.4 Unhandled Rejection

// ❌ Promise gagal tanpa penangkap
ambilJson('https://alamat-salah.contoh');
// → UnhandledPromiseRejection: proses Node.js BERHENTI

// ✅ Selalu tangani
ambilJson(url).catch(err => console.error(err.message));

// ✅ Jaring pengaman terakhir di titik masuk aplikasi
process.on('unhandledRejection', (alasan) => {
    console.error('Promise gagal tanpa penangkap:', alasan);
    process.exit(1);
});
Aturan praktis penanganan error:
  • Tangkap error di tempat yang benar-benar bisa melakukan sesuatu terhadapnya
  • Kalau tidak bisa berbuat apa-apa, lempar ulang (throw err) — jangan ditelan diam-diam
  • Jangan pernah menulis catch (e) {} kosong. Error yang hilang tanpa jejak jauh lebih sulit dilacak daripada aplikasi yang mati dengan pesan jelas
  • Pesan error harus menyebut apa yang gagal dan di mana

8. Eksekusi Berurutan vs Serentak Indikator 2.3

Setelah paham await, muncul pertanyaan berikutnya yang berdampak besar pada performa: kalau ada tiga operasi asinkron, haruskah dikerjakan satu per satu?

8.1 Berurutan (Sequential)

console.time('berurutan');

const a = await ambil('/api/users');      // tunggu 1 detik
const b = await ambil('/api/posts');      // tunggu 1 detik lagi
const c = await ambil('/api/comments');   // tunggu 1 detik lagi

console.timeEnd('berurutan');            // ± 3000 ms
users1000 ms
posts1000 ms
comments1000 ms
Total: 3000 ms — setiap operasi menunggu yang sebelumnya

8.2 Serentak (Concurrent) dengan Promise.all

console.time('serentak');

const [a, b, c] = await Promise.all([
    ambil('/api/users'),
    ambil('/api/posts'),
    ambil('/api/comments')
]);

console.timeEnd('serentak');              // ± 1000 ms
users1000 ms
posts1000 ms
comments1000 ms
Total: 1000 ms — ketiganya dimulai bersamaan, 3× lebih cepat

8.3 Praktik: Mengukur Sendiri di Proyek Nyata

Contoh di atas memakai ambil() rekaan. Sekarang kita buktikan dengan permintaan sungguhan ke API, lengkap dari membuat proyek. Buat proyek baru bernama latihan-paralel:

Langkah 0: Buat proyek

$ mkdir latihan-paralel $ cd latihan-paralel $ npm init -y $ npm pkg set type=module

Langkah 1: Fungsi bantu ambil.js

Semua skrip berikutnya memakai satu fungsi yang sama. Ini sekaligus latihan modul dari bagian 1: fungsi dan konstanta di-export, lalu di-import oleh file lain. Fungsinya juga melempar error kalau server membalas status gagal (misalnya 404), karena fetch sendiri tidak melempar error untuk status tersebut.

// ambil.js
export const BASE = 'https://jsonplaceholder.typicode.com';

export async function ambilJson(url) {
    const respons = await fetch(url);
    if (!respons.ok) {
        throw new Error(`HTTP ${respons.status} untuk ${url}`);
    }
    return respons.json();
}

Langkah 2: Berurutan — berurutan.js

Tiga data untuk pengguna nomor 1: profil, daftar post, dan daftar todo. Setiap await menunggu yang sebelumnya selesai:

Langkah 3: Serentak — serentak.js

Data yang sama, tetapi ketiga permintaan dikirim sekaligus. Perhatikan Promise.all menerima array janji, dan hasilnya datang sebagai array dengan urutan yang sama seperti yang diminta:

// serentak.js
import { BASE, ambilJson } from './ambil.js';

console.time('serentak');

const [user, posts, todos] = await Promise.all([
    ambilJson(`${BASE}/users/1`),
    ambilJson(`${BASE}/posts?userId=1`),
    ambilJson(`${BASE}/todos?userId=1`),

$ node serentak.js serentak: 1.210s Leanne Graham | 10 post | 20 todo

Datanya identik, tetapi waktunya jauh lebih singkat. Angka di komputer kalian akan berbeda karena bergantung pada koneksi internet; yang perlu dibandingkan adalah selisih kedua skrip, bukan angka mutlaknya.

Mengapa tidak persis 3× lebih cepat? Pada contoh rekaan di 8.1–8.2, tiap operasi tepat 1000 ms. Pada jaringan sungguhan, permintaan pertama ke sebuah server menanggung biaya membuka sambungan (DNS dan TLS) yang tidak ikut dipercepat. Prinsipnya tetap sama: waktu serentak mendekati operasi paling lambat, bukan jumlah semuanya.

Langkah 4: Ketika harus berurutan — bergantung.js

Serentak tidak selalu bisa. Di sini kita mau menampilkan nama penulis dan komentar dari post nomor 1. Nama penulis baru bisa diminta kalau kita sudah tahu userId-nya, dan userId itu hanya ada di dalam data post. Jadi tahap 1 wajib berurutan. Begitu userId diketahui, penulis dan komentar tidak saling bergantung, sehingga tahap 2 boleh serentak:

// bergantung.js
import { BASE, ambilJson } from './ambil.js';

console.time('total');

// Tahap 1: WAJIB berurutan. Kita butuh userId dari post ini.
const post = await ambilJson(`${BASE}/posts/1`);
console.log(`Post 1 ditulis oleh userId ${post.userId}`);

// Tahap 2: dua data ini tidak saling bergantung, jadi serentak.
const [penulis, komentar] = await Promise.all([
    ambilJson(`${BASE}/users/${post.userId}`),
    ambilJson(`${BASE}/comments?postId=${post.id}`),
]);

console.timeEnd('total');
console.log(`Penulis: ${penulis.name}, ${komentar.length} komentar`);
$ node bergantung.js Post 1 ditulis oleh userId 1 total: 2.194s Penulis: Leanne Graham, 5 komentar

Pola ini paling sering muncul di aplikasi nyata: berurutan untuk yang bergantung, serentak untuk yang bebas. Total waktunya dua tahap, bukan tiga permintaan berurutan.

Langkah 5: Kalau salah satu gagal — sebagian-gagal.js

Sekarang satu dari tiga permintaan sengaja dibuat gagal (pengguna nomor 99999 tidak ada). Bandingkan Promise.all dengan Promise.allSettled (lihat tabel di 8.5):

// sebagian-gagal.js
import { BASE, ambilJson } from './ambil.js';

const daftarUrl = [
    `${BASE}/users/1`,
    `${BASE}/users/99999`,   // tidak ada → HTTP 404
    `${BASE}/users/3`,
];

// Promise.all: satu gagal, semuanya dianggap gagal
try {
    await Promise.all(daftarUrl.map(ambilJson));
} catch (err) {
    console.log('Promise.all     →', err.message);
}

// Promise.allSettled: semua ditunggu, tiap hasil dilaporkan
const hasil = await Promise.allSettled(daftarUrl.map(ambilJson));

hasil.forEach((r, i) => {
    if (r.status === 'fulfilled') {
        console.log(`allSettled [${i}] → berhasil: ${r.value.name}`);
    } else {
        console.log(`allSettled [${i}] → gagal: ${r.reason.message}`);
    }
});
$ node sebagian-gagal.js Promise.all → HTTP 404 untuk https://jsonplaceholder.typicode.com/users/99999 allSettled [0] → berhasil: Leanne Graham allSettled [1] → gagal: HTTP 404 untuk https://jsonplaceholder.typicode.com/users/99999 allSettled [2] → berhasil: Clementine Bauch

Promise.all membuang dua data yang sebenarnya berhasil hanya karena satu yang gagal. Promise.allSettled mengembalikan ketiganya beserta statusnya, jadi kalian bebas memutuskan: tampilkan yang berhasil dan beri tahu yang gagal.

File Pola Pelajaran

serentak.js Promise.all Waktu ≈ permintaan paling lambat
bergantung.js await lalu Promise.all Berurutan hanya untuk yang bergantung
sebagian-gagal.js allSettled Satu gagal tidak menggugurkan yang lain

8.4 Kapan Memilih yang Mana?

Pakai berurutan kalau... Pakai serentak kalau...
Hasil operasi pertama dibutuhkan operasi kedua Operasi saling tidak bergantung
Contoh: ambil user → lalu ambil pesanan milik user itu Contoh: ambil daftar produk, kategori, dan banner sekaligus
Ada batas laju (rate limit) di API tujuan Jumlah permintaan sedikit dan terkendali
Kesalahan yang sangat sering terjadi: memakai await berurutan padahal operasinya sama sekali tidak saling bergantung. Kode tetap benar, tetapi aplikasinya berkali-kali lipat lebih lambat — dan ini termasuk yang diperiksa saat tinjauan kode.

8.5 Empat Varian Promise

Metode Selesai ketika Kalau ada yang gagal Dipakai untuk
Promise.all Semua berhasil Langsung gagal semuanya Semua data wajib ada
Promise.allSettled Semua selesai Tetap lanjut, statusnya dilaporkan Sebagian boleh gagal
Promise.race Ada satu yang selesai duluan Yang duluan menentukan hasil Timeout, mirror tercepat
Promise.any Ada satu yang berhasil Gagal hanya kalau semua gagal Beberapa sumber cadangan 
// allSettled — cocok saat sebagian sumber boleh gagal
const hasil = await Promise.allSettled([
    ambil('/api/a'),
    ambil('/api/rusak'),
    ambil('/api/c')
]);

hasil.forEach((r, i) => {
    if (r.status === 'fulfilled') {
        console.log(i, 'berhasil', r.value);
    } else {
        console.log(i, 'gagal', r.reason.message);
    }
});

// race — membuat batas waktu buatan
const data = await Promise.race([
    ambil(url),
    tunggu(3000).then(() => { throw new Error('Timeout 3 detik'); })
]);

8.6 Membatasi Jumlah Permintaan Serentak

Promise.all dengan 1000 URL akan menembakkan 1000 permintaan sekaligus — server tujuan bisa memblokir kalian. Solusi sederhana: pecah menjadi kelompok kecil.

async function ambilBerkelompok(daftarUrl, ukuran = 5) {
    const semua = [];

    for (let i = 0; i < daftarUrl.length; i += ukuran) {
        const kelompok = daftarUrl.slice(i, i + ukuran);
        const hasil = await Promise.all(kelompok.map(u => ambilJson(u)));
        semua.push(...hasil);
    }
    return semua;
}

9. Praktik: Gabungkan Data Lokal & Direktori Kampus Latihan

Latihan ini menyatukan seluruh Pertemuan 3: modul, fetch, async/await, penanganan error, dan perbandingan waktu eksekusi. Langkah 2 — Pembungkus fetch (src/http.js)

export async function ambilJson(url, opsi = {}) {
    const respons = await fetch(url, {
        ...opsi,
        signal: AbortSignal.timeout(5000)
    });

    if (!respons.ok) {
        throw new Error(`HTTP ${respons.status} pada ${url}`);
    }
    return respons.json();
}

Langkah 3 — Gabungkan Data (src/gabung.js)

import { readFile } from 'node:fs/promises';
import { ambilJson } from './http.js';

export async function muatMahasiswaLokal() {
    const isi = await readFile('./data/mahasiswa.json', 'utf-8');
    return JSON.parse(isi);
}

export async function ambilProfilDirektori(id) {
    // Menyimulasikan panggilan ke API direktori kampus lewat API publik
    return ambilJson(`https://jsonplaceholder.typicode.com/users/${id}`);
}

export async function gabungkanSemua(mode = 'serentak') {
    const mahasiswa = await muatMahasiswaLokal();
    const hasil = [];

    if (mode === 'berurutan') {
        for (const m of mahasiswa) {
            const profil = await ambilProfilDirektori(m.idPublik);
            hasil.push({ ...m, email: profil.email, kota: profil.address?.city });
        }
    } else {
        const profilSemua = await Promise.all(
            mahasiswa.map(m => ambilProfilDirektori(m.idPublik))
        );
        mahasiswa.forEach((m, i) => {
            hasil.push({ ...m, email: profilSemua[i].email, kota: profilSemua[i].address?.city });
        });
    }
    return hasil;
}

Langkah 4 — Titik Masuk (index.js)

import { gabungkanSemua } from './src/gabung.js';

for (const mode of ['berurutan', 'serentak']) {
    const mulai = Date.now();

    try {
        const data = await gabungkanSemua(mode);
        const durasi = Date.now() - mulai;

        console.log(`\n[${mode}] selesai dalam ${durasi} ms`);
        data.forEach(m => console.log(`  ${m.nama} — ${m.email} (${m.kota})`));
    } catch (err) {
        console.error(`[${mode}] gagal:`, err.message);
    }
}
