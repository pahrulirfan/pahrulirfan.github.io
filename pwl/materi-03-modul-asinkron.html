1. Modul: Memecah Program Jadi Banyak Berkas Indikator 2.1

Mengapa Perlu Modul?

Di Pertemuan 1–2, semua kode masih muat dalam satu berkas. Begitu proyek bertambah besar, cara itu berhenti bekerja: berkas jadi ribuan baris, nama fungsi bentrok, dan tidak ada yang tahu bagian mana yang boleh diubah tanpa merusak yang lain.

Modul adalah cara memecah program menjadi beberapa berkas, di mana setiap berkas hanya membuka sebagian isinya untuk dipakai berkas lain. Konsep ini sudah kalian kenal di PHP lewat require, include, dan autoload Composer — hanya sintaks dan aturannya yang berbeda.

Apa yang berubah dibanding PHP:
  • Di PHP, include menempelkan seluruh isi berkas. Di JavaScript, kalian memilih apa saja yang boleh keluar (export) dan apa yang mau diambil (import).
  • Semua yang tidak di-export bersifat privat bagi berkas itu — tidak bisa disentuh dari luar.
  • Satu modul hanya dijalankan sekali, walaupun di-import dari banyak tempat.

1.1 Dua Sistem Modul di Node.js

Node.js mendukung dua sistem modul. Kalian akan menemui keduanya di internet, jadi harus bisa membedakannya.

Aspek CommonJS (CJS) — gaya lama ES Modules (ESM) — standar resmi
Mengambil const x = require('./a') import x from './a.js'
Mengeluarkan module.exports = x export default x
Cara mengaktifkan Bawaan Node (tanpa konfigurasi) "type": "module" di package.json
Ekstensi berkas Boleh dihilangkan Wajib ditulis (./util.js)
Waktu dimuat Saat baris require dijalankan Sebelum kode berjalan (statis)
Top-level await ❌ Tidak bisa ✅ Bisa
Berlaku di browser ❌ Tidak ✅ Ya — sintaks yang sama
Di mata kuliah ini kita memakai ESM. Alasannya: ESM adalah standar resmi JavaScript, sintaksnya sama persis dengan yang nanti dipakai di React (Minggu 11), dan mendukung top-level await. CommonJS tetap dibahas karena banyak tutorial dan paket lama memakainya — kalian harus bisa mengenalinya, bukan memakainya.

1.2 Mengaktifkan ESM

// package.json
{
  "name": "latihan-modul",
  "type": "module",      // ← baris ini yang menentukan
  "main": "index.js"
}

Tanpa baris itu, Node menganggap semua .js sebagai CommonJS dan import akan menghasilkan galat Cannot use import statement outside a module.

1.3 Named Export — Mengeluarkan Banyak Hal

// hitung.js
export const PPN = 0.11;

export function subtotal(qty, harga) {
    return qty * harga;
}

export const denganPajak = (n) => n * (1 + PPN);

// Fungsi ini TIDAK di-export → privat, tidak terlihat dari luar
function bulatkan(n) {
    return Math.round(n);
}
// index.js
import { subtotal, denganPajak, PPN } from './hitung.js';

console.log(subtotal(3, 25000));            // 75000
console.log(denganPajak(75000));            // 83250
console.log(PPN);                           // 0.11

// Mengganti nama saat mengambil
import { subtotal as hitungSubtotal } from './hitung.js';

// Mengambil semua sekaligus sebagai satu object
import * as hitung from './hitung.js';
console.log(hitung.subtotal(2, 10000));   // 20000

1.4 Default Export — Satu Hal Utama

// mahasiswa.js
export default class Mahasiswa {
    constructor(nim, nama) {
        this.nim = nim;
        this.nama = nama;
    }
}

// Boleh dicampur dengan named export
export const JURUSAN = 'Teknik Informatika';
// index.js — default diambil TANPA kurung kurawal
import Mahasiswa, { JURUSAN } from './mahasiswa.js';

const m = new Mahasiswa('F1D021001', 'Andi');
console.log(m.nama, JURUSAN);
Kesalahan paling sering: tertukar antara ada dan tidak adanya kurung kurawal.
  • import { x } from './a.js' → mengambil named export bernama x
  • import x from './a.js' → mengambil default export, namanya bebas
  • Kalau salah, nilainya jadi undefined tanpa pesan galat yang jelas

Node menyediakan modul bawaan untuk berkas, jalur, HTTP, dan lainnya. Sejak Node modern, tulis dengan awalan node: agar jelas bahwa itu modul bawaan, bukan paket dari npm.

2. Sinkron vs Asinkron Indikator 2.5

Ini adalah konsep paling penting di seluruh pertemuan ini, dan yang paling berbeda dari PHP. Kalau bagian ini dipahami, sisanya hanya soal sintaks.

  • Sinkron — setiap baris kode menunggu baris sebelumnya selesai dulu sebelum lanjut. Kalau ada satu baris yang lambat (misalnya menunggu jawaban database), semua baris sesudahnya ikut tertahan.
  • Asinkron — sebuah pekerjaan yang lambat dititipkan untuk dikerjakan di "belakang layar", dan kode tidak menunggu di situ — ia langsung lanjut ke baris berikutnya. Hasil pekerjaan yang dititipkan tadi baru diambil belakangan, ketika sudah siap.

Perbedaan ini paling terasa saat dibandingkan langsung: PHP (yang sudah kalian kenal) memilih jalan sinkron, Node.js memilih jalan asinkron. Alasannya bukan soal selera, melainkan cara keduanya melayani banyak pengunjung sekaligus:

2.1 Cara PHP Bekerja

Saat kalian menulis kode PHP seperti ini:

// PHP
$data = file_get_contents('data.json');   // tunggu sampai selesai
$hasil = $db->query('SELECT * FROM users'); // tunggu sampai selesai
echo "Selesai";

Setiap baris menunggu baris sebelumnya benar-benar selesai. Selama menunggu database, proses PHP itu diam — tidak melakukan apa pun. Ini tidak masalah, karena web server menyediakan satu proses terpisah untuk setiap pengunjung. Pengunjung lain dilayani proses lain.

2.2 Cara Node.js Bekerja

Node.js hanya punya satu thread untuk menjalankan kode kalian, dan thread itu melayani semua pengunjung sekaligus. Kalau thread tersebut ikut diam menunggu database, seluruh aplikasi berhenti untuk semua orang.

Karena itu Node memakai pendekatan berbeda: pekerjaan yang butuh menunggu dititipkan ke sistem, lalu kode lanjut jalan. Ketika hasilnya siap, Node kembali mengerjakannya.

Analogi warung kopi:
  • Cara sinkron (PHP) — barista menerima pesanan, menyeduh kopi sampai selesai, menyerahkannya, baru melayani pelanggan berikutnya. Antrean di belakang menunggu, walaupun mereka hanya mau memesan air putih.
  • Cara asinkron (Node.js) — barista menerima pesanan, menyalakan mesin kopi, lalu langsung melayani pelanggan berikutnya. Saat mesin berbunyi, ia kembali mengambil kopi itu dan menyerahkannya.
Baristanya tetap satu orang. Yang berubah adalah ia tidak berdiri diam saat menunggu mesin.

2.3 Apa Saja yang Asinkron?

Asinkron (menunggu sesuatu di luar) Sinkron (murni hitungan)
Membaca / menulis berkas map, filter, reduce
Kueri ke basis data JSON.parse, JSON.stringify
Memanggil API lain (fetch) Perhitungan matematika
Timer (setTimeout) Manipulasi string
Menerima permintaan HTTP Percabangan & perulangan biasa

Polanya sederhana: kalau harus menunggu sesuatu di luar proses Node — disk, jaringan, basis data — operasinya asinkron.

2.4 Urutan Eksekusi yang Mengejutkan

Contoh klasik yang wajib bisa kalian jelaskan:

console.log('1. Mulai');

setTimeout(() => {
    console.log('2. Timer 0 detik');
}, 0);

Promise.resolve().then(() => {
    console.log('3. Promise');
});

console.log('4. Selesai');

Yang tercetak:

1. Mulai 4. Selesai 3. Promise 2. Timer 0 detik
Mengapa urutannya begitu? Node menjalankan seluruh kode sinkron sampai habis dulu (1 dan 4). Baru setelah itu ia memeriksa antrean pekerjaan tertunda. Antrean microtask (Promise) diperiksa lebih dulu daripada antrean macrotask (timer) — itu sebabnya 3 mendahului 2, walaupun timernya 0 detik.

2.5 Event Loop

Mekanisme yang mengatur giliran itu disebut event loop. Gambaran sederhananya:

1. Call Stack
Jalankan semua kode sinkron sampai habis
↓ stack kosong?
2. Microtask Queue
Promise, async/await — kerjakan SEMUA sampai antrean habis
↓
3. Macrotask Queue
setTimeout, I/O — ambil SATU, lalu kembali ke langkah 1
↻ ulangi selamanya, kembali ke langkah 1
Konsekuensi penting: kalau kalian menulis perulangan berat yang berjalan 5 detik, seluruh server berhenti melayani siapa pun selama 5 detik itu — event loop terblokir. Di PHP hal ini tidak terjadi karena tiap request punya prosesnya sendiri. Inilah alasan Node melarang operasi berat yang sinkron di jalur permintaan.

3. Callback dan Callback Hell Indikator 2.3

Sebelum ada Promise, satu-satunya cara menangani hasil asinkron adalah callback: menitipkan sebuah fungsi yang akan dipanggil nanti, ketika hasilnya siap. Kalian sudah punya bekalnya — di Pertemuan 1 sudah dibahas bahwa fungsi adalah nilai yang bisa dioper.

3.1 Bentuk Dasar Callback

import fs from 'node:fs';

// Pola "error-first callback" — khas Node.js
fs.readFile('data.json', 'utf-8', (err, isi) => {
    if (err) {
        console.error('Gagal:', err.message);
        return;
    }
    console.log(isi);
});

console.log('Baris ini jalan LEBIH DULU');   // ← perhatikan!
Konvensi "error-first": argumen pertama callback selalu galat (null kalau tidak ada masalah), argumen kedua barulah hasilnya. Pola ini dipakai konsisten di seluruh API lama Node.js.
Coba di latihan-async. Buat data.json ini sekali saja di folder proyek — dipakai lagi, persis sama, di:
  • Section 4.3 (Memakai Promise)
  • Section 5.3 (Bentuk-bentuk Penulisan async/await)
  • Section 7.1 (try/catch dengan await)
// data.json
[
  { "produk": "Buku Tulis", "qty": 3, "harga": 5000 },
  { "produk": "Pulpen", "qty": 10, "harga": 2000 },
  { "produk": "Penggaris", "qty": 5, "harga": 3000 }
]
Lalu buat 31-callback.js berisi kode readFile di atas (ganti import fs from 'node:fs' dan panggil seperti contohnya):
$ node 31-callback.js Baris ini jalan LEBIH DULU [ { "produk": "Buku Tulis", "qty": 3, "harga": 5000 }, { "produk": "Pulpen", "qty": 10, "harga": 2000 }, { "produk": "Penggaris", "qty": 5, "harga": 3000 } ]
Perhatikan urutannya: baris terakhir kode (console.log('Baris ini jalan LEBIH DULU')) malah tercetak lebih dulu — readFile tidak menunggu, ia menitipkan pekerjaannya dan baru kembali setelah isi berkas selesai dibaca.

3.2 Masalahnya: Callback Hell

Selama hanya satu operasi, callback masih nyaman. Masalah muncul ketika operasinya berurutan — hasil satu dipakai untuk yang berikutnya:

// Ambil user → ambil pesanannya → ambil detail tiap pesanan
ambilUser(1, (err, user) => {
    if (err) return tangani(err);

    ambilPesanan(user.id, (err, pesanan) => {
        if (err) return tangani(err);

        ambilDetail(pesanan[0].id, (err, detail) => {
            if (err) return tangani(err);

            hitungTotal(detail, (err, total) => {
                if (err) return tangani(err);

                console.log(total);      // ← akhirnya sampai juga
            });
        });
    });
});

Bentuk menjorok ke kanan seperti ini disebut callback hell atau pyramid of doom. Masalahnya nyata, bukan sekadar soal estetika:

Masalah Akibatnya
Sulit dibaca Alur logika terkubur di dalam kurung berlapis
Penanganan galat berulang if (err) harus ditulis di setiap tingkat
Tidak bisa dibungkus try/catch Galat di dalam callback tidak tertangkap oleh try di luarnya
Sulit dijalankan serentak Menjalankan tiga operasi paralel butuh penghitung manual
Kabar baiknya: kalian tidak perlu menulis kode seperti itu. Semua yang kita pakai di mata kuliah ini — fs/promises, fetch, Prisma — sudah berbasis Promise. Callback dibahas agar kalian bisa membaca kode lama dan memahami mengapa Promise diciptakan.

4. Promise Indikator 2.2

4.1 Apa itu Promise?

Promise adalah objek yang mewakili hasil yang belum ada sekarang, tetapi akan ada nanti — entah berhasil, entah gagal.

Analogi nomor antrean: saat memesan di restoran cepat saji, kalian tidak langsung menerima makanan, melainkan nomor antrean. Nomor itu bukan makanan, tetapi janji bahwa makanan akan datang. Kalian bisa memegangnya, duduk, mengerjakan hal lain. Nanti nomor itu dipanggil — entah membawa makanan (berhasil), entah kabar bahwa stok habis (gagal).

4.2 Tiga Keadaan Promise

Keadaan Artinya Ditangani oleh
pending Masih diproses, hasil belum ada —
fulfilled Selesai, ada nilainya .then() / await
rejected Gagal, ada alasannya .catch() / try...catch

Sekali berpindah dari pending, keadaan Promise tidak bisa berubah lagi.

4.3 Memakai Promise

import { readFile } from 'node:fs/promises';

readFile('data.json', 'utf-8')
    .then(isi => {
        console.log('Berhasil');
        return JSON.parse(isi);      // nilai ini masuk ke .then berikutnya
    })
    .then(data => {
        console.log(`${data.length} baris`);
    })
    .catch(err => {
        console.error('Gagal:', err.message);   // menangkap galat dari SEMUA .then di atas
    })
    .finally(() => {
        console.log('Selesai, berhasil atau tidak');
    });
Keunggulan dibanding callback: rantai .then() tetap rata, tidak menjorok ke kanan, dan cukup satu .catch() di ujung untuk menangani galat dari seluruh rantai.
Coba di latihan-async. Pakai data.json yang sama dari Section 3.1. Buat 43-promise.js berisi kode di atas:
$ node 43-promise.js Berhasil 3 baris Selesai, berhasil atau tidak
Coba juga: ganti nama berkas jadi 'tidak-ada.json' yang memang tidak ada, jalankan lagi — perhatikan yang tercetak hanya Gagal: ... dan Selesai, berhasil atau tidak, blok .then() dilewati semua.

4.4 Membuat Promise Sendiri

Sebagian besar waktu kalian hanya memakai Promise yang sudah disediakan pustaka. Membuat sendiri diperlukan saat membungkus API lama berbasis callback:

function tunggu(detik) {
    return new Promise((resolve, reject) => {
        if (detik < 0) {
            reject(new Error('Detik tidak boleh negatif'));
            return;
        }
        setTimeout(() => resolve(`Selesai setelah ${detik} detik`), detik * 1000);
    });
}

tunggu(2)
    .then(pesan => console.log(pesan))
    .catch(err => console.error(err.message));
Fungsi Dipanggil ketika Keadaan menjadi
resolve(nilai)Operasi berhasilfulfilled
reject(error)Operasi gagalrejected
Selalu reject(new Error(...)), bukan reject('teks'). Objek Error membawa stack trace yang menunjukkan baris penyebab masalah. Menolak dengan string biasa membuat pelacakan bug jauh lebih sulit.

5. async / await Indikator 2.3

async/await adalah cara menulis Promise yang terlihat seperti kode sinkron biasa. Di baliknya tetap Promise — hanya sintaksnya yang jauh lebih mudah dibaca. Ini adalah gaya penulisan yang akan kita pakai sepanjang semester.

5.1 Dua Aturan Dasar

Kata kunci Aturannya
async Ditulis di depan fungsi. Fungsi itu selalu mengembalikan Promise, apa pun isinya
await Menunggu Promise selesai lalu mengambil nilainya. Hanya boleh di dalam fungsi async — atau di baris paling luar berkas ESM (top-level await)

5.2 Perbandingan Langsung

Kode yang sama, ditulis dengan tiga gaya berbeda:

// ❌ Callback — menjorok ke kanan
fs.readFile('a.json', 'utf-8', (err, isi) => {
    if (err) return console.error(err);
    const data = JSON.parse(isi);
    console.log(data.length);
});

// 🙂 Promise — rata, tapi masih berlapis .then
readFile('a.json', 'utf-8')
    .then(isi => JSON.parse(isi))
    .then(data => console.log(data.length))
    .catch(err => console.error(err));

// ✅ async/await — terbaca seperti kode biasa
try {
    const isi = await readFile('a.json', 'utf-8');
    const data = JSON.parse(isi);
    console.log(data.length);
} catch (err) {
    console.error(err);
}
Perhatikan versi ketiga. Bentuknya persis seperti kode PHP yang kalian tulis selama ini — baris demi baris, dengan try/catch yang normal. Padahal di baliknya tetap asinkron dan tidak memblokir event loop. Inilah sebabnya async/await menjadi gaya baku JavaScript modern.

5.3 Bentuk-bentuk Penulisan

(Empat bentuk di bawah semuanya membaca data.json yang sama dari Section 3.1 — ganti salah satu jadi berkas nyata kalau mau mencobanya sendiri.)

// Fungsi biasa
async function ambilData() {
    const isi = await readFile('data.json', 'utf-8');
    return JSON.parse(isi);
}

// Arrow function
const ambilData2 = async () => {
    const isi = await readFile('data.json', 'utf-8');
    return JSON.parse(isi);
};

// Metode dalam class / object
const layanan = {
    async ambil() { /* ... */ }
};

// Top-level await — hanya di berkas ESM
const data = await ambilData();

5.4 Fungsi async Selalu Mengembalikan Promise

async function angka() {
    return 42;                    // terlihat seperti angka biasa
}

console.log(angka());              // Promise { 42 }  ← bukan 42!
console.log(await angka());        // 42              ← harus di-await
Kesalahan nomor satu mahasiswa: lupa menulis await. Gejalanya khas — yang tercetak adalah Promise { <pending> } atau undefined, bukan datanya. Kalau kalian melihat itu di terminal, periksa dulu apakah ada await yang hilang.

5.5 await di Dalam Perulangan

Ini jebakan yang sangat sering terjadi. map(), filter(), dan forEach() tidak menunggu fungsi async di dalamnya:

// ❌ SALAH — forEach tidak menunggu apa pun
daftarId.forEach(async (id) => {
    const data = await ambil(id);
    hasil.push(data);
});
console.log(hasil);        // [] — kosong, karena belum ada yang selesai

// ✅ BENAR (berurutan) — pakai for...of
for (const id of daftarId) {
    const data = await ambil(id);
    hasil.push(data);
}

// ✅ BENAR (serentak) — map menghasilkan array Promise, lalu ditunggu sekaligus
const hasil = await Promise.all(daftarId.map(id => ambil(id)));

Kapan memilih yang mana dibahas tuntas di Section 8.

6. fetch dan Pemanggilan Layanan Luar Indikator 2.2

fetch() adalah fungsi bawaan untuk melakukan permintaan HTTP. Sejak Node.js 18 ia tersedia langsung tanpa memasang pustaka apa pun, dan sintaksnya sama persis di Node.js maupun di browser — jadi yang kalian pelajari sekarang akan langsung terpakai lagi di Minggu 11 saat membangun antarmuka React.

6.1 Permintaan GET

const respons = await fetch('https://jsonplaceholder.typicode.com/users/1');
const user = await respons.json();

console.log(user.name);       // "Leanne Graham"
Perhatikan ada DUA await. Itu bukan salah ketik:
  • await fetch(...) — menunggu header tanggapan tiba
  • await respons.json() — menunggu badan tanggapan selesai diunduh dan diurai
Melupakan await kedua adalah kesalahan yang sangat sering terjadi — yang tercetak jadi Promise { <pending> }.

6.2 Memeriksa Status — Jangan Dilewati

Ini perilaku fetch yang paling sering mengejutkan: fetch tidak menganggap status 404 atau 500 sebagai kegagalan. Promise-nya tetap fulfilled. Yang membuatnya rejected hanya kegagalan jaringan — server tidak terjangkau, DNS gagal, koneksi putus.

const respons = await fetch('https://api.contoh.id/tidak-ada');

console.log(respons.ok);       // false
console.log(respons.status);   // 404

// ❌ Tanpa pemeriksaan: data jadi { error: "Not Found" }
//    dan program lanjut seolah-olah tidak terjadi apa-apa

// ✅ Pola yang benar — WAJIB dipakai:
if (!respons.ok) {
    throw new Error(`HTTP ${respons.status} — ${respons.statusText}`);
}
const data = await respons.json();

6.3 Fungsi Pembantu yang Layak Dipakai Ulang

// src/http.js
export async function ambilJson(url, opsi = {}) {
    const respons = await fetch(url, opsi);

    if (!respons.ok) {
        throw new Error(`Permintaan gagal: HTTP ${respons.status} pada ${url}`);
    }
    return respons.json();
}

6.4 Permintaan POST

const respons = await fetch('https://jsonplaceholder.typicode.com/posts', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({
        title: 'Judul',
        body: 'Isi tulisan',
        userId: 1
    })
});

const hasil = await respons.json();
Bagian Fungsinya Catatan
method GET, POST, PUT, PATCH, DELETE Tanpa ini, bawaannya GET
headers Metadata permintaan Content-Type wajib untuk kiriman JSON
body Isi kiriman Harus berupa string → bungkus JSON.stringify()
Dua kesalahan klasik pada POST: mengirim object langsung ke body tanpa JSON.stringify(), dan lupa header Content-Type. Keduanya membuat server menerima badan permintaan kosong — dan galatnya membingungkan karena permintaannya sendiri "berhasil".

6.5 Batas Waktu (Timeout)

Secara bawaan, fetch akan menunggu selamanya kalau server tidak menjawab. Pada API produksi hal ini tidak boleh dibiarkan:

const respons = await fetch(url, {
    signal: AbortSignal.timeout(5000)     // batalkan setelah 5 detik
});

7. Penanganan Galat Asinkron Indikator 2.4

Kode asinkron yang tidak menangani galat adalah sumber masalah paling umum pada aplikasi Node.js. Satu Promise yang gagal tanpa penangkap bisa menjatuhkan seluruh proses server — dan bersamanya, semua pengguna yang sedang dilayani.

7.1 try/catch Bekerja dengan await

(Masih memakai data.json yang sama dari Section 3.1. Coba panggil bacaData() dengan nama berkas yang tidak ada untuk melihat jalur catch-nya.)

async function bacaData() {
    try {
        const isi = await readFile('data.json', 'utf-8');
        return JSON.parse(isi);      // galat parse juga tertangkap
    } catch (err) {
        console.error('Gagal membaca:', err.message);
        return [];                       // nilai cadangan yang aman
    } finally {
        console.log('Selesai — blok ini SELALU jalan');
    }
}
Yang tidak bekerja: try/catch tidak menangkap galat dari callback. Kode berikut tetap membuat proses mati: 
try {
    fs.readFile('x.json', (err, isi) => {
        throw err;         // ❌ TIDAK tertangkap di bawah
    });
} catch (e) {
    console.log('tidak pernah sampai sini');
}
Alasannya: saat callback dipanggil, blok try sudah lama selesai dijalankan. Ini salah satu alasan kuat memakai Promise dan async/await.

7.2 Membedakan Jenis Galat

Tidak semua kegagalan sama, dan penanganannya berbeda. Bedakan sejak awal:

Jenis Contoh Terdeteksi lewat Penanganan
Galat jaringan Server mati, DNS gagal fetch ditolak → masuk catch Coba lagi, atau tampilkan pesan gangguan
Galat HTTP 4xx 404, 401, 422 respons.ok === false Salah dari sisi klien — perbaiki permintaan
Galat HTTP 5xx 500, 503 respons.ok === false Salah dari sisi server — coba lagi nanti
Galat penguraian Jawaban bukan JSON yang sah .json() melempar galat Periksa Content-Type
Galat logika Data ada, tetapi tidak masuk akal Validasi kalian sendiri Lempar galat kustom

7.3 Galat Kustom

Membuat kelas galat sendiri membuat penanganan di lapisan atas jauh lebih rapi. Pola ini akan langsung terpakai di Minggu 4 untuk penanganan galat terpusat Express:

// src/galat.js
export class GalatHttp extends Error {
    constructor(status, pesan, url) {
        super(pesan);
        this.name = 'GalatHttp';
        this.status = status;
        this.url = url;
    }
}

// Pemakaian
try {
    const data = await ambilJson(url);
} catch (err) {
    if (err instanceof GalatHttp && err.status === 404) {
        console.log('Data tidak ditemukan, memakai data kosong');
    } else {
        throw err;                 // yang tidak dikenali diteruskan ke atas
    }
}

7.4 Unhandled Rejection

// ❌ Promise gagal tanpa penangkap
ambilJson('https://alamat-salah.contoh');
// → UnhandledPromiseRejection: proses Node.js BERHENTI

// ✅ Selalu tangani
ambilJson(url).catch(err => console.error(err.message));

// ✅ Jaring pengaman terakhir di titik masuk aplikasi
process.on('unhandledRejection', (alasan) => {
    console.error('Promise gagal tanpa penangkap:', alasan);
    process.exit(1);
});
Aturan praktis penanganan galat:
  • Tangkap galat di tempat yang benar-benar bisa melakukan sesuatu terhadapnya
  • Kalau tidak bisa berbuat apa-apa, lempar ulang (throw err) — jangan ditelan diam-diam
  • Jangan pernah menulis catch (e) {} kosong. Galat yang hilang tanpa jejak jauh lebih sulit dilacak daripada aplikasi yang mati dengan pesan jelas
  • Pesan galat harus menyebut apa yang gagal dan di mana

8. Eksekusi Berurutan vs Serentak Indikator 2.3

Setelah paham await, muncul pertanyaan berikutnya yang berdampak besar pada performa: kalau ada tiga operasi asinkron, haruskah dikerjakan satu per satu?

8.1 Berurutan (Sequential)

console.time('berurutan');

const a = await ambil('/api/users');      // tunggu 1 detik
const b = await ambil('/api/posts');      // tunggu 1 detik lagi
const c = await ambil('/api/comments');   // tunggu 1 detik lagi

console.timeEnd('berurutan');            // ± 3000 ms
users1000 ms
posts1000 ms
comments1000 ms
Total: 3000 ms — setiap operasi menunggu yang sebelumnya

8.2 Serentak (Concurrent) dengan Promise.all

console.time('serentak');

const [a, b, c] = await Promise.all([
    ambil('/api/users'),
    ambil('/api/posts'),
    ambil('/api/comments')
]);

console.timeEnd('serentak');              // ± 1000 ms
users1000 ms
posts1000 ms
comments1000 ms
Total: 1000 ms — ketiganya dimulai bersamaan, 3× lebih cepat

8.3 Kapan Memilih yang Mana?

Pakai berurutan kalau... Pakai serentak kalau...
Hasil operasi pertama dibutuhkan operasi kedua Operasi saling tidak bergantung
Contoh: ambil user → lalu ambil pesanan milik user itu Contoh: ambil daftar produk, kategori, dan banner sekaligus
Ada batas laju (rate limit) di API tujuan Jumlah permintaan sedikit dan terkendali
Kesalahan yang sangat sering terjadi: memakai await berurutan padahal operasinya sama sekali tidak saling bergantung. Kode tetap benar, tetapi aplikasinya berkali-kali lipat lebih lambat — dan ini termasuk yang diperiksa saat tinjauan kode.

8.4 Empat Varian Promise

Metode Selesai ketika Kalau ada yang gagal Dipakai untuk
Promise.all Semua berhasil Langsung gagal semuanya Semua data wajib ada
Promise.allSettled Semua selesai Tetap lanjut, statusnya dilaporkan Sebagian boleh gagal
Promise.race Ada satu yang selesai duluan Yang duluan menentukan hasil Timeout, mirror tercepat
Promise.any Ada satu yang berhasil Gagal hanya kalau semua gagal Beberapa sumber cadangan 
// allSettled — cocok saat sebagian sumber boleh gagal
const hasil = await Promise.allSettled([
    ambil('/api/a'),
    ambil('/api/rusak'),
    ambil('/api/c')
]);

hasil.forEach((r, i) => {
    if (r.status === 'fulfilled') {
        console.log(i, 'berhasil', r.value);
    } else {
        console.log(i, 'gagal', r.reason.message);
    }
});

// race — membuat batas waktu buatan
const data = await Promise.race([
    ambil(url),
    tunggu(3000).then(() => { throw new Error('Timeout 3 detik'); })
]);

8.5 Membatasi Jumlah Permintaan Serentak

Promise.all dengan 1000 URL akan menembakkan 1000 permintaan sekaligus — server tujuan bisa memblokir kalian. Solusi sederhana: pecah menjadi kelompok kecil.

async function ambilBerkelompok(daftarUrl, ukuran = 5) {
    const semua = [];

    for (let i = 0; i < daftarUrl.length; i += ukuran) {
        const kelompok = daftarUrl.slice(i, i + ukuran);
        const hasil = await Promise.all(kelompok.map(u => ambilJson(u)));
        semua.push(...hasil);
    }
    return semua;
}

9. Praktik: Gabungkan Data Lokal & Direktori Kampus Latihan

Latihan ini menyatukan seluruh Pertemuan 3: modul, fetch, async/await, penanganan galat, dan perbandingan waktu eksekusi. Skenarionya: data mahasiswa yang kalian olah sejak Pertemuan 1–2 (dari berkas KHS lokal) sekarang perlu dilengkapi email dan kota domisili yang tersimpan di sistem direktori/SSO kampus — layanan terpisah yang hanya bisa diakses lewat API. Karena belum ada direktori kampus sungguhan untuk diajak latihan, kita simulasikan lewat API publik yang bentuk datanya mirip (nama, email, alamat).

Langkah 1 — Struktur Proyek

├── data/
│   └── mahasiswa.json

Langkah 2 — Pembungkus fetch (src/http.js)

export async function ambilJson(url, opsi = {}) {
    const respons = await fetch(url, {
        ...opsi,
        signal: AbortSignal.timeout(5000)
    });

    if (!respons.ok) {
        throw new Error(`HTTP ${respons.status} pada ${url}`);
    }
    return respons.json();
}

Langkah 3 — Gabungkan Data (src/gabung.js)

import { readFile } from 'node:fs/promises';
import { ambilJson } from './http.js';

export async function muatMahasiswaLokal() {
    const isi = await readFile('./data/mahasiswa.json', 'utf-8');
    return JSON.parse(isi);
}

export async function ambilProfilDirektori(id) {
    // Menyimulasikan panggilan ke API direktori kampus lewat API publik
    return ambilJson(`https://jsonplaceholder.typicode.com/users/${id}`);
}

export async function gabungkanSemua(mode = 'serentak') {
    const mahasiswa = await muatMahasiswaLokal();
    const hasil = [];

    if (mode === 'berurutan') {
        for (const m of mahasiswa) {
            const profil = await ambilProfilDirektori(m.idPublik);
            hasil.push({ ...m, email: profil.email, kota: profil.address?.city });
        }
    } else {
        const profilSemua = await Promise.all(
            mahasiswa.map(m => ambilProfilDirektori(m.idPublik))
        );
        mahasiswa.forEach((m, i) => {
            hasil.push({ ...m, email: profilSemua[i].email, kota: profilSemua[i].address?.city });
        });
    }
    return hasil;
}

Langkah 4 — Titik Masuk (index.js)

import { gabungkanSemua } from './src/gabung.js';

for (const mode of ['berurutan', 'serentak']) {
    const mulai = Date.now();

    try {
        const data = await gabungkanSemua(mode);
        const durasi = Date.now() - mulai;

        console.log(`\n[${mode}] selesai dalam ${durasi} ms`);
        data.forEach(m => console.log(`  ${m.nama} — ${m.email} (${m.kota})`));
    } catch (err) {
        console.error(`[${mode}] gagal:`, err.message);
    }
}
