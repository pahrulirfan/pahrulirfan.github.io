Ringkasan Metode yang Wajib Dikuasai

Metode Mengembalikan Dipakai untuk
map() Array baru, panjang sama Mengubah bentuk setiap elemen
filter() Array baru, panjang ≤ asal Menyaring elemen sesuai syarat
reduce() Satu nilai apa saja Meringkas: total, rata-rata, pengelompokan
find() Elemen pertama yang cocok, atau undefined Mencari satu data
some() true / false Apakah ada minimal satu yang cocok?
every() true / false Apakah semua cocok?
sort() Array terurut (mengubah aslinya!) Mengurutkan

1.1 map() — Mengubah Bentuk

map() menjalankan fungsi yang kalian berikan satu kali untuk setiap elemen, lalu mengumpulkan nilai yang dikembalikan fungsi itu ke dalam array baru. Fungsi tersebut menerima tiga argumen — (elemen, indeks, arrayAsli) — tetapi hampir selalu hanya argumen pertama yang dipakai.

// Ambil nama saja
const namaSaja = mahasiswa.map(m => m.nama);
// ["Andi", "Budi", "Citra", "Dewi", "Eko"]

// Memakai indeks (argumen kedua) untuk membuat nomor urut
const bernomor = mahasiswa.map((m, i) => `${i + 1}. ${m.nama}`);
// ["1. Andi", "2. Budi", ...]

// Ubah ke bentuk yang siap dikirim sebagai tanggapan API
const ringkas = mahasiswa.map(m => ({
    id: m.nim,
    label: `${m.nama} (IPK ${m.ipk})`,
    lulusSyarat: m.ipk >= 3.0
}));
// [{ id: "F1D021001", label: "Andi (IPK 3.75)", lulusSyarat: true }, ...]
Tiga hal yang harus melekat soal map():
  • Array hasil selalu baru dan jumlah elemennya sama persis dengan array asal. Kalau jumlahnya berubah, yang kalian butuhkan filter(), bukan map().
  • Array asal tidak berubah — map tidak memutasi.
  • Untuk mengembalikan object dari arrow function, bungkus dengan kurung: m => ({ ... }). Tanpa kurung, { } dikira badan fungsi (kesalahan dari Pertemuan 1).
Coba di latihan-materi-2. Buat berkas 01-map.js: 
// 01-map.js
import { mahasiswa } from './data.js';

const namaSaja = mahasiswa.map(m => m.nama);
const ringkas = mahasiswa.map(m => ({ nama: m.nama, lulus: m.ipk >= 3.0 }));

console.log(namaSaja);
console.log(ringkas);
console.log('array asal utuh?', mahasiswa.length === 5);
$ node 01-map.js [ 'Andi', 'Budi', 'Citra', 'Dewi', 'Eko' ] [ { nama: 'Andi', lulus: true }, { nama: 'Budi', lulus: true }, { nama: 'Citra', lulus: true }, { nama: 'Dewi', lulus: true }, { nama: 'Eko', lulus: false } ] array asal utuh? true

1.2 filter() — Menyaring

Fungsi yang diberikan ke filter() disebut predikat — ia harus mengembalikan nilai yang bisa dibaca sebagai benar/salah. Elemen yang predikatnya benar (truthy) ikut ke array hasil; yang salah dibuang. Panjang array hasil selalu ≤ array asal.

const aktif = mahasiswa.filter(m => m.aktif);
// 4 mahasiswa (Citra tersaring keluar karena aktif: false)

// Beberapa syarat sekaligus dengan && dan ||
const berprestasi = mahasiswa.filter(m => m.aktif && m.ipk >= 3.5);
// Andi dan Dewi

// filter yang mengembalikan array kosong BUKAN error — panjangnya 0
const ds = mahasiswa.filter(m => m.ipk > 4.0);   // []
map vs filter — jangan tertukar: map menjawab “ubah tiap elemen jadi apa?” (jumlah tetap); filter menjawab “elemen mana yang disimpan?” (bentuk tetap, jumlah menyusut). Butuh keduanya? Rangkai: .filter(...).map(...) — lihat 1.5.
Coba di latihan-materi-2. Buat berkas 02-filter.js: 
// 02-filter.js
import { mahasiswa } from './data.js';

const aktif = mahasiswa.filter(m => m.aktif);
const berprestasi = mahasiswa.filter(m => m.aktif && m.ipk >= 3.5);

console.log('aktif      :', aktif.map(m => m.nama));
console.log('berprestasi:', berprestasi.map(m => m.nama));
$ node 02-filter.js aktif : [ 'Andi', 'Budi', 'Dewi', 'Eko' ] berprestasi: [ 'Andi', 'Dewi' ]

1.3 reduce() — Meringkas Jadi Satu Nilai

reduce() adalah metode yang paling ditakuti mahasiswa, padahal polanya sederhana. Ia berjalan dari elemen pertama ke terakhir sambil membawa satu ember penampung (akumulator).

//        akumulator, elemen         nilai awal ember
//             ↓         ↓                    ↓
const totalIpk = mahasiswa.reduce((total, m) => total + m.ipk, 0);
// 17.25

const rataRata = totalIpk / mahasiswa.length;
// 3.45

Langkah demi langkah, supaya jelas apa yang terjadi:

Putaran total masuk m.ipk total keluar
awal——0
1 (Andi)03.753.75
2 (Budi)3.753.206.95
3 (Citra)6.953.9010.85
4 (Dewi)10.853.5514.40
5 (Eko)14.402.8517.25

Ember penampung tidak harus angka. Ini pola pengelompokan yang akan sangat sering kalian pakai:

// Kelompokkan mahasiswa per semester
const perSemester = mahasiswa.reduce((hasil, m) => {
    const kunci = m.semester;
    if (!hasil[kunci]) hasil[kunci] = [];
    hasil[kunci].push(m.nama);
    return hasil;
}, {});

// { "4": ["Dewi", "Eko"], "6": ["Andi", "Budi", "Citra"] }
Dua kesalahan klasik pada reduce():
  • Lupa nilai awal (argumen kedua). Tanpa itu, elemen pertama dipakai sebagai ember — dan hasilnya kacau saat ember seharusnya berupa object atau angka 0. Pada array kosong tanpa nilai awal, reduce bahkan melempar TypeError.
  • Lupa return di dalam badan berkurung kurawal. Ember jadi undefined pada putaran berikutnya, lalu undefined.push(...) membuat program mati.
Kapan pakai reduce? Setiap kali kalian ingin mengubah banyak elemen menjadi satu hasil: total, rata-rata, nilai maksimum, sebuah object pengelompokan, sebuah string gabungan, atau bahkan array baru yang bentuknya tidak sepadan 1:1 dengan asalnya. Kalau hasil akhirnya masih berupa array sepanjang asal → itu map. Kalau lebih pendek tapi elemennya tak berubah → itu filter.
Coba di latihan-materi-2. Buat berkas 03-reduce.js: 
// 03-reduce.js
import { mahasiswa } from './data.js';

const totalIpk = mahasiswa.reduce((total, m) => total + m.ipk, 0);
const rataRata = totalIpk / mahasiswa.length;

const perSemester = mahasiswa.reduce((hasil, m) => {
    (hasil[m.semester] ??= []).push(m.nama);
    return hasil;
}, {});

console.log('total IPK :', totalIpk);
console.log('rata-rata :', rataRata.toFixed(2));
console.log('per semester:', perSemester);
$ node 03-reduce.js total IPK : 17.25 rata-rata : 3.45 per semester: { '4': [ 'Dewi', 'Eko' ], '6': [ 'Andi', 'Budi', 'Citra' ] }
??= (nullish assignment) mengisi hasil[kunci] dengan [] hanya kalau ia masih undefined — bentuk ringkas dari if (!hasil[kunci]) hasil[kunci] = [].

1.4 find(), some(), every()

// find — satu data saja, atau undefined kalau tidak ketemu
const cari = mahasiswa.find(m => m.nim === "F1D021003");
// { nim: "F1D021003", nama: "Citra", ... }

// some — apakah ADA minimal satu?
const adaCumlaude = mahasiswa.some(m => m.ipk >= 3.5);   // true

// every — apakah SEMUA memenuhi?
const semuaLulus = mahasiswa.every(m => m.ipk >= 3.0);   // false (Eko 2.85)

// Pola pemeriksaan yang aman sebelum memakai hasil find:
if (!cari) {
    console.log("Mahasiswa tidak ditemukan");   // nanti → HTTP 404
}
MetodePertanyaan yang dijawabHasil
find“Mana satu elemen yang cocok?”elemen, atau undefined
findIndex“Di posisi ke berapa?”angka indeks, atau -1
some“Ada minimal satu yang cocok?”true / false
every“Semua cocok?”true / false
includes“Array ini mengandung nilai X?” (nilai sederhana, bukan object)true / false
Pada array kosong: some selalu false, every selalu true (“semua nol elemen memenuhi syarat” — ini benar secara logika, tapi sering mengejutkan).
Coba di latihan-materi-2. Buat berkas 04-find-some-every.js: 
// 04-find-some-every.js
import { mahasiswa } from './data.js';

const citra = mahasiswa.find(m => m.nim === 'F1D021003');
const hantu = mahasiswa.find(m => m.nim === 'XXX');

console.log('ketemu   :', citra?.nama);
console.log('tak ada  :', hantu);
console.log('ada >=3.5?', mahasiswa.some(m => m.ipk >= 3.5));
console.log('semua >=3?', mahasiswa.every(m => m.ipk >= 3.0));
$ node 04-find-some-every.js ketemu : Citra tak ada : undefined ada >=3.5? true semua >=3? false

1.5 Merangkai Metode (Chaining)

Karena map() dan filter() mengembalikan array, hasilnya bisa langsung disambung ke metode berikutnya. Inilah rantai filter – map – reduce yang menjadi inti pertemuan ini.

// "Berapa rata-rata IPK mahasiswa aktif semester 6?"
const aktifSemester6 = mahasiswa
    .filter(m => m.aktif && m.semester === 6)   // saring dulu
    .map(m => m.ipk)                              // ambil angkanya
    .reduce((a, b) => a + b, 0) / 2;               // jumlahkan, bagi

// 3.475

// Daftar nama, urut IPK tertinggi, hanya yang aktif
const peringkat = mahasiswa
    .filter(m => m.aktif)
    .sort((a, b) => b.ipk - a.ipk)          // b - a = menurun
    .map((m, i) => `${i + 1}. ${m.nama} — ${m.ipk}`);

// ["1. Andi — 3.75", "2. Dewi — 3.55", "3. Budi — 3.2", "4. Eko — 2.85"]
Awas sort(): metode ini mengubah array aslinya (berbeda dari map/filter). Kalau array asli tidak boleh berubah, salin dulu: [...mahasiswa].sort(...) atau pakai mahasiswa.toSorted(...) yang tersedia di Node.js modern.
Fungsi pembanding sort((a, b) => ...): ia dipanggil berpasang-pasangan dan hanya melihat tanda hasilnya — negatif berarti a di depan b, positif berarti b di depan a, 0 berarti urutan tetap. Karena itu:
  • Angka menaik: (a, b) => a - b
  • Angka menurun: (a, b) => b - a
  • Teks: (a, b) => a.nama.localeCompare(b.nama)
Tanpa fungsi pembanding, sort() mengurutkan sebagai teks — [2, 10, 1] jadi [1, 10, 2].
Coba di latihan-materi-2. Buat berkas 05-chaining.js — menjawab satu pertanyaan nyata dengan satu rantai: 
// 05-chaining.js — "rata-rata IPK mahasiswa aktif semester 6?"
import { mahasiswa } from './data.js';

const terpilih = mahasiswa.filter(m => m.aktif && m.semester === 6);
const rata = terpilih.reduce((s, m) => s + m.ipk, 0) / terpilih.length;

const peringkat = mahasiswa
    .filter(m => m.aktif)
    .toSorted((a, b) => b.ipk - a.ipk)
    .map((m, i) => `${i + 1}. ${m.nama} (${m.ipk})`);

console.log('terpilih:', terpilih.map(m => m.nama));
console.log('rata IPK:', rata.toFixed(2));
console.log(peringkat);
$ node 05-chaining.js terpilih: [ 'Andi', 'Budi' ] rata IPK: 3.48 [ '1. Andi (3.75)', '2. Dewi (3.55)', '3. Budi (3.2)', '4. Eko (2.85)' ]
Dipakai toSorted() (bukan sort()) supaya array hasil filter tidak diurutkan di tempat — lebih aman sebagai kebiasaan.

1.6 Data JSON Bersarang

Data nyata jarang serata contoh di atas. Biasanya ada array di dalam object:

const kelas = [
    {
        kode: "MPK1300210",
        nama: "Pemrograman Web Lanjut",
        peserta: [
            { nama: "Andi", nilai: 85 },
            { nama: "Budi", nilai: 78 }
        ]
    },
    {
        kode: "MPK1300135",
        nama: "DevOps",
        peserta: [
            { nama: "Citra", nilai: 92 }
        ]
    }
];

// flatMap: map + ratakan satu tingkat — semua peserta dari semua kelas
const semuaPeserta = kelas.flatMap(k => k.peserta);
// 3 peserta dalam satu array datar

// Ringkasan per kelas
const laporan = kelas.map(k => ({
    kode: k.kode,
    jumlah: k.peserta.length,
    rataRata: k.peserta.reduce((s, p) => s + p.nilai, 0) / k.peserta.length
}));

// [{ kode: "MPK1300210", jumlah: 2, rataRata: 81.5 },
//  { kode: "MPK1300135", jumlah: 1, rataRata: 92 }]
flatMap vs map + flat: kelas.flatMap(k => k.peserta) sama dengan kelas.map(k => k.peserta).flat() — map menghasilkan array berisi array, lalu flat() meratakannya satu tingkat. flatMap menggabung dua langkah itu dan sedikit lebih cepat.

2. Destrukturisasi, Spread & Optional Chaining Indikator 1.6

Tiga sintaks ini membuat kode jadi jauh lebih pendek dan lebih aman. Ketiganya muncul di hampir setiap berkas kode JavaScript modern, jadi harus dikenali sampai reflek.

2.1 Destrukturisasi Object

Mengambil beberapa properti sekaligus, tanpa menulis nama objectnya berulang kali.

const m = { nim: "F1D021001", nama: "Andi", ipk: 3.75 };

// Cara lama
const nama = m.nama;
const ipk = m.ipk;

// Destrukturisasi
const { nama, ipk } = m;

// Ganti nama variabel
const { nama: namaMahasiswa } = m;

// Nilai bawaan kalau properti tidak ada
const { nama, jurusan = "Teknik Informatika" } = m;
// jurusan → "Teknik Informatika"

// Bersarang
const data = { user: { profil: { kota: "Mataram" } } };
const { user: { profil: { kota } } } = data;
// kota → "Mataram"

Yang paling sering dipakai: destrukturisasi langsung di parameter fungsi. Pola ini akan muncul terus di Express dan React.

// Tanpa destrukturisasi
function tampil(m) {
    return `${m.nama} — ${m.ipk}`;
}

// Dengan destrukturisasi di parameter
function tampil({ nama, ipk }) {
    return `${nama} — ${ipk}`;
}

// Nanti di Express akan terlihat seperti ini:
// app.post('/mahasiswa', (req, res) => {
//     const { nama, nim, ipk } = req.body;   ← pola yang sama
// });
Salah satu jebakan: destrukturisasi properti yang bersarang (const { user: { profil } } = data) akan error kalau user ternyata undefined. Untuk data yang mungkin tak lengkap, beri nilai bawaan di setiap tingkat: const { user: { profil } = {} } = data — atau lebih aman, pakai optional chaining (2.5).
Coba di latihan-materi-2. Buat berkas 07-destr-object.js: 
// 07-destr-object.js
import { mahasiswa } from './data.js';

// destrukturisasi + rename + nilai bawaan sekaligus
const { nama: n, ipk, jurusan = 'Teknik Informatika' } = mahasiswa[0];
console.log(n, ipk, jurusan);

// destrukturisasi di parameter fungsi
const baris = ({ nim, nama }) => `${nim} — ${nama}`;
console.log(mahasiswa.map(baris));
$ node 07-destr-object.js Andi 3.75 Teknik Informatika [ 'F1D021001 — Andi', 'F1D021002 — Budi', 'F1D021003 — Citra', 'F1D021004 — Dewi', 'F1D021005 — Eko' ]

2.2 Destrukturisasi Array

const warna = ["merah", "hijau", "biru"];

const [pertama, kedua] = warna;          // "merah", "hijau"
const [, , ketiga] = warna;               // lewati dua yang pertama
const [kepala, ...sisa] = warna;         // "merah", ["hijau","biru"]

// Menukar nilai tanpa variabel bantu
let a = 1, b = 2;
[a, b] = [b, a];                         // a=2, b=1

2.3 Spread (...)

Tanda tiga titik menyalin isi array atau object ke tempat baru.

// Menyalin dan menggabung array
const a = [1, 2];
const b = [3, 4];
const gabung = [...a, ...b];              // [1, 2, 3, 4]
const salinan = [...a];                   // salinan baru, bukan rujukan

// Menyalin dan menimpa object — POLA PALING SERING DIPAKAI
const m = { nim: "001", nama: "Andi", ipk: 3.75 };

const diperbarui = { ...m, ipk: 3.80 };
// { nim: "001", nama: "Andi", ipk: 3.80 } — m TIDAK berubah

const tanpaIpk = (({ ipk, ...sisa }) => sisa)(m);
// { nim: "001", nama: "Andi" } — pola membuang satu field
// (nanti dipakai untuk membuang password sebelum dikirim ke klien)
Mengapa menyalin, bukan mengubah langsung? Mengubah data asli (mutasi) adalah sumber bug yang sangat sulit dilacak, terutama di React nanti — React memutuskan perlu tidaknya menggambar ulang dengan membandingkan object lama dan baru. Kalau kalian mengubah isinya di tempat, React menganggap tidak ada yang berubah. Biasakan membuat salinan sejak sekarang.
Spread hanya menyalin satu tingkat (shallow copy). { ...m } membuat object luar yang baru, tetapi object atau array di dalam m masih dibagi (rujukan yang sama). 
const asli = { nama: 'Andi', nilai: { uts: 80 } };
const salin = { ...asli };
salin.nilai.uts = 0;
console.log(asli.nilai.uts);   // 0  ← ikut berubah!
Untuk menyalin tingkat dalam juga: { ...asli, nilai: { ...asli.nilai } }, atau structuredClone(asli) untuk salinan penuh.
Coba di latihan-materi-2. Buat berkas 08-spread.js: 
// 08-spread.js
import { mahasiswa } from './data.js';

const andi = mahasiswa[0];

// menyalin + menimpa satu field (tanpa mengubah asli)
const naik = { ...andi, ipk: 3.90 };

// membuang satu field (mis. sebelum dikirim ke klien)
const { aktif, ...tanpaAktif } = andi;

// menggabung dua array
const semuaNama = ['(daftar)', ...mahasiswa.map(m => m.nama)];

console.log(naik.ipk, '| asli:', andi.ipk);
console.log(tanpaAktif);
console.log(semuaNama);
$ node 08-spread.js 3.9 | asli: 3.75 { nim: 'F1D021001', nama: 'Andi', ipk: 3.75, semester: 6 } [ '(daftar)', 'Andi', 'Budi', 'Citra', 'Dewi', 'Eko' ]

2.4 Rest Parameter

Kalau spread (2.3) membongkar array/object jadi elemen-elemen lepas, rest melakukan kebalikannya: mengumpulkan sisa nilai menjadi satu array. Tanda ... sama, tetapi maknanya ditentukan posisi — di sisi kiri = atau di parameter fungsi berarti "kumpulkan".

// Menampung argumen sebanyak apa pun
function jumlahkan(...angka) {
    return angka.reduce((a, b) => a + b, 0);
}
jumlahkan(1, 2, 3, 4);      // 10

// Parameter tetap + sisanya dikumpulkan
function sapa(pembuka, ...nama) {
    return `${pembuka} ${nama.join(', ')}`;
}
sapa('Halo', 'Andi', 'Budi');   // "Halo Andi, Budi"

2.5 Optional Chaining (?.) dan Nullish Coalescing (??)

Data dari API atau basis data sering tidak lengkap. Dua operator ini mencegah aplikasi mati hanya karena satu field kosong.

const user = { nama: "Andi" };   // tidak punya .alamat

// ❌ Aplikasi mati:
// console.log(user.alamat.kota);
//   TypeError: Cannot read properties of undefined

// ✅ Aman:
console.log(user.alamat?.kota);           // undefined, tidak error

// Rantai panjang pun aman
console.log(user.alamat?.kota?.toUpperCase());

// Juga bekerja untuk pemanggilan metode dan indeks array
user.simpan?.();                          // dipanggil hanya jika ada
user.nilai?.[0];

?? memberi nilai cadangan — tetapi hanya untuk null dan undefined. Ini bedanya dengan ||, dan perbedaan ini sering menjadi bug:

const jumlah = 0;

console.log(jumlah || 10);      // 10 ❌ — 0 dianggap "kosong"
console.log(jumlah ?? 10);      // 0  ✅ — 0 adalah nilai sah

// Gabungan yang paling sering dipakai:
const kota = user.alamat?.kota ?? "Belum diisi";
Nilai x || "cadangan" x ?? "cadangan"
null"cadangan""cadangan"
undefined"cadangan""cadangan"
0"cadangan" ⚠️0
"""cadangan" ⚠️""
false"cadangan" ⚠️false
Aturan pakai: ?. untuk menelusuri struktur yang mungkin tidak ada; ?? untuk memberi nilai cadangan. Keduanya sering berpasangan: data?.profil?.kota ?? 'Belum diisi'. Jangan pakai ?. di mana-mana — kalau sebuah field seharusnya selalu ada, biarkan error muncul supaya bug ketahuan.
Coba di latihan-materi-2. Buat berkas 09-optional-chaining.js: 
// 09-optional-chaining.js
const pesanan = [
    { id: 1, pelanggan: { nama: 'Andi', alamat: { kota: 'Mataram' } }, diskon: 0 },
    { id: 2, pelanggan: { nama: 'Budi' } },
    { id: 3 }
];

for (const p of pesanan) {
    const kota = p.pelanggan?.alamat?.kota ?? '(tidak ada)';
    const diskon = p.diskon ?? 0;
    console.log(`#${p.id}  ${p.pelanggan?.nama ?? '???'}  kota=${kota}  diskon=${diskon}`);
}
$ node 09-optional-chaining.js #1 Andi kota=Mataram diskon=0 #2 Budi kota=(tidak ada) diskon=0 #3 ??? kota=(tidak ada) diskon=0
Coba ubah p.diskon ?? 0 menjadi p.diskon || 5: baris #1 (diskon asli 0) akan salah menampilkan 5, karena || menganggap 0 sebagai "kosong". Inilah alasan memakai ??.

3. Praktik: Rekap KHS & Perhitungan IPS Latihan

Bagian ini menyatukan semua yang sudah dibahas, dan mulai membangun bagian pertama dari sistem akademik sederhana yang akan kita kembangkan sepanjang semester ini — dari sekadar mengolah JSON di pertemuan ini, sampai jadi API dan antarmuka utuh di pertemuan-pertemuan berikutnya. Kita mulai dari satu berkas JSON — Kartu Hasil Studi (KHS) mentah — lalu mengubahnya menjadi rekap IPS hanya dengan rantai filter – map – reduce.

Praktik ini pakai proyek terpisah: praktek-materi-2. Folder latihan-materi-2 tadi hanya untuk mencoba potongan kode; praktik yang dinilai dikerjakan di proyek sendiri — sama seperti pwl-praktik di Pertemuan 1. Simpan folder ini, karena akan dilanjutkan menjadi API di Pertemuan 4.

Langkah 0 — Buat Proyek Praktik

$ mkdir praktek-materi-2 $ cd praktek-materi-2 $ npm init -y $ mkdir data

Tambahkan "type": "module" di package.json agar bisa memakai import. Semua berkas di langkah berikut dibuat di dalam praktek-materi-2.

Langkah 2 — Baca Berkas JSON

// rekap-ips.js
import { readFile } from 'node:fs/promises';

const isi = await readFile('./data/khs.json', 'utf-8');
const khs = JSON.parse(isi);

console.log(`Total baris: ${khs.length}`);   // 6
JSON.parse() vs JSON.stringify() — pasangan yang akan kalian pakai terus-menerus:
  • JSON.parse(teks) → teks JSON menjadi object JavaScript
  • JSON.stringify(obj) → object JavaScript menjadi teks JSON
  • Padanan PHP: json_decode() dan json_encode()

Langkah 3 — Saring Nilai yang Final

const final = khs.filter(k => k.status === 'final');
// 5 baris — mata kuliah yang dibatalkan dibuang

Langkah 4 — Hitung Poin Tiap Baris

Rumus IPS: poin = sks × bobot nilai huruf. Tambahkan field poin ke tiap baris dengan map.

const bobot = { A: 4, B: 3, C: 2, D: 1, E: 0 };

const denganPoin = final.map(k => ({ ...k, poin: k.sks * bobot[k.nilaiHuruf] }));
// baris pertama sekarang punya: poin: 8   (2 sks × bobot A 4)

Langkah 5 — Ringkas dengan reduce()

Dua total ini sudah cukup untuk menghitung IPS:

const totalSks  = denganPoin.reduce((s, k) => s + k.sks, 0);   // 11
const totalPoin = denganPoin.reduce((s, k) => s + k.poin, 0);   // 39
const ips = totalPoin / totalSks;                                  // 3.545...

Langkah 6 — Program Utuh

Gabungkan semuanya. Dibuat sesederhana mungkin — yang dinilai adalah kalian paham rantai filter → map → reduce-nya, bukan kerapian keluaran.

// rekap-ips.js
import { readFile } from 'node:fs/promises';

const bobot = { A: 4, B: 3, C: 2, D: 1, E: 0 };
const khs = JSON.parse(await readFile('./data/khs.json', 'utf-8'));

const final = khs.filter(k => k.status === 'final');

const totalSks  = final.reduce((s, k) => s + k.sks, 0);
const totalPoin = final.reduce((s, k) => s + k.sks * bobot[k.nilaiHuruf], 0);

console.log('Mata kuliah final :', final.length, 'dari', khs.length);
console.log('Total SKS         :', totalSks);
console.log('IPS Semester      :', (totalPoin / totalSks).toFixed(2));

Hasil:

$ node rekap-ips.js Mata kuliah final : 5 dari 6 Total SKS : 11 IPS Semester : 3.55

Langkah 7 — Menyederhanakan dengan Pustaka opsional

Operasi seperti "jumlahkan field X", "kelompokkan per Y", "urutkan per beberapa kunci" muncul terus-menerus. Pustaka Lodash menyediakannya sebagai satu pemanggilan. Pasang seperti paket lain (pola dari Pertemuan 1):

$ npm install lodash

Bandingkan — rekap per kategori yang di Langkah 5 butuh reduce bertingkat, di sini jadi dua baca:

import _ from 'lodash';

const denganPoin = final.map(k => ({ ...k, poin: k.sks * bobot[k.nilaiHuruf] }));

const ips         = _.sumBy(denganPoin, 'poin') / _.sumBy(denganPoin, 'sks');
const perKategori = _.mapValues(_.groupBy(denganPoin, 'kategori'), r => _.sumBy(r, 'poin'));
const terbaik     = _.maxBy(denganPoin, 'poin').mataKuliah;

console.log(ips.toFixed(2), perKategori, terbaik);
// 3.55 { wajib: 33, pilihan: 6 } "Basis Data Lanjut"
Sering kali pustaka pun tak perlu. Pengelompokan sekarang sudah bawaan JavaScript modern (Node 21+): 
const perKategori = Object.groupBy(denganPoin, k => k.kategori);
// { wajib: [ ...5 baris... ], pilihan: [ ...2 baris... ] }
Alternatif Lodash yang lebih modern & ringan: es-toolkit dan radash (fungsi yang sama, ukuran jauh lebih kecil).
Untuk penilaian Pertemuan 2, kerjakan versi reduce dulu (Langkah 6). Indikator 1.5 menguji apakah kalian paham cara kerja map/filter/reduce. Pustaka dipakai setelah paham — supaya saat membaca kode pustaka (atau kode buatan AI), kalian tahu apa yang sebenarnya terjadi di dalamnya.
“Yang penting paham, sintaks nanti dibantu AI” — sebagian besar benar. Yang perlu melekat bukan hafalan urutan tanda kurung, melainkan:
  • Tahu transformasi apa yang dibutuhkan — "saring dulu, kelompokkan per kategori, jumlahkan poin, bagi dengan sks". Ini yang kalian ketik ke AI sebagai perintah.
  • Bisa membaca & memverifikasi hasilnya — apakah reduce punya nilai awal? apakah sort mengubah array asli? apakah array kosong ditangani (ingat [].reduce tanpa nilai awal → error, 0/0 → NaN)? AI sering meleset di titik-titik ini.
  • Kenal kosakatanya — map, filter, reduce, groupBy, flatMap. Tanpa ini kalian tidak bisa menilai apakah jawaban AI sudah tepat atau berputar-putar.
Jadi latihan menulis rantai ini bukan supaya hafal, tapi supaya fasih membaca — keterampilan yang justru makin penting saat kode datang dari AI.

Latihan Mandiri

Kerjakan di praktek-materi-2, kembangkan rekap-ips.js (atau buat berkas baru) untuk menjawab pertanyaan berikut. Semuanya bisa diselesaikan dengan metode yang sudah dibahas — tanpa perulangan for manual.

  1. Berapa IPS jika hanya mata kuliah kategori "wajib" yang dihitung (abaikan "pilihan")?
  2. Mata kuliah apa saja yang nilainya di bawah B (C, D, atau E)? Tampilkan sebagai daftar nama. (petunjuk: filter lalu map)
  3. Apakah ada mata kuliah bernilai A dengan SKS lebih dari 2? (petunjuk: some)
  4. Apakah semua mata kuliah wajib lulus (nilai bukan D atau E)? (petunjuk: every setelah filter kategori)
  5. Buat rekap per kategori berupa object { wajib: { sks, poin, ips }, pilihan: { ... } } dengan satu reduce.
  6. Bungkus pembacaan berkas dengan try/catch sehingga kalau data/khs.json tidak ada, program mencetak pesan yang jelas (mis. "Berkas KHS tidak ditemukan di ./data/khs.json") lalu berhenti rapi — bukan menumpahkan stack trace.
  7. Tambahkan satu berkas khs2.json untuk mahasiswa kedua, lalu ubah program agar menerima nama berkas dari argumen: node rekap-ips.js data/khs2.json (petunjuk: process.argv[2] dari Pertemuan 1).
Menuju Pertemuan 3: perhatikan kata await pada readFile. Membaca berkas adalah operasi asinkron — Node tidak berhenti menunggu, ia lanjut mengerjakan hal lain dan kembali saat berkasnya siap. Bagaimana persisnya itu bekerja, dan bagaimana menanganinya dengan benar, dibahas di Pertemuan 3: Modul dan Pemrograman Asinkron — di sana data KHS ini akan digabungkan dengan data dari layanan lain lewat fetch.
