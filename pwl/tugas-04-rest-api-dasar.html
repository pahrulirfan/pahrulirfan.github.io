Tugas 4 — REST API Dasar dengan Express

Pertemuan 4, lanjutan dari Materi 4: REST API Dasar dengan Express dan Pengenalan GraphQL

REST API dengan Data Sendiri Tugas 4

Tujuan: mahasiswa mampu meng-install Express, menjalankan server, lalu membuat route REST untuk melihat data (GET daftar dan GET detail) dengan data buatan sendiri. Kalian tidak membuat ulang API Mahasiswa dari materi: ganti topiknya dengan data milik kalian. Rujukan langkah-langkahnya ada di Materi 4.

Instruksi

  1. Tentukan data kalian sendiri. Pilih satu topik yang berbeda dari API Mahasiswa dan dari topik teman, lalu buat data dalam bentuk array of object, minimal 10 data.
    • Setiap data punya id (angka unik) dan minimal 3 field lain yang sesuai topik.
    • Contoh topik: koleksi buku, film favorit, daftar menu kantin, playlist, game yang pernah dimainkan, tempat makan di Mataram, dan seterusnya (lihat Contoh Bentuk Data).
    • Simpan data di file terpisah, misalnya src/data/buku.js, lalu export array-nya (seperti src/data/mahasiswa.js di materi).
  2. Install dan jalankan Express seperti Section 3 Materi 4: buat folder proyek, npm init -y, aktifkan type: module, tambahkan script dev dengan --watch, lalu npm install express. Pastikan GET / menampilkan teks sambutan.
  3. Buat route untuk resource kalian. Nama resource harus berbentuk jamak, huruf kecil, tanpa kata kerja (contoh: /buku, /film). Route yang wajib:
    MethodURLFungsinyaStatus
    GET/nama-resourceMenampilkan semua data200
    GET/nama-resource/:idMenampilkan satu data berdasarkan id200, atau 404 kalau id tidak ada
  4. Opsional (nilai tambah): hapus data. Kalau kalian bisa, tambahkan DELETE /nama-resource/:id yang mengembalikan 204 No Content kalau berhasil, dan 404 kalau id tidak ada. Data hanya hidup di memori, jadi akan kembali ke kondisi awal saat server restart (itu wajar).
  5. Pakai format response yang konsisten seperti Section 7.2: response berhasil dibungkus { data: ... }, response gagal dibungkus { error: { pesan, kode } }.
  6. Uji dengan Postman (atau alat setara seperti Thunder Client, Bruno, REST Client). Buat screenshot:
    • Terminal yang menunjukkan server berjalan (npm run dev).
    • GET daftar: terlihat method, URL, status 200 OK, dan isi response.
    • GET detail dengan id yang ada (status 200).
    • GET detail dengan id yang tidak ada (status 404).
    • Kalau mengerjakan opsional: DELETE yang berhasil (204), lalu GET daftar lagi yang menunjukkan data sudah berkurang.
  7. Isi dokumentasi dan deklarasi penggunaan AI di README.md (lihat bagian di bawah).

Contoh Bentuk Data

Dua contoh berikut hanya gambaran bentuknya (dipendekkan menjadi 3 data). Data di tugas kalian harus berbeda, buatan sendiri, dan berisi minimal 10 data.

Contoh 1 — Koleksi buku

// src/data/buku.js
export const buku = [
    { id: 1, judul: "Laskar Pelangi",   penulis: "Andrea Hirata", tahun: 2005, sudahDibaca: true  },
    { id: 2, judul: "Bumi Manusia",     penulis: "Pramoedya A.T.", tahun: 1980, sudahDibaca: false },
    { id: 3, judul: "Cantik Itu Luka",  penulis: "Eka Kurniawan", tahun: 2002, sudahDibaca: true  },
    // ... lanjutkan sampai minimal 10 buku
];

Route-nya: GET /buku dan GET /buku/:id.

Contoh 2 — Tempat makan

// src/data/tempat-makan.js
export const tempatMakan = [
    { id: 1, nama: "Warung Bu Ani",  jenis: "Nasi campur", hargaRata2: 15000, buka24Jam: false },
    { id: 2, nama: "Kopi Sudut",     jenis: "Kafe",        hargaRata2: 25000, buka24Jam: true  },
    { id: 3, nama: "Sate Pak Dul",   jenis: "Sate",        hargaRata2: 30000, buka24Jam: false },
    // ... lanjutkan sampai minimal 10 tempat
];

Route-nya: GET /tempat-makan dan GET /tempat-makan/:id. Perhatikan nama resource yang terdiri dari dua kata ditulis dengan tanda hubung (kebab-case), seperti Section 2.3.

Struktur proyek yang disarankan: 
api-nama-kalian/
├── src/
│   └── data/
│       └── buku.js
├── screenshot/
├── index.js
├── package.json
├── .gitignore        (isi: node_modules)
└── README.md
Jangan upload folder node_modules ke GitHub. Orang lain bisa membuatnya ulang dengan npm install.
Pengingat dari materi: req.params.id selalu berupa string. Ubah dulu dengan Number(...) sebelum dibandingkan dengan id di data. Untuk opsional DELETE, array hasil import tidak bisa di-assign ulang, jadi gunakan findIndex() lalu splice() untuk menghapus elemennya.

Deklarasi Penggunaan AI

Menggunakan AI (ChatGPT, Claude, Copilot, Gemini, dan sejenisnya) boleh, tetapi kalian wajib mendeklarasikannya dengan jujur di README.md. Yang dinilai adalah kejujuran dan kelengkapan deklarasi, bukan banyak-sedikitnya AI yang dipakai. Isi bagian ini dengan tabel berikut:

## Deklarasi Penggunaan AI

| Bagian | Alat AI | Dipakai untuk apa | Bagaimana saya memeriksa hasilnya |
|--------|---------|-------------------|-----------------------------------|
| Data (src/data/buku.js) | ChatGPT | Membuat 10 contoh data buku | Saya cek sendiri tahun terbit tiap buku |
| Route GET /buku/:id | Claude | Menanyakan kenapa id tidak cocok | Saya uji di Postman, ternyata id masih string |
| README | - | - | - |

Pernyataan: [Saya menggunakan AI pada bagian yang tertulis di tabel. Bagian lain saya kerjakan sendiri.]
  • Tulis setiap bagian yang dibantu AI: data, route, perbaikan error, README, atau lainnya. Kalau suatu bagian tidak memakai AI, boleh diberi tanda -.
  • Jelaskan untuk apa AI dipakai (misalnya membuat data, menjelaskan error, menulis kode, merapikan kalimat), bukan hanya menyebut nama alatnya.
  • Tuliskan cara kalian memeriksa hasil dari AI. Kode dari AI tetap harus kalian pahami dan uji sendiri.
  • Kalau tidak memakai AI sama sekali, tulis tegas: "Saya tidak menggunakan AI dalam mengerjakan tugas ini."
  • Tambahkan minimal satu contoh prompt yang kalian pakai (kalau memakai AI), supaya terlihat apa yang kalian minta.
Bersiaplah ditanya. Kalian bisa diminta menjelaskan kode yang dikumpulkan. Deklarasi yang tidak jujur (misalnya ada bagian yang jelas dibuat AI tetapi tidak dicantumkan) dapat mengurangi nilai tugas.
