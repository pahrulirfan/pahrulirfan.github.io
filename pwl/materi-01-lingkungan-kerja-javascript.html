1. Arsitektur Aplikasi Web Modern Indikator 1.1

Dari Mana Kita Berangkat?

Di mata kuliah Pemrograman Web, kalian sudah membangun aplikasi web dengan PHP dan Laravel. Polanya kurang lebih begini: browser meminta sebuah alamat, server memproses, mengambil data dari database, menempelkannya ke template Blade, lalu mengirim HTML yang sudah jadi ke browser. Setiap kali ada perubahan data, halaman dimuat ulang.

Mata kuliah Pemrograman Web Lanjut melanjutkan dari titik itu. Yang berubah bukan tujuannya, tetapi cara aplikasi disusun: antarmuka dipisahkan dari server, dan keduanya berbicara lewat API.

Analogi restoran:
  • Server-rendered (Laravel/Blade) — kalian pesan makanan, dapur memasak, lalu piring lengkap diantar ke meja. Mau tambah sambal? Piring dibawa ke dapur lagi, ditata ulang, diantar lagi.
  • Antarmuka terpisah + API — dapur (API) hanya mengirim bahan mentah yang sudah dimasak, pelayan (antarmuka) yang menata di meja. Mau tambah sambal? Cukup minta sambal saja, piring tidak perlu dibawa bolak-balik.

3. Node.js, npm & package.json Indikator 1.2 & 1.3

Apa itu Node.js?

Node.js adalah program yang membuat JavaScript bisa dijalankan di luar browser. Mesin JavaScript milik Chrome (V8) diambil, lalu ditambahi kemampuan yang tidak dimiliki browser: membaca berkas, membuka koneksi jaringan, mengakses basis data, dan menjalankan server.

Posisinya persis seperti php di terminal kalian. Kalau PHP menjalankan index.php, Node.js menjalankan index.js.

Fakta Node.js:
  • Dibuat oleh Ryan Dahl tahun 2009
  • Memakai mesin V8 buatan Google, mesin yang sama dengan Chrome
  • Bersifat single-threaded tetapi non-blocking — ini kunci performanya
  • Versi LTS (Long Term Support) adalah yang dipakai untuk produksi. Kita memakai Node.js 24 LTS
  • Dikelola oleh OpenJS Foundation, bukan satu perusahaan

Memasang dan Memeriksa

Unduh dari nodejs.org, pilih versi LTS. Setelah selesai, buka terminal dan pastikan keduanya terbaca:

$ node -v v24.4.1 $ npm -v 11.3.0
Kalau muncul command not found: Node.js belum masuk ke PATH. Tutup terminal, buka lagi. Kalau masih gagal, pasang ulang dan pastikan opsi "Add to PATH" tercentang saat instalasi di Windows.

Memulai Proyek Baru

Alurnya sangat mirip composer init:

$ mkdir latihan-js $ cd latihan-js $ npm init -y Wrote to .../latihan-js/package.json

Sampai di sini folder masih hanya berisi package.json — belum ada kode. Buat berkas index.js lalu isi dengan satu baris. Kalian bisa membuatnya lewat editor (VS Code: New File) atau dari terminal:

# macOS / Linux $ touch index.js # Windows (PowerShell) $ ni index.js

Isi index.js:

// index.js
console.log('Halo dari Node.js!');

Baru setelah berkasnya ada, jalankan dengan node:

$ node index.js Halo dari Node.js!
Alur proyek npm: mkdir membuat folder → npm init -y membuat package.json (KTP proyek) → buat berkas .js dan tulis kode → jalankan dengan node namafile.js. Tidak ada langkah lain yang wajib. Fokus pertemuan ini: memakai npm dan dasar JavaScript.

Objek process: Jendela ke Proses Node

Ketika kalian menjalankan node index.js, Node membuat satu proses sistem operasi untuk menjalankan kode kalian. Di dalam kode, proses itu diwakili oleh satu objek global bernama process — selalu ada, tidak perlu di-import. Lewat process, program bisa mengetahui di lingkungan seperti apa ia sedang berjalan dan berinteraksi dengan dunia luar. Di PHP, informasi serupa tersebar di $_SERVER, $_ENV, $argv, getenv(), dan php_sapi_name(); Node menyatukannya di satu tempat.

Anggota process Isinya Contoh nilai
process.version Versi Node yang sedang dipakai "v24.4.1"
process.platform Sistem operasi "darwin", "win32", "linux"
process.env Semua environment variable (object). Ini yang dibaca dotenv saat memuat .env process.env.DATABASE_URL
process.argv Array argumen baris perintah. Indeks 0 = path node, 1 = path berkas, 2 dan seterusnya = argumen kalian ["/usr/.../node", "/.../index.js", "--nama", "Andi"]
process.cwd() Folder tempat perintah node dijalankan (current working directory) "/Users/andi/latihan-js"
process.pid Nomor ID proses dari sistem operasi 48213
process.uptime() Berapa detik proses sudah berjalan 0.081
process.memoryUsage() Pemakaian memori proses (object, dalam byte) { rss: 38 000 000, ... }
process.exit(kode) Menghentikan proses sekarang juga. 0 = sukses, selain 0 = gagal process.exit(1)
process.stdout / process.stdin Aliran keluaran & masukan terminal. console.log sebenarnya menulis ke process.stdout process.stdout.write("teks")
process.on('exit', fn) Memasang fungsi yang dijalankan tepat sebelum proses berhenti (untuk membersihkan sesuatu) —

Buat berkas process-info.js di latihan-js untuk melihat isinya sendiri:

// process-info.js
console.log('Versi Node :', process.version);
console.log('Sistem OS  :', process.platform);
console.log('Folder     :', process.cwd());
console.log('PID        :', process.pid);
console.log('Argumen    :', process.argv.slice(2));
$ node process-info.js --nama Andi Versi Node : v24.4.1 Sistem OS : darwin Folder : /Users/andi/latihan-js PID : 48213 Argumen : [ '--nama', 'Andi' ]
Kenapa perlu tahu ini sekarang? process.env adalah cara kita menyimpan konfigurasi rahasia (lihat .env di Section 5), process.argv dipakai membuat perkakas baris perintah, dan process.exit() menentukan sukses/gagalnya sebuah skrip — penting saat otomasi & pengujian di pertemuan lanjut. Untuk sekarang cukup kenali bahwa process adalah "papan dashboard" proses Node kalian.

Memasang Paket

Paket (package) adalah kode siap pakai buatan orang lain yang kita ambil dari npm. Ini padanan composer require. Kita coba dengan chalk — paket kecil untuk memberi warna pada teks di terminal:

$ npm install chalk added 1 package in 1s

Tiga hal berubah setelah perintah itu:

  • package.json — muncul "chalk" di dalam "dependencies"
  • package-lock.json — dibuat/diperbarui, mencatat versi persis yang terpasang
  • folder node_modules/ — berisi kode chalk yang sebenarnya, hasil unduhan

Perintah npm lain yang sering dipakai:

$ npm install chalk # tambah paket ke dependencies $ npm install -D vitest # tambah ke devDependencies (hanya untuk pengembangan) $ npm install # pasang semua paket yang tercatat di package.json $ npm ci # pasang persis sesuai package-lock.json $ npm uninstall chalk # hapus paket $ npm audit # periksa kerentanan keamanan paket
Paket yang lebih besar seperti Express (kerangka server) baru kita pasang di Pertemuan 4. Untuk sekarang cukup paket kecil seperti chalk supaya fokusnya di cara memasang dan memakai paket, bukan pada isi paketnya.

Membedah package.json

Berkas ini adalah KTP proyek. Isinya menentukan bagaimana proyek dijalankan dan pustaka apa saja yang dibutuhkan. Setelah npm init -y, ditambah "type": "module" dan chalk tadi, isinya kira-kira begini:

{
  "name": "latihan-js",
  "version": "1.0.0",
  "type": "module",          // pakai sintaks import/export modern
  "main": "index.js",
  "scripts": {
    "dev": "node --watch index.js",
    "start": "node index.js"
  },
  "dependencies": {
    "chalk": "^5.3.0"        // paket yang tadi dipasang
  }
}
Kunci Fungsi
name, version Identitas proyek
type "module" = pakai import/export. Tanpa ini, Node memakai gaya lama require() (dibahas di Pertemuan 3)
main Berkas utama proyek — titik masuk kalau proyek ini dipakai sebagai paket oleh proyek lain
scripts Pintasan perintah (lihat penjelasan di bawah). Padanan php artisan
dependencies Pustaka yang dibutuhkan aplikasi saat berjalan
devDependencies Pustaka yang hanya dibutuhkan saat mengembangkan (penguji, linter). Tidak ikut ke produksi — diisi lewat npm install -D <paket>

Lebih jauh soal "scripts"

Setiap entri di scripts berupa pasangan "nama": "perintah yang dijalankan". Kalian memanggilnya dengan npm run <nama>, dan npm menjalankan perintah di sebelah kanannya seolah kalian mengetiknya sendiri di terminal.

"scripts": {
  "dev":   "node --watch index.js",
  "start": "node index.js",
  "lint":  "eslint ."
}
  • npm run dev menjalankan node --watch index.js. Opsi --watch membuat Node menjalankan ulang berkas otomatis setiap kali kalian menyimpan perubahan — jadi tidak perlu berkali-kali menekan panah atas lalu Enter. Cocok saat sedang menulis kode (dev = mode pengembangan).
  • Nama skrip bebas. "dev" dan "start" hanya kesepakatan umum, bukan kata kunci. Kalau kalian menamainya "jalan", memanggilnya jadi npm run jalan. Perintah di kanan tidak berubah artinya.
  • Dua nama diperlakukan khusus dan boleh dipanggil tanpa kata run: npm start (sama dengan npm run start) dan npm test (sama dengan npm run test). Semua nama lain wajib memakai run — npm dev saja akan gagal, harus npm run dev.
  • Ketik npm run tanpa argumen untuk melihat daftar skrip yang tersedia. Kalau nama salah, npm menjawab Missing script: "...".
Padanan Laravel: scripts di npm itu seperti composer.json bagian "scripts", dan menjalankannya (npm run dev) mirip php artisan <perintah> — sama-sama pintasan untuk perintah panjang yang sering diulang.

Semantic Versioning (semver)

Versi paket ditulis tiga angka: MAJOR.MINOR.PATCH. Aturannya baku dan dipatuhi hampir semua paket npm.

Bagian Contoh naik Artinya
MAJOR 4.18.2 → 5.0.0 Ada perubahan yang merusak kode lama. Wajib baca panduan migrasi
MINOR 4.18.2 → 4.19.0 Ada fitur baru, kode lama tetap jalan
PATCH 4.18.2 → 4.18.3 Perbaikan bug saja

Tanda di depan versi menentukan seberapa longgar npm boleh memperbarui:

Penulisan Versi yang diterima Kapan dipakai
^4.18.2 ≥ 4.18.2 dan < 5.0.0 Default npm. Aman untuk sebagian besar kasus
~4.18.2 ≥ 4.18.2 dan < 4.19.0 Hanya mau perbaikan bug
4.18.2 Persis versi itu saja Kalau versi lain terbukti bermasalah

Untuk Apa package-lock.json?

package.json menulis ^4.18.2 — itu rentang, bukan versi persis. Kalau teman kalian menjalankan npm install tiga bulan kemudian, dia bisa mendapat 4.21.0. Kode yang sama, pustaka berbeda, bug muncul di komputernya saja.

package-lock.json mencatat versi persis setiap paket beserta seluruh turunannya. Selama berkas ini ikut disalin, semua orang memasang pustaka yang identik. Jangan diedit tangan — npm yang mengurusnya.

Tiga jenis berkas, tiga perlakuan:
  • package.json + package-lock.json — berkas inti proyek, selalu ikut ke mana pun proyek dibagikan
  • node_modules/ — hasil unduhan, tidak perlu ikut dibagikan; cukup jalankan npm install untuk membuatnya kembali
  • .env — berisi rahasia (password, kunci API), jangan pernah dibagikan atau diunggah; sebagai gantinya bagikan .env.example yang hanya berisi nama variabelnya
Titik periksa Section 3: di terminal kalian, node -v dan npm -v menampilkan versi; ada folder proyek berisi package.json; kalian bisa menjelaskan beda dependencies dan devDependencies serta guna package-lock.json.

4. JavaScript vs PHP: Yang Berbeda Indikator 1.4

Kalian sudah bisa memprogram. Percabangan, perulangan, array, fungsi — semua itu tidak perlu dipelajari ulang. Bagian ini hanya membahas hal yang berbeda, karena di situlah kesalahan biasanya muncul.

Praktikkan sambil membaca — pakai proyek latihan-js dari Section 3. Setiap subbagian di bawah (4.1–4.5) punya kotak “Coba di latihan-js”. Pola kerjanya selalu sama:

4.1 let, const, dan var

Di PHP, kalian menulis $nama = "Andi"; tanpa peduli apakah nanti nilainya akan diganti atau tidak — caranya sama saja. JavaScript memaksa kalian menyatakan itu di depan, lewat kata yang dipakai untuk membuat variabel:

  • const — nilainya tidak akan diganti setelah baris ini. Kalau dicoba, JavaScript menolak (error).
  • let — nilainya boleh diganti nanti, misalnya angka yang bertambah di dalam perulangan.
  • var — cara lama sebelum let/const ada. Perilakunya lebih berantakan (dibahas di 4.2) dan tidak dipakai lagi di kode baru.
const nama = "Andi";      // tidak akan di-assign ulang → PILIHAN UTAMA
let total = 0;            // nilainya akan berubah
var lama = "jangan";      // gaya lama, JANGAN dipakai lagi
Aturan praktis: pakai const untuk semua hal. Ganti ke let hanya kalau editor/Node memprotes karena nilainya memang di-assign ulang. var tidak punya alasan untuk dipakai lagi di kode baru.

Titik yang sering bikin bingung: const pada array/object

Bayangkan variabel sebagai label pada sebuah kotak, dan isinya adalah nilai yang disimpan. const hanya merekatkan labelnya — label itu tidak boleh dipindah ke kotak lain. Tetapi kalau kotaknya berisi array atau object, kalian tetap boleh membuka kotak itu dan mengubah isinya, karena itu bukan mengganti label.

const daftar = [1, 2];
daftar.push(3);          // BOLEH — ini mengubah ISI kotak, labelnya tetap "daftar"
daftar = [4, 5];       // ERROR — ini usaha memindah label ke kotak lain

Jadi aturannya: const melarang penulisan ulang tanda = (label pindah kotak), bukan melarang perubahan isi array/object di dalamnya. Kalau kalian memang butuh menimpa seluruh isi dengan array/object yang benar-benar baru (bukan mengubah isinya sedikit demi sedikit), itu tandanya variabelnya butuh let, bukan const.

Coba di latihan-js. Buat berkas 41-variabel.js: 
// 41-variabel.js
const nama = "Andi";
let total = 0;
total = total + 10;          // let boleh di-assign ulang

const daftar = [1, 2];
daftar.push(3);              // isi array diubah
console.log(nama, total, daftar);

nama = "Budi";                // baris ini akan menghentikan program
Jalankan:
$ node 41-variabel.js Andi 10 [ 1, 2, 3 ] TypeError: Assignment to constant variable.
Setelah melihat galatnya, hapus baris terakhir lalu jalankan lagi — sekarang bersih.

4.2 Lingkup Variabel (Scope)

Lingkup (scope) adalah jawaban atas pertanyaan: "dari bagian kode mana saja sebuah variabel bisa dibaca?" Variabel tidak ada di mana-mana — ia hanya hidup di wilayah tempat ia dibuat. Salah paham soal ini adalah sumber bug paling sering pada minggu-minggu awal.

Tiga tingkat lingkup

Lingkup Dibuat di mana Bisa dibaca dari
Global Di luar semua fungsi dan blok Seluruh berkas — hati-hati, mudah tercemar
Fungsi Di dalam sebuah function Hanya di dalam fungsi itu (termasuk fungsi bersarang di dalamnya)
Blok Di dalam sepasang { } mana pun — if, for, while, atau blok telanjang Hanya di dalam { } itu. Hanya berlaku untuk let dan const

Perbedaan var vs let/const

function contoh() {
    if (true) {
        var a = "var";    // lingkup: SELURUH fungsi contoh()
        let b = "let";    // lingkup: blok { } milik if ini saja
    }
    console.log(a);       // "var"  — bocor keluar blok if
    console.log(b);       // ReferenceError: b is not defined
}

var mengabaikan blok { } — ia selalu naik ke tingkat fungsi terdekat. let dan const berhenti tepat di blok tempat ia ditulis. Blok yang lebih rapat hampir selalu lebih aman, karena variabel tidak "bocor" ke tempat yang tidak kalian sangka.

Coba di latihan-js. Buat berkas 42-scope.js dan ketik ulang kode contoh() di atas: 
// 42-scope.js
function contoh() {
    if (true) {
        var a = "var: bocor keluar blok";
        let b = "let: hanya di dalam blok";
    }
    console.log(a);     // jalan
    console.log(b);     // akan error di sini
}
contoh();
Jalankan:
$ node 42-scope.js var: bocor keluar blok ReferenceError: b is not defined
Sekarang perbaiki: pindahkan let b ke luar if (deklarasikan di awal fungsi), isi nilainya di dalam if. Jalankan lagi — kedua console.log berhasil. Simpan kedua versi supaya kelihatan bedanya.

Hoisting: kapan variabel "mulai ada"

JavaScript memindahkan deklarasi variabel ke atas lingkupnya sebelum kode dijalankan (disebut hoisting). Yang membedakan:

console.log(x);   // undefined — var sudah "ada" tapi belum diisi
var x = 5;

console.log(y);   // ReferenceError — y belum boleh disentuh
let y = 5;      // (rentang sebelum baris ini disebut "Temporal Dead Zone")

Dengan let/const, memakai variabel sebelum barisnya langsung dianggap error — ini justru menolong: bug ketahuan lebih cepat, bukan diam-diam bernilai undefined.

Jebakan klasik: var di dalam perulangan

// dengan var — SEMUA cetak 3
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);   // 3, 3, 3
}

// dengan let — tiap iterasi punya i sendiri
for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);   // 0, 1, 2
}

Karena var i hanya satu untuk seluruh fungsi, saat setTimeout akhirnya jalan, perulangan sudah selesai dan i bernilai 3. Dengan let, setiap putaran membuat i baru, sehingga nilai yang "terekam" oleh fungsi di dalamnya tetap benar.

Coba di latihan-js. Buat berkas 42-loop.js, isi dengan kedua perulangan di atas sekaligus: 
// 42-loop.js
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log('var:', i), 100);
}
for (let j = 0; j < 3; j++) {
    setTimeout(() => console.log('let: ', j), 100);
}
Jalankan:
$ node 42-loop.js var: 3 var: 3 var: 3 let: 0 let: 1 let: 2
Bandingkan urutannya dengan penjelasan di atas — var mencetak angka terakhir tiga kali, let mencetak angka yang berbeda tiap baris.

Lingkup bersarang & shadowing

const pesan = "luar";

function cetak() {
    const pesan = "dalam";   // menutupi (shadow) yang di luar
    console.log(pesan);        // "dalam"
}
cetak();
console.log(pesan);            // "luar" — yang di dalam tidak mengubah yang di luar

Fungsi bisa membaca variabel dari lingkup di luarnya (ini yang membuat closure di Pertemuan 2 bekerja), tetapi kalau ada nama yang sama di lingkup lebih dalam, yang dipakai adalah yang paling dekat. JavaScript mencari nama variabel dari lingkup terdalam ke terluar, berhenti pada kecocokan pertama.

Beda dengan PHP: di PHP, fungsi tidak otomatis melihat variabel di luarnya — harus pakai global atau use (...) pada closure. Di JavaScript sebaliknya: fungsi otomatis melihat semua variabel di lingkup luarnya. Ini terasa praktis, tetapi juga alasan kenapa disiplin memakai const dan blok yang rapat itu penting — supaya tidak ada variabel luar yang tidak sengaja ikut terbawa.

Contoh 1 — variabel if yang dibutuhkan di luar

// salah: diskon dideklarasikan di dalam if, mati begitu blok selesai
function hitungBayar(total, anggota) {
    if (anggota) {
        const diskon = total * 0.1;
    }
    return total - diskon;   // ReferenceError: diskon is not defined
}

// benar: deklarasikan di lingkup tempat ia dipakai, isi di dalam if
function hitungBayar(total, anggota) {
    let diskon = 0;
    if (anggota) {
        diskon = total * 0.1;
    }
    return total - diskon;   // 0 kalau bukan anggota
}

Contoh 2 — lupa const/let membuat variabel global tak sengaja

function isiKeranjang() {
    for (i = 0; i < 3; i++) {   // ⚠️ lupa "let" → i jadi global
        /* ... */
    }
}
isiKeranjang();
console.log(i);   // 3  — bocor ke seluruh program, menabrak "i" milik kode lain

Menulis "use strict" di atas berkas (otomatis aktif pada berkas "type": "module") mengubah kelalaian ini menjadi ReferenceError yang langsung terlihat — satu alasan lagi memakai ESM.

Contoh 3 — nama sama di dua fungsi tidak saling mengganggu

function a() { const x = 1; b(); console.log(x); }  // 1
function b() { const x = 99; }                        // x milik b(), terpisah
a();
// b() TIDAK bisa membaca x milik a() — fungsi hanya mengintip ke LUAR,
// mengikuti tempat ia DITULIS, bukan tempat ia DIPANGGIL.

4.3 Tipe Dinamis dan Jebakan ==

Sama seperti PHP, JavaScript tidak mewajibkan penulisan tipe. Bedanya, aturan konversi otomatisnya lebih longgar dan lebih mengejutkan:

console.log("5" == 5);        // true  — tipe dikonversi diam-diam
console.log("5" === 5);       // false — nilai DAN tipe dibandingkan

console.log(0 == "");          // true  😱
console.log(null == undefined); // true  😱
console.log([] == false);      // true  😱

// Aturannya satu kalimat: SELALU pakai === dan !==
Aturan wajib di mata kuliah ini: gunakan === dan !==. Penggunaan == akan dianggap kesalahan pada tinjauan kode, kecuali dalam satu pola yang memang lazim: x == null untuk memeriksa null dan undefined sekaligus.
Coba di latihan-js. Buat berkas 43-tipe.js: 
// 43-tipe.js
console.log("5" == 5, "5" === 5);         // ?
console.log(0 == "", 0 === "");             // ?
console.log([] == false, [] === false);       // ?
console.log(typeof "a", typeof 1, typeof null);  // ?
Tebak dulu hasil tiap baris, baru jalankan node 43-tipe.js untuk mengeceknya:
$ node 43-tipe.js true false true false true false string number object
Perhatikan kolom kiri (==) selalu true karena tipe dikonversi diam-diam, kolom kanan (===) selalu false. Dan typeof null yang seharusnya "null" malah "object" — bug lama JavaScript yang tidak bisa diperbaiki.

4.4 Fungsi Adalah Nilai

Ini perbedaan paling penting dan yang paling sering membuat mahasiswa tersandung. Di JavaScript, fungsi bukan sekadar sesuatu yang dipanggil — fungsi adalah nilai biasa, sama seperti angka atau string. Ia bisa disimpan di variabel, dioper sebagai argumen, dan dikembalikan dari fungsi lain.

// 1. Disimpan di variabel
const sapa = function(nama) {
    return `Halo, ${nama}`;
};

// 2. Arrow function — bentuk ringkas yang paling sering dipakai
const sapa2 = (nama) => `Halo, ${nama}`;

// 3. Dioper sebagai argumen (inilah "callback")
const angka = [1, 2, 3];
const dobel = angka.map((n) => n * 2);   // [2, 4, 6]

// 4. Dikembalikan dari fungsi lain
const pengali = (faktor) => (n) => n * faktor;
const kaliTiga = pengali(3);
console.log(kaliTiga(5));                   // 15
Mengapa ini penting? Seluruh materi setelah ini bergantung pada konsep tersebut:
  • array.map(fn) — fungsi dioper ke metode array (Section 5)
  • app.get('/x', handler) — fungsi dioper ke Express (Minggu 4)
  • tombol.addEventListener('click', fn) — fungsi dioper ke event (Minggu 11)
  • Middleware, promise, dan async semuanya memakai pola yang sama
Kalau bagian ini terasa asing, ulangi sampai paham — ini fondasinya.
Coba di latihan-js. Buat berkas 44-fungsi.js: 
// 44-fungsi.js
// fungsi disimpan di variabel
const sapa = (nama) => `Halo, ${nama}`;
console.log(sapa("Andi"));

// fungsi dioper sebagai argumen (callback)
const nilai = [70, 85, 90];
console.log(nilai.map((n) => n + 5));

// fungsi dikembalikan dari fungsi lain
const pengali = (faktor) => (n) => n * faktor;
const kaliTiga = pengali(3);
console.log(kaliTiga(5));

console.log(typeof sapa);   // bukti: fungsi adalah nilai
$ node 44-fungsi.js Halo, Andi [ 75, 90, 95 ] 15 function

4.5 Bentuk Penulisan Arrow Function

// Satu parameter, langsung mengembalikan nilai
const a = n => n * 2;

// Beberapa parameter → kurung wajib
const b = (x, y) => x + y;

// Badan lebih dari satu baris → kurung kurawal + return
const c = (n) => {
    const hasil = n * 2;
    return hasil + 1;
};

// Mengembalikan object → bungkus dengan kurung biasa
const d = (nama) => ({ nama, aktif: true });
Kesalahan yang sangat sering terjadi: n => { nama: n } mengembalikan undefined, bukan object — kurung kurawal itu dibaca sebagai badan fungsi, bukan object. Bungkus dengan kurung biasa: n => ({ nama: n }).
Coba di latihan-js. Buat berkas 45-arrow.js dan buktikan sendiri kesalahan di atas: 
// 45-arrow.js
const salah = (n) => { nama: n };      // { } dibaca sebagai badan fungsi
const benar = (n) => ({ nama: n });    // ( ) memaksa { } jadi object

console.log(salah("Andi"));   // ?
console.log(benar("Andi"));   // ?
$ node 45-arrow.js undefined { nama: 'Andi' }

Root tanpa password boleh untuk latihan lokal, tetapi jangan pernah dipakai di server produksi — di sana root wajib berpassword kuat dan aplikasi memakai user khusus dengan hak terbatas.

Langkah 4 — buat cek-koneksi.js di latihan-js:

// cek-koneksi.js
import 'dotenv/config';
import mysql from 'mysql2/promise';

const koneksi = await mysql.createConnection(process.env.DATABASE_URL);

6. Praktik: Menyiapkan Proyek dari Nol Latihan

Bagian ini merangkai langkah-langkah dari Section 3 dan 4 menjadi satu alur kerja utuh: dari folder kosong sampai proyek npm yang siap dipakai. Kerjakan sendiri di komputer kalian, jangan hanya membaca.

Fokus praktik ini: membuat proyek npm dari nol, memasang paket dari npm, lalu memakainya di kode. Koneksi ke MySQL tidak diulang di sini — langkah lengkapnya sudah ada di Section 5.3 dan dikerjakan di proyek latihan-js.

Langkah 1 — Buat Folder Proyek & Inisialisasi npm

$ mkdir pwl-praktik $ cd pwl-praktik $ npm init -y Wrote to .../pwl-praktik/package.json

{
  "name": "pwl-praktik",
  "version": "1.0.0",
  "type": "module",
  "main": "index.js"
}

process.version di sini adalah salah satu anggota objek process — papan dashboard proses Node yang dibahas di Section 3. Coba ganti dengan process.platform atau process.cwd() lalu jalankan lagi.

Langkah 3 — Memasang Paket dari npm (contoh: chalk)

Latih pola yang dipakai untuk paket apa pun: pasang → baca dokumentasi → pakai. Kita coba dengan chalk — paket kecil untuk memberi warna pada teks di terminal.

Langkah 3a — pasang paketnya:

$ npm install chalk added 1 package in 1s

Perhatikan apa yang berubah setelah perintah itu:

  • package.json — muncul "chalk" di dalam "dependencies"
  • package-lock.json — dibuat/diperbarui, mencatat versi persis yang terpasang
  • folder node_modules/ — berisi kode chalk yang sebenarnya, hasil unduhan npm

Langkah 3b — baca dokumentasinya dulu, jangan menebak. Buka halaman paket di npmjs.com/package/chalk (atau tautan “Repository” ke GitHub-nya). Di bagian Usage tertulis kira-kira begini:

import chalk from 'chalk';

console.log(chalk.blue('Hello world!'));

Dari dokumentasi itu kita tahu tiga hal: cara meng-import-nya (default export, jadi tanpa kurung kurawal), nama fungsi yang tersedia (chalk.blue, chalk.red, …), dan bahwa fungsi-fungsi itu bisa dirangkai (chalk.bold.bgRed).

// warna.js
import chalk from 'chalk';

Kebiasaan yang dilatih di sini: setiap kali butuh fungsi baru, langkahnya selalu sama — cari paketnya di npm, baca bagian Usage di dokumentasi, baru tulis kode. Bukan menyalin dari jawaban teman. Perhatikan juga: percobaan paket ditaruh di berkasnya sendiri (warna.js), index.js dibiarkan sederhana.
Selesai kalau: node warna.js mencetak teks berwarna dan package.json mencatat chalk di "dependencies". (Bukti koneksi MySQL sudah dikerjakan terpisah di latihan-js, Section 5.3.)
Lanjutan praktik ini — memasang paket sendiri berdasarkan dokumentasi (cowsay, figlet, dan lainnya) — dikerjakan sebagai Tugas 1, bukan lagi di halaman materi ini.
