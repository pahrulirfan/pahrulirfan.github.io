ETS — Mini Project REST API (Express.js + MySQL)

Mini Project ETS ETS

Mahasiswa membuat REST API CRUD menggunakan Express.js + MySQL (Prisma), dengan kasus yang dipilih sendiri dari daftar pilihan yang diberikan. Dikerjakan di rumah, lalu dilengkapi video presentasi.

Ketentuan Umum

  1. Buat REST API menggunakan Express.js dengan struktur berlapis seperti di Pertemuan 5 (routes, controllers, services, data, middleware, validators).
  2. Gunakan MySQL sebagai database, diakses lewat Prisma, dengan migrasi (folder prisma/migrations di-commit) dan seed yang dapat diulang.
  3. Buat tabel utama dengan minimal 6 kolom.
    • Wajib ada kolom angka (contoh: price, stock, gpa, rating).
    • Wajib ada kolom tanggal (contoh: birthdate, created_at, expired_date).
    • Kolom lain bisa berupa teks atau boolean. Salah satu kolom teks harus unik.
  4. Buat satu tabel kedua yang berelasi dengan tabel utama (satu-ke-banyak atau banyak-ke-banyak), misalnya kategori, pelanggan, atau dokter.
  5. Endpoint yang harus ada untuk tabel utama:
    • GET /resource dengan paginasi (halaman dan ukuran) dan satu filter pilihan sendiri (misalnya berdasarkan kategori atau nama)
    • GET /resource/:id, POST /resource, PUT /resource/:id, DELETE /resource/:id
    • Satu endpoint untuk tabel kedua yang menampilkan data beserta relasinya (include)
  6. Satu operasi yang mengubah dua tabel sekaligus (misalnya membuat pesanan sambil mengurangi stok) wajib dibungkus transaksi ($transaction).
  7. Tambahkan middleware: logger (mencatat method + url + status), validasi (Joi, input tidak boleh kosong/salah), dan errorHandler terpusat (format jawaban error seragam; error 500 tidak membocorkan detail).
  8. Gunakan file .env untuk konfigurasi database dan port. .env tidak di-commit; sertakan .env.example.
  9. Lakukan uji API dengan Postman atau REST Client (requests.http) dan screenshot hasil ujicoba: berhasil (200/201/204) dan gagal (400/404/409/422).
  10. Hasil screenshot dimasukkan ke folder screenshot yang di-upload ke GitHub dan diberikan penjelasan pada file README.md. Setiap gambar memperlihatkan nama atau NIM kalian (misalnya pada data yang diuji).
  11. Silakan berkreasi dan buat sebaik mungkin.

Pilihan Kasus

Mahasiswa bebas memilih salah satu kasus di bawah ini (atau membuat kasus lain). Nama kolom boleh disesuaikan; tabel kedua dirancang sendiri.

  1. Books API: books (id, title, author, year, price, stock)
  2. Students API: students (id, name, nim, major, gpa, birthdate)
  3. Medicines API: medicines (id, name, type, dosage, price, expired_date)
  4. Movies API: movies (id, title, genre, director, release_year, rating)
  5. Products API: products (id, name, category, price, stock, created_at)
  6. Patients API: patients (id, name, gender, birthdate, disease, admitted_date)
  7. Employees API: employees (id, name, position, salary, hire_date, is_active)
  8. Orders API: orders (id, customer_name, product_name, quantity, total_price, order_date)

Video Presentasi

  1. Durasi maksimal 15 menit.
  2. Wajib ada bagian live coding: menulis ulang satu fungsi CRUD lengkap dari route, controller, service, sampai data, lalu ujicoba di Postman dan buktikan hasilnya di phpMyAdmin. Fungsi yang direkam ditentukan dari digit terakhir NIM:
    Digit terakhir NIMFungsi untuk live coding
    0, 1POST (tambah data)
    2, 3PUT (ubah data, termasuk 404 dan 409)
    4, 5GET daftar (paginasi dan filter)
    6, 7Transaksi: endpoint yang membuat data di tabel kedua sekaligus mengubah angka di tabel utama (penjelasan di bawah tabel)
    8, 9DELETE beserta alur errornya (404 dan error 500 lewat errorHandler)
    Untuk NIM 6 dan 7 (transaksi): yang direkam adalah endpoint yang melakukan dua langkah sekaligus: (1) menyimpan baris di tabel kedua, dan (2) mengubah angka di tabel utama. Contoh: POST /orders membuat pesanan dan mengurangi stock produk; POST /peminjaman membuat peminjaman dan mengurangi stok buku. Kalau kasus kalian lain, pakai padanannya.

    Yang ditulis ulang: route, validasi, service yang berisi prisma.$transaction, dan lapis data.

    Yang dijelaskan:
    1. Kenapa dua langkah itu harus berhasil bersama atau gagal bersama: apa yang rusak kalau langkah 1 berhasil tetapi langkah 2 gagal.
    2. Kenapa di dalam transaksi dipakai tx, bukan prisma.
    3. Di mana aturan bisnis (misalnya stok tidak cukup) diperiksa, dan apa yang terjadi pada transaksi kalau ada throw di dalamnya.
    4. Buktikan dua kasus lewat Postman dan phpMyAdmin: berhasil (baris baru ada dan angka berkurang) dan gagal (misalnya stok kurang, jawaban 409, kedua tabel tidak berubah).
    Percobaan membuat error untuk fungsi ini: sengaja throw new Error(...) setelah baris tabel kedua dibuat, lalu tunjukkan bahwa baris itu tidak tersimpan. Rujukan: Materi 7, Section 3.
    Hapus dulu kode fungsi itu (misalnya dengan git stash), tulis ulang sambil menjelaskan alurnya, dan kembalikan di akhir. Bagian ini satu kali rekam, tanpa potongan dan tanpa dipercepat, dengan suara sendiri.
  3. Setelah berjalan, lakukan satu percobaan membuat error dengan sengaja (misalnya melewati pemeriksaan data unik, memasang errorHandler sebelum route, atau melempar error di tengah transaksi), jelaskan akibatnya, lalu kembalikan.
  4. Tampilkan alur project (folder, migrasi, route, controller, service, data, middleware).
  5. Tunjukkan hasil uji API di Postman.
  6. Akhiri dengan kesimpulan pribadi.
