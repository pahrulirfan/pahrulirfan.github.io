EAS — Proyek Akhir Kelompok (Full-Stack)

Proyek Akhir EAS

Kelompok (maksimal 3 orang) mengembangkan satu aplikasi web full-stack: front end (Vue atau React) yang tersambung ke API Express + MySQL, diuji otomatis, lalu dirilis agar bisa diakses dari luar komputer sendiri. Dikerjakan sepanjang Pertemuan 11–15, dinilai lewat laporan proyek (PDF), demonstrasi, dan wawancara kode pada Pertemuan 16.

Ketentuan Umum

  1. Dasar proyek: pilih satu backend dari anggota kelompok (hasil Pertemuan 1–10) lalu kembangkan bersama. Tema bebas, boleh melanjutkan kasus ETS atau membuat kasus baru, selama memenuhi ketentuan di bawah.
  2. Backend: REST API berlapis seperti sebelumnya (Prisma, validasi, errorHandler terpusat), ditambah autentikasi dan otorisasi (Materi 9) dengan minimal 2 peran, serta perbaikan temuan keamanan sesuai Materi 10. Basis data minimal:
    • 5 tabel, sudah termasuk tabel pengguna (users)
    • Minimal satu relasi banyak-ke-banyak (tabel penghubung)
    • Minimal satu operasi transaksi yang mengubah dua tabel atau lebih
  3. Front end: Vue atau React (pilih satu) dengan minimal:
    • 6 halaman dengan routing sisi klien (2 halaman per anggota), termasuk halaman login/daftar dan halaman yang hanya bisa dibuka setelah login atau oleh peran tertentu
    • Setiap tabel utama di backend punya tampilan di front end (daftar, detail, atau form)
    • Daftar data dan satu formulir dengan validasi dan pesan error yang jelas
    • Penanganan keadaan memuat, kosong, dan galat saat mengambil data dari API
    • Tata letak responsif (layar HP dan laptop)
  4. Pengujian: minimal beberapa pengujian unit, satu pengujian end-to-end untuk satu alur utama, dan satu uji regresi keamanan (Materi 13). Seluruhnya berjalan otomatis lewat pipeline CI di GitHub.
  5. Rilis: API dan front end dirilis ke layanan hosting dengan alamat publik. Konfigurasi lewat variabel environment; tidak ada rahasia di repositori (Materi 14).
  6. Kualitas: ukur LCP, INP, CLS dan lakukan audit aksesibilitas WCAG 2.2. Tuliskan hasil sebelum dan sesudah perbaikan, minimal satu temuan yang diperbaiki (Materi 15).
  7. Jalur cadangan: produk wajib bisa dipasang dan dijalankan dari salinan bersih repositori di komputer lain hanya dengan mengikuti README.md, kalau layanan daring tidak bisa diakses saat penilaian. Sertakan .env.example dan jelaskan cara menyiapkan basis data di README (migrasi Prisma, db push, atau berkas SQL), lengkap dengan akun contoh untuk mencoba tiap peran.
  8. Pakai Git bersama: setiap anggota punya commit dan pull request sendiri. Riwayat commit dipakai untuk memeriksa pembagian kerja.
  9. README.md memuat: nama anggota + NIM, deskripsi singkat, tautan aplikasi, cara menjalankan, pembagian tugas tiap anggota, dan hasil audit.
  10. Silakan berkreasi dan buat sebaik mungkin. Migrasi (folder prisma/migrations di-commit) dan seed bersifat opsional, tetapi dihargai sebagai nilai lebih. Fitur tambahan lain (misalnya PWA atau TypeScript) juga dihargai sebagai pengayaan, bukan kewajiban.

Contoh Judul Proyek

Kelompok bebas memilih salah satu contoh di bawah ini atau mengusulkan judul sendiri (konsultasikan dulu dengan dosen). Pastikan judulnya cukup besar untuk 5 tabel, 6 halaman, dan 2 peran.

  1. Sistem Peminjaman Buku Perpustakaan (anggota, petugas; buku, kategori, peminjaman)
  2. Toko Online Sederhana (pembeli, admin; produk, kategori, pesanan, detail pesanan)
  3. Reservasi Ruang atau Laboratorium Kampus (mahasiswa, admin; ruang, jadwal, reservasi)
  4. Klinik atau Puskesmas: Pendaftaran Pasien dan Antrean (pasien, petugas; dokter, jadwal, kunjungan)
  5. Pengaduan Layanan Publik Desa atau Kampus (warga, petugas; pengaduan, kategori, tanggapan)
  6. Manajemen Event dan Pendaftaran Peserta (peserta, panitia; event, sesi, pendaftaran)
  7. Kursus atau Kelas Online Mini (siswa, pengajar; kursus, materi, pendaftaran)
  8. Pencatatan Keuangan Pribadi atau Kelompok (pengguna, admin; transaksi, kategori, anggaran)

Laporan Proyek (PDF)

Satu laporan per kelompok, 10–20 halaman, berformat PDF. Ditulis dengan bahasa sendiri, ringkas, dan memuat gambar (bukan hanya teks). Isi minimal:

  1. Sampul: judul proyek, nama anggota + NIM, tautan GitHub dan aplikasi.
  2. Pendahuluan: latar belakang, tujuan, dan peran pengguna (misalnya admin dan pengguna biasa).
  3. Rancangan: diagram arsitektur (front end, API, database), ERD (minimal 5 tabel), dan daftar endpoint.
  4. Implementasi: tangkapan layar setiap halaman (6 halaman atau lebih) disertai penjelasan singkat alur dan fitur utamanya.
  5. Pengujian: daftar kasus uji, hasil pengujian unit dan end-to-end, serta tangkapan layar pipeline CI yang berhasil.
  6. Rilis dan evaluasi kualitas: alamat aplikasi, hasil LCP/INP/CLS dan audit WCAG 2.2 sebelum dan sesudah perbaikan.
  7. Pembagian tugas: tabel kontribusi tiap anggota (halaman, endpoint, pengujian yang dikerjakan).
  8. Deklarasi penggunaan AI: sama seperti di README, tetapi lebih rinci per anggota.
  9. Kesimpulan dan kendala: apa yang berhasil, apa yang sulit, dan rencana pengembangan.

Demonstrasi dan Wawancara (Pertemuan 16)

  1. Tiap kelompok mendapat sekitar 15 menit: demo alur utama aplikasi, tunjukkan hasil pipeline CI, ringkasan hasil audit.
  2. Lalu wawancara kode per individu: setiap anggota diminta menjelaskan atau mengubah sedikit bagian kode yang menjadi tanggung jawabnya.
  3. Alamat publik dicoba lebih dulu. Kalau gagal, penilaian berlanjut lewat jalur cadangan (instalasi dari README).

Deklarasi Penggunaan AI

AI boleh dipakai sebagai alat bantu belajar, tetapi wajib dideklarasikan jujur di README: bagian mana, untuk apa, dan bagaimana kalian memeriksa hasilnya. Yang dinilai kejujuran dan pemahaman, bukan banyaknya AI. Wawancara kode memeriksa bahwa kalian mengerti kode kalian sendiri.

Kumpulkan

  1. Link GitHub — nama repository pwl26-proyek-akhir, status Public.
  2. Link aplikasi yang sudah dirilis (front end dan API).
  3. File laporan PDF dengan nama Laporan-Kelompok-NN.pdf, juga dimasukkan ke folder docs di repository.
  4. Upload link dan file PDF ke Berajah — selain PDF laporan, tidak perlu file/ZIP. Cukup satu perwakilan kelompok.
Perhatian:
  • Repository dan aplikasi tetap public / dapat diakses hingga akhir semester. node_modules dan .env tidak di-upload.
  • Terlambat mengumpulkan link: nilai dikurangi 10 poin per hari.
  • Menyalin pekerjaan kelompok lain: kedua kelompok mendapat nilai maksimal 50.
  • Anggota yang tidak bisa menjelaskan kode di wawancara, dari sumber mana pun, berisiko mendapat nilai 0 pada komponen wawancara.
