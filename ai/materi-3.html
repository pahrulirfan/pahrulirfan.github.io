1. Mengapa Kita Butuh Heuristik? Motivasi

Algoritma pencarian buta (BFS, DFS, IDS, UCS) tidak menggunakan pengetahuan tentang lokasi tujuan. Mereka "buta" — mengeksplorasi semua arah secara sistematis. Ini sangat boros untuk masalah berukuran besar.

💡 Analogi:

Bayangkan mencari kunci di rumah besar. Pencarian buta memeriksa setiap sudut ruangan secara urut. Pencarian heuristik lebih cerdas — ia menduga di mana kunci kemungkinan besar berada (kamar tidur, meja dapur) dan memeriksa sana dulu.

🎯 Ide Utama Pencarian Heuristik:

Gunakan fungsi heuristik h(n) — estimasi biaya dari simpul n ke tujuan — untuk memandu ekspansi ke arah yang paling menjanjikan. Semakin akurat h(n), semakin sedikit simpul yang perlu diekspansi.

2. Fungsi Evaluasi: g(n), h(n), dan f(n) Inti

g(n)

Biaya Lintasan

Biaya aktual dari keadaan awal s₀ ke simpul n. Nilai ini diketahui dengan pasti saat n dibangkitkan.

h(n)

Fungsi Heuristik

Estimasi biaya dari simpul n ke tujuan terdekat. Ini adalah "pengetahuan" tambahan yang dimiliki agen. h(goal) = 0 selalu.

f(n)

Fungsi Evaluasi

f(n) = g(n) + h(n) — estimasi biaya total lintasan terbaik yang melalui simpul n. Digunakan A* untuk mengurutkan frontier.

3. Greedy Best-First Search Algoritma

Greedy BFS hanya menggunakan fungsi heuristik h(n) sebagai prioritas — ia selalu mengekspansi simpul yang terlihat paling dekat ke tujuan menurut estimasi heuristik, tanpa memperhitungkan biaya yang sudah ditempuh.

📌 Fungsi evaluasi Greedy:

f(n) = h(n)

Tidak memperhitungkan biaya lintasan g(n) sama sekali. Seperti "orang yang selalu bergerak ke arah tujuan, tak peduli jalannya berliku."

Pseudocode Greedy BFS

function GREEDY-BEST-FIRST-SEARCH(problem, h) returns node | failure
    node     ← Node(problem.initial)
    frontier ← PriorityQueue(key=lambda n: h(n.state))
    frontier.insert(node)
    explored ← set()

    loop:
        if frontier.is_empty(): return failure
        node ← frontier.pop_min()       -- ambil simpul dengan h(n) terkecil
        if problem.is_goal(node.state): return node
        explored.add(node.state)
        for child in node.expand(problem):
            if child.state not in explored and child.state not in frontier:
                frontier.insert(child)

4. Algoritma A* Inti

A* menggabungkan keunggulan UCS (optimalitas, biaya aktual g) dengan keunggulan Greedy BFS (panduan heuristik h). A* adalah algoritma pencarian terinformasi yang paling banyak digunakan dalam AI klasik.

🏆 Fungsi evaluasi A*:

f(n) = g(n) + h(n)

g(n) = biaya yang sudah ditempuh dari awal ke n  |  h(n) = estimasi sisa biaya dari n ke tujuan

Pseudocode A*

function A-STAR-SEARCH(problem, h) returns node | failure
    node     ← Node(problem.initial, path_cost=0)
    frontier ← PriorityQueue(key=lambda n: n.path_cost + h(n.state))
    frontier.insert(node)
    explored ← set()

    loop:
        if frontier.is_empty(): return failure
        node ← frontier.pop_min()       -- ambil simpul dengan f(n) = g+h terkecil
        if problem.is_goal(node.state): return node
        explored.add(node.state)

        for child in node.expand(problem):
            child_f = child.path_cost + h(child.state)
            if child.state not in explored:
                if child.state not in frontier:
                    frontier.insert(child)
                elif frontier[child.state].path_cost > child.path_cost:
                    frontier.replace(child)  -- update jika ditemukan lintasan lebih murah

Implementasi A* dengan Python

import heapq

def astar(graph, start, goal, h):
    """
    graph : dict {node: [(neighbor, cost), ...]}
    h     : dict {node: heuristic_value}
    """
    # (f_score, g_score, node, path)
    frontier = [(h[start], 0, start, [start])]
    explored = set()

    while frontier:
        f, g, node, path = heapq.heappop(frontier)
        if node == goal:
            return path, g        # kembalikan lintasan dan biayanya
        if node in explored:
            continue
        explored.add(node)
        for neighbor, cost in graph.get(node, []):
            if neighbor not in explored:
                g_new = g + cost
                f_new = g_new + h[neighbor]
                heapq.heappush(frontier, (f_new, g_new, neighbor, path + [neighbor]))

    return None, float('inf')   # tidak ada solusi

5. Sifat Admissible (Dapat Diterima) Pembuktian

📌 Definisi Admissible:

Fungsi heuristik h(n) dikatakan admissible jika untuk setiap simpul n:

h(n) ≤ h*(n)

di mana h*(n) adalah biaya aktual (sesungguhnya) dari n ke tujuan. Heuristik admissible tidak pernah melebih-lebihkan biaya yang sebenarnya.

Teorema: A* dengan Heuristik Admissible adalah Optimal

Teorema: Jika h(n) admissible, maka A* pada pohon pencarian pasti menemukan solusi optimal.


Sketsa Bukti (Kontradiksi):

1️⃣
Misalkan A* mengembalikan solusi suboptimal G₂

Dengan biaya lintasan f(G₂) = g(G₂) > C* (biaya solusi optimal G₁).

2️⃣
Pasti ada simpul n di frontier pada lintasan menuju G₁

Karena G₁ belum diekspansi, ada simpul n pada lintasan optimal yang masih di frontier.

3️⃣
f(n) ≤ C* karena h admissible

f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C* (karena h(n) ≤ h*(n)).

4️⃣
Kontradiksi: f(n) ≤ C* < g(G₂) = f(G₂)

Artinya A* seharusnya memilih n sebelum G₂ — kontradiksi dengan asumsi bahwa G₂ dipilih. ∎

Contoh Heuristik Admissible

📏

Jarak Garis Lurus (SLD)

Untuk masalah rute peta: SLD selalu ≤ jarak jalan sebenarnya. Admissible.

🔢

Jumlah Ubin Salah Tempat

Untuk 8-puzzle: setiap ubin butuh minimal 1 gerakan — selalu ≤ gerakan aktual. Admissible.

↔️

Manhattan Distance

Jumlah gerak horizontal + vertikal setiap ubin ke posisi tujuan. Admissible (lebih tajam dari jumlah ubin salah).

❌

Contoh TIDAK Admissible

h(n) = 2 × jarak_sld. Bisa melebihi biaya aktual pada jalan lurus — tidak admissible.

6. Konsistensi (Monotonicity) Teorema

📌 Definisi Konsistensi:

Heuristik h(n) dikatakan konsisten (atau monotone) jika untuk setiap simpul n dan setiap penerus n' melalui aksi a:

h(n) ≤ cost(n, a, n') + h(n')

Ini adalah bentuk ketidaksamaan segitiga — estimasi biaya dari n tidak boleh melebihi biaya satu langkah ke n' ditambah estimasi dari n'.

Visualisasi Konsistensi

Hubungan Konsistensi dengan Admissible dan Optimalitas

PropertiDefinisiImplikasi
Admissible h(n) ≤ h*(n) untuk semua n A* pada pohon pencarian menghasilkan solusi optimal
Konsisten h(n) ≤ c(n,a,n') + h(n') untuk semua n, a, n' A* pada graf pencarian menghasilkan solusi optimal; nilai f tidak pernah turun sepanjang lintasan
Hubungan Konsisten ⟹ Admissible. Admissible tidak selalu konsisten, tapi hampir selalu dalam praktik.
✅ Jika h konsisten:
  • Nilai f(n) tidak pernah menurun sepanjang lintasan yang dipilih A*.
  • Setiap simpul yang diekspansi A* pasti melalui lintasan optimal ke simpul tersebut.
  • A* pada graf pencarian (dengan explored set) tetap optimal — tidak perlu periksa ulang simpul yang sudah diekspansi.

7. Merancang Fungsi Heuristik Teknik

Merancang heuristik yang baik adalah seni sekaligus ilmu dalam AI. Heuristik yang terlalu lemah membuat A* lambat; heuristik yang tidak admissible membuat A* tidak optimal.

Teknik 1: Masalah yang Dilonggarkan (Relaxed Problem)

💡 Ide:

Buat versi masalah yang lebih mudah dengan menghapus sebagian batasan. Biaya optimal masalah yang dilonggarkan selalu ≤ biaya masalah asli → otomatis admissible!

🧩

8-Puzzle: h₁

Batasan dihapus: Ubin bisa dipindah ke mana saja (bukan hanya ke ruang kosong).
→ h₁ = jumlah ubin salah tempat.

🗺️

8-Puzzle: h₂

Batasan dihapus: Ubin bisa melewati ubin lain (hanya tidak bisa diagonal).
→ h₂ = Manhattan distance.

🐦

Peta Rute: h_SLD

Batasan dihapus: Boleh terbang garis lurus, tidak perlu ikuti jalan.
→ h_SLD = jarak garis lurus ke tujuan.

🔗

Rute String: Jaccard

Integrasi penelitian [Ref. 23]: Jaccard similarity sebagai heuristik jarak edit kata — masalah yang dilonggarkan dari edit distance.

Teknik 2: Heuristik Komposit (Maksimum)

# Jika punya beberapa heuristik admissible, ambil maksimumnya
# Hasilnya tetap admissible dan lebih tajam!

def h_composite(state):
    h1 = misplaced_tiles(state)    # h₁: ubin salah tempat
    h2 = manhattan_distance(state)  # h₂: Manhattan distance
    return max(h1, h2)              # max tetap admissible, lebih tajam

# Mengapa max admissible?
# h1 ≤ h*(n) dan h2 ≤ h*(n)
# → max(h1, h2) ≤ h*(n)  ✅

Teknik 3: Heuristik dari Pola Database

Pattern Database Heuristics:

Pra-komputasi biaya optimal untuk sub-masalah (misalnya, hanya gerakan ubin 1–4) dan simpan dalam database. Biaya sub-masalah selalu ≤ biaya masalah penuh → admissible dan sangat tajam. Digunakan untuk memecahkan 15-puzzle dan 24-puzzle.

Checklist Heuristik yang Baik

✓
h(goal) = 0

Heuristik harus bernilai 0 di semua keadaan tujuan.

✓
h(n) ≥ 0 untuk semua n

Nilai heuristik tidak boleh negatif.

✓
h(n) ≤ h*(n) — Admissible

Tidak pernah melebih-lebihkan biaya sebenarnya ke tujuan.

✓
Efisien dihitung

Waktu komputasi h(n) harus jauh lebih kecil dari biaya pencarian. O(1) atau O(n) lebih baik dari O(n²).

✓
Tajam (h lebih besar = lebih baik)

Di antara dua heuristik admissible, pilih yang nilainya lebih besar — ia lebih mendekati h*(n) dan mengurangi simpul yang diekspansi.

8. Dominasi Heuristik Analisis

📌 Definisi Dominasi:

Heuristik h₂ mendominasi h₁ jika untuk semua simpul n:

h₂(n) ≥ h₁(n) (dan keduanya admissible)

Heuristik yang lebih dominan selalu menghasilkan lebih sedikit simpul diekspansi oleh A*.

9. Pencarian Lokal: Hill Climbing & Simulated Annealing Pelengkap

Greedy BFS dan A* menyimpan seluruh frontier dan melacak lintasan. Untuk masalah optimasi di mana yang penting hanya keadaan akhir (bukan lintasan menuju ke sana), kita bisa memakai pencarian lokal: simpan hanya satu keadaan "saat ini", lalu terus pindah ke tetangga yang lebih baik. Hemat memori, tetapi tidak menjamin optimalitas.

Lanskap Ruang Keadaan

Istilah pada permukaan fungsi objektif

Hill climbing selalu bergerak "menanjak" — sehingga bisa terjebak di maksimum lokal, plateau (datar, tak ada arah menanjak), atau ridge (punggungan yang butuh gerak zig-zag).

Simple Hill Climbing

Variasi dari DFS: pada tiap langkah, ambil tetangga pertama yang lebih baik dari keadaan sekarang, lalu pindah ke sana. Analogi: mendaki gunung dalam kabut tebal sambil terkena amnesia — hanya tahu apakah langkah berikutnya naik atau turun.

function SIMPLE-HILL-CLIMBING(problem) returns state
    current ← problem.initial
    loop:
        if problem.is_goal(current): return current
        for next in successors(current):
            if value(next) > value(current):   # tetangga PERTAMA yang lebih baik
                current ← next
                break
        else:
            return current                      # tak ada tetangga lebih baik → berhenti
⚠️ Tiga kelemahan Simple Hill Climbing:
  • Berhenti di optimum lokal, bukan global.
  • Urutan pemakaian operator sangat memengaruhi solusi yang ditemukan.
  • Tidak boleh "mengintip" lebih dari satu langkah ke depan.

Steepest-Ascent Hill Climbing

Mirip Simple HC, tetapi mengevaluasi semua tetangga lebih dulu, lalu pindah ke yang paling baik. Berhenti jika tidak ada tetangga yang lebih baik dari keadaan sekarang.

Simulated Annealing (SA)

🔥 Ide:

Untuk lolos dari optimum lokal, SA sesekali mengizinkan langkah yang memperburuk keadaan, dengan probabilitas yang menurun seiring "suhu" T yang mendingin. Di awal (T tinggi) agen bebas menjelajah; menjelang akhir (T rendah) agen berperilaku seperti hill climbing biasa. Terinspirasi proses annealing (pendinginan lambat) pada logam.

P(terima langkah buruk) = e−ΔE / T

Generate and Test

Metode paling sederhana: bangkitkan sebuah kandidat solusi (acak atau sistematis), lalu uji apakah ia solusi. Jika bukan, ulangi. Setara DFS jika pembangkitannya sistematis; setara pencarian acak jika tidak. Praktis hanya untuk ruang solusi kecil.

✅ Kapan memakai pencarian lokal?

Saat lintasan menuju solusi tidak penting (mis. penjadwalan, penempatan komponen, penyetelan parameter, N-Queens), ruang keadaan sangat besar, dan solusi "cukup baik" sudah memadai. Untuk solusi yang dijamin optimal beserta lintasannya, tetap gunakan A*.

10. Perbandingan: Greedy BFS vs A* vs UCS Ringkasan

🟡 Greedy Best-First

Fungsi evaluasi: f(n) = h(n)

Strategi: Selalu ke yang terlihat paling dekat ke tujuan

Kelengkapan: ❌ Tidak terjamin

Optimalitas: ❌ Tidak terjamin

Kecepatan: ✅ Sangat cepat jika heuristik baik

Cocok untuk: Situasi real-time di mana kecepatan lebih penting dari optimalitas

🔵 A*

Fungsi evaluasi: f(n) = g(n) + h(n)

Strategi: Seimbangkan biaya aktual dan estimasi sisa

Kelengkapan: ✅ Ya (b terhingga, h admissible)

Optimalitas: ✅ Ya (h admissible/konsisten)

Kecepatan: ✅ Tergantung kualitas heuristik

⚠️ Keterbatasan A*:

Meskipun optimal, A* masih menghabiskan memori O(bd) untuk menyimpan frontier. Pada masalah sangat besar, varian seperti IDA* (Iterative Deepening A*) digunakan — menggabungkan A* dengan pendekatan iterative deepening untuk menghemat memori.

11. Rangkuman Pertemuan 5 & 6

✅ Poin-poin Kunci:
  • Heuristik h(n) adalah estimasi biaya dari simpul n ke tujuan — "pengetahuan domain" yang memandu pencarian.
  • g(n) = biaya aktual dari awal ke n; h(n) = estimasi sisa; f(n) = g+h = estimasi total.
  • Greedy BFS hanya pakai h(n) — cepat tapi tidak optimal dan tidak lengkap.
  • A* pakai f(n) = g(n)+h(n) — optimal jika h admissible, lebih optimal pada graf jika h konsisten.
  • Admissible: h(n) ≤ h*(n) — tidak melebih-lebihkan biaya → menjamin optimalitas A*.
  • Konsisten: h(n) ≤ c(n,a,n') + h(n') — ketidaksamaan segitiga → f tidak pernah turun sepanjang lintasan.
  • Teknik desain heuristik: masalah yang dilonggarkan, maksimum beberapa heuristik, pattern database.
  • Dominasi: h₂ dominan atas h₁ jika h₂(n) ≥ h₁(n) → A* dengan h₂ lebih efisien.
  • Pencarian lokal (Hill Climbing, Simulated Annealing) menyimpan satu keadaan saja — hemat memori, cocok untuk optimasi tanpa peduli lintasan, tapi rawan terjebak optimum lokal.
