Kelemahan Pencarian Buta

Kelemahan blind search:
  • Waktu akses lama.
  • Memori yang dibutuhkan besar.
  • Tidak cocok untuk ruang masalah yang besar, karena kecepatan komputer dan memori terbatas.

Solusi: pencarian heuristik.

Blind vs Heuristic Search

Blind Search

Tidak ada alternatif yang dibuang. Semua simpul tetap akan diperiksa; yang diatur hanya urutan (prioritas) pemeriksaannya.

Heuristic Search

Ada beberapa alternatif yang dibuang karena estimasinya buruk. Dari sinilah efisiensinya berasal. Konsekuensinya, bila estimasinya keliru, jalur yang sebenarnya baik bisa ikut terbuang.

2. Pendekatan Heuristik 01 · Konsep

Apa Itu Heuristik?

  • Kata heuristic berasal dari kata kerja bahasa Yunani heuriskein, yang berarti "mencari" atau "menemukan".
  • Dalam pemrograman, sebagian orang memakai kata heuristik sebagai lawan kata algoritmik. Heuristik diartikan sebagai proses yang mungkin dapat menyelesaikan suatu masalah, tetapi tidak ada jaminan bahwa solusi yang dicari selalu ditemukan.
  • Heuristik juga dapat diartikan sebagai kaidah, yaitu metode atau prosedur yang didasarkan pada pengalaman dan praktik, syarat, trik, atau bantuan lain yang membantu mempersempit dan memfokuskan proses pelacakan menuju suatu tujuan.
Analogi:

Bayangkan mencari kunci di rumah besar. Pencarian buta memeriksa setiap sudut ruangan secara urut. Pencarian heuristik lebih cerdas: ia menduga di mana kunci kemungkinan besar berada (kamar tidur, meja dapur) dan memeriksa tempat itu lebih dahulu.

Teknik Pencarian Heuristik

1
Selektif

Pencarian heuristik adalah strategi untuk menelusuri ruang keadaan secara selektif. Pencarian dipandu di sepanjang jalur yang kemungkinan suksesnya paling besar, dan usaha yang "dianggap bodoh" serta memboroskan waktu dikesampingkan.

2
Efisien, tetapi bisa mengorbankan kelengkapan

Heuristik meningkatkan efisiensi pencarian, dengan kemungkinan mengorbankan kelengkapan (completeness).

3
Heuristik sebagai fungsi estimasi

Dalam metode-metode pencarian ini, heuristik diartikan sebagai fungsi yang memberikan biaya perkiraan (estimasi) dari suatu solusi. Fungsi ini ditulis h(n): perkiraan biaya dari simpul n ke tujuan.

Dua Situasi Pemakaian Heuristik

Kecerdasan buatan memakai heuristik dalam dua situasi dasar:

Solusi pasti, tetapi mahal

Masalahnya memiliki solusi pasti, tetapi biaya komputasi untuk mendapatkannya sangat tinggi. Contoh: 8-puzzle, catur, rute terpendek pada peta besar.

Tidak ada solusi pasti

Masalahnya mungkin tidak memiliki solusi pasti karena ambiguitas (keraguan atau ketidakpastian). Contoh: diagnosis kedokteran.

3. Kasus 8-Puzzle: Tiga Fungsi Heuristik 01 · Contoh

Susun ubin dari keadaan awal menjadi keadaan tujuan. Fungsi heuristik h apa yang dapat menilai seberapa dekat suatu susunan ke tujuan?

Ada 4 aksi (aturan): ubin kosong digeser ke kiri, ke kanan, ke atas, atau ke bawah. Fungsi heuristik yang mungkin:

HeuristikDefinisiYang lebih baikh(awal)h(tujuan)
h₁banyak ubin yang menempati posisi yang benarlebih tinggi58
h₂banyak ubin yang menempati posisi yang salahlebih rendah30
h₃total gerakan yang diperlukan untuk mencapai tujuanlebih rendah30
Cara menghitung pada keadaan awal:
  • h₁ = 5: ubin 1, 2, 3, 4, dan 5 sudah di tempatnya. Kotak kosong tidak dihitung.
  • h₂ = 3: ubin 7, 8, dan 6 belum di tempatnya. Karena ada 8 ubin, selalu berlaku h₂ = 8 − h₁.
  • h₃ = 3: ubin 7 perlu 1 langkah (turun), ubin 8 perlu 1 langkah (ke kiri), ubin 6 perlu 1 langkah (ke kanan). Menjumlahkan jarak mendatar dan tegak setiap ubin ke posisinya disebut jarak Manhattan.

# Tiga fungsi heuristik 8-puzzle (slide 19-25). 0 = ubin kosong.
AWAL = (1, 2, 3,
        7, 8, 4,
        6, 0, 5)
TUJUAN = (1, 2, 3,
          8, 0, 4,
          7, 6, 5)
ARAH = [('kiri', 0, -1), ('kanan', 0, 1), ('atas', -1, 0), ('bawah', 1, 0)]


def geser(s, dr, dc):
    """Geser ubin kosong. None jika keluar papan."""
    i = s.index(0)
    r, c = divmod(i, 3)
    r2, c2 = r + dr, c + dc
    if not (0 <= r2 < 3 and 0 <= c2 < 3):
        return None
    j = r2 * 3 + c2
    t = list(s)
    t[i], t[j] = t[j], t[i]
    return tuple(t)


def h1(s):  # banyak ubin di posisi BENAR (makin besar makin baik)
    return sum(1 for a, b in zip(s, TUJUAN) if a != 0 and a == b)


def h2(s):  # banyak ubin di posisi SALAH (makin kecil makin baik)
    return sum(1 for a, b in zip(s, TUJUAN) if a != 0 and a != b)


def h3(s):  # total gerakan tiap ubin ke posisinya (jarak Manhattan)
    total = 0
    for i, v in enumerate(s):
        if v != 0:
            j = TUJUAN.index(v)
            total += abs(i // 3 - j // 3) + abs(i % 3 - j % 3)
    return total


def cetak(s):
    return ' / '.join(' '.join(str(v) if v else '_' for v in s[r:r + 3]) for r in (0, 3, 6))


print('Awal  :', cetak(AWAL), '  h1 =', h1(AWAL), ' h2 =', h2(AWAL), ' h3 =', h3(AWAL))
print('Tujuan:', cetak(TUJUAN), '  h1 =', h1(TUJUAN), ' h2 =', h2(TUJUAN), ' h3 =', h3(TUJUAN))

for nama, h, pilih in [('h1', h1, max), ('h2', h2, min), ('h3', h3, min)]:
    print()
    print('=== Hill climbing dengan', nama, '(pilih', pilih.__name__ + ') ===')
    s, sebelum = AWAL, None
    while s != TUJUAN:
        anak = []
        for arah, dr, dc in ARAH:
            t = geser(s, dr, dc)
            if t is None:
                print('  {:5s}: tidak valid (keluar papan)'.format(arah))
            elif t == sebelum:
                print('  {:5s}: {}  {} = {}  (kembali ke induk)'.format(arah, cetak(t), nama, h(t)))
            else:
                print('  {:5s}: {}  {} = {}'.format(arah, cetak(t), nama, h(t)))
                anak.append((h(t), arah, t))
        nilai, arah, terbaik = pilih(anak)
        print('  -> pilih', arah, '(' + nama, '=', str(nilai) + ')')
        sebelum, s = s, terbaik
    print('  Tujuan tercapai.')

4. Kasus Jalur Terpendek & Syarat Fungsi Heuristik 01 · Contoh

Empat simpul A, B, C, dan D terletak pada garis lurus y = 10. Jalan yang menghubungkannya berkelok, sehingga panjang jalan berbeda dengan jarak lurusnya. Contohnya, jarak lurus B ke C hanya 20 satuan, tetapi jalannya memutar sepanjang 100. Jika yang diketahui hanya koordinat setiap simpul, perkiraan apa yang masuk akal untuk sisa jarak ke tujuan?

Fungsi heuristik yang mungkin: jarak garis lurus (Straight Line Distance, SLD)

Dengan fungsi heuristik h berupa jarak Euclidean:

dab = √( (yb − ya)² + (xb − xa)² )

Pilih simpul tujuan untuk melihat nilai h setiap simpul. Garis putus-putus merah adalah jarak garis lurus. Tabel di bawahnya membandingkan h dengan jarak jalan yang sebenarnya.

SLD cocok sebagai heuristik karena dua alasan. Pertama, murah dihitung, cukup dari koordinat. Kedua, nilainya tidak mungkin melebihi jarak jalan, karena garis lurus adalah lintasan terpendek antara dua titik. Heuristik yang sama dipakai pada peta Romania di bagian GBFS dan A*.

import math

# Kasus jalur terpendek (slide 26-27): koordinat setiap simpul
KOORDINAT = {'A': (20, 10), 'B': (35, 10), 'C': (55, 10), 'D': (65, 10)}


def h_sld(a, b):
    (xa, ya), (xb, yb) = KOORDINAT[a], KOORDINAT[b]
    return math.sqrt((yb - ya) ** 2 + (xb - xa) ** 2)


for kota in KOORDINAT:
    print('h({}) = jarak garis lurus {} ke D = {:.0f}'.format(kota, kota, h_sld(kota, 'D')))

Syarat Fungsi Heuristik

Diterima jika tidak melebihi biaya sebenarnya

Fungsi heuristik diterima jika estimasi biaya yang dihasilkan tidak melebihi biaya sebenarnya. Sifat ini disebut admissible: h(n) ≤ h*(n). Contoh: SLD pada peta, dan h₂ pada 8-puzzle.

Terlalu tinggi berbahaya

Fungsi heuristik yang terlalu tinggi (overestimate) dapat membuat proses pencarian hilang atau mencapai hasil yang tidak optimal, karena rute terbaik tampak mahal lalu dilewatkan.

Yang baik mendekati biaya sebenarnya

Fungsi heuristik yang baik memberikan perkiraan yang mendekati biaya sebenarnya. h = 0 selalu admissible tetapi tidak membantu: A* dengan h = 0 sama dengan UCS.

5. Best First Search & Greedy Best First Search 02 · Algoritma

Metode Best First Search

  • Best First Search menitikberatkan pengembangan pada simpul yang dinilai paling menguntungkan berdasarkan suatu nilai estimasi.
  • Umumnya pencarian dilakukan dengan memberikan estimasi seberapa jauh suatu simpul dari solusi yang diinginkan.
  • Ekspansi dilakukan terhadap simpul yang memiliki estimasi terpendek.
  • Dua varian Best First Search adalah Greedy Best First Search dan A* (dibaca "A-star"). Keduanya hanya berbeda pada fungsi evaluasi f(n) yang dipakai untuk mengurutkan antrean.
g(n)

Biaya Lintasan

Biaya aktual dari keadaan awal ke simpul n. Nilainya pasti, dijumlahkan dari bobot sisi yang sudah dilalui.

h(n)

Fungsi Heuristik

Estimasi biaya dari simpul n ke tujuan. Selalu h(tujuan) = 0.

f(n)

Fungsi Evaluasi

Nilai yang dipakai untuk mengurutkan antrean. Greedy: f(n) = h(n). A*: f(n) = g(n) + h(n).

Metode Greedy Best First Search (GBFS)

Fungsi evaluasi Greedy:

f(n) = h(n) = hSLD(n)

  • f(n) sama dengan fungsi heuristik h(n), yaitu estimasi biaya dari suatu lokasi ke tujuan.
  • Pada peta, h dinotasikan hSLD(n): jarak garis lurus dari satu lokasi ke tujuan.
  • GBFS mengekspansi simpul yang terlihat paling dekat ke tujuan, tanpa memperhitungkan biaya yang sudah ditempuh.

Contoh Algoritma GBFS

Algorithm 9.2 Best-first Search (Input: S, Goal)
  1. Open = [S]
  2. Closed = [ ]
  3. repeat
  4.     if Open.Head = Goal then
  5.         return success
  6.     end if
  7.     generate children's set C of Open.Head
  8.     if n ∈ C already exists in OPEN and new n is reachable by shorter path then
  9.         remove the old n
  10.     end if
  11.     if n ∈ C already exists in Closed and reachable by shorter path then
  12.         replace n ∈ C by the same node from Closed, along with shorter distance from root
  13.     end if
  14.     remove Open.Head and insert into Closed
  15.     update distance from root for all C nodes
  16.     add all C to either side of Open and record their parents
  17.     sort Open by path length so that least cost path node is at front

Algorithm 9.3 Admissible search A* (Input: G, S, Goal)
  1. Open = [S]
  2. Closed = [ ]
  3. compute f*(n) for all n ∈ Open
  4. repeat
  5.     select the open node n whose f*(n) is smallest
  6.     resolve ties arbitrarily, but always in favor of any node n ∈ Goal
  7.     if n ∈ Goal then
  8.         move n to Closed
  9.         terminate algorithm
  10.     else
  11.         move n to Closed
  12.         apply successor operator to n
  13.         calculate f* for each successor ni of n
  14.         move all ni ∉ Closed to Open
  15.         move to Open any ni ∈ Closed for which f*(ni) is smaller now than it was when ni was in Closed
  16.     end if
  17. until Open = nil
  18. return fail

8. Sifat Admissible (Dapat Diterima) Pembuktian

Definisi Admissible:

Fungsi heuristik h(n) dikatakan admissible jika untuk setiap simpul n:

h(n) ≤ h*(n)

di mana h*(n) adalah biaya aktual (sesungguhnya) dari n ke tujuan. Heuristik admissible tidak pernah melebih-lebihkan biaya yang sebenarnya.

Teorema: A* dengan Heuristik Admissible adalah Optimal

Teorema: Jika h(n) admissible, maka A* pada pohon pencarian pasti menemukan solusi optimal.


Sketsa Bukti (Kontradiksi):

1
Misalkan A* mengembalikan solusi suboptimal G₂

Dengan biaya lintasan f(G₂) = g(G₂) > C* (biaya solusi optimal G₁).

2
Pasti ada simpul n di frontier pada lintasan menuju G₁

Karena G₁ belum diekspansi, ada simpul n pada lintasan optimal yang masih di frontier.

3
f(n) ≤ C* karena h admissible

f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C* (karena h(n) ≤ h*(n)).

4
Kontradiksi: f(n) ≤ C* < g(G₂) = f(G₂)

Artinya A* seharusnya memilih n sebelum G₂ — kontradiksi dengan asumsi bahwa G₂ dipilih. ∎

Contoh Heuristik Admissible

Jarak Garis Lurus (SLD)

Untuk masalah rute peta: SLD selalu ≤ jarak jalan sebenarnya. Admissible.

Jumlah Ubin Salah Tempat

Untuk 8-puzzle: setiap ubin butuh minimal 1 gerakan — selalu ≤ gerakan aktual. Admissible.

Manhattan Distance

9. Konsistensi (Monotonicity) Teorema

Definisi Konsistensi:

Heuristik h(n) dikatakan konsisten (atau monotone) jika untuk setiap simpul n dan setiap penerus n' melalui aksi a:

h(n) ≤ cost(n, a, n') + h(n')

Ini adalah bentuk ketidaksamaan segitiga — estimasi biaya dari n tidak boleh melebihi biaya satu langkah ke n' ditambah estimasi dari n'.

Visualisasi Konsistensi

Contoh Pelanggaran: Graf Latihan S–G

Periksa setiap sisi graf Latihan 1. Hampir semua sisi memenuhi ketidaksamaan segitiga, kecuali sisi D–H:

h(D) = 14 > c(D, H) + h(H) = 5 + 6 = 11

Jadi heuristik ini admissible tetapi tidak konsisten. Akibatnya terlihat pada Latihan 2: A* mengambil H lebih dahulu lewat S → C → H (g = 16, f = 22). Sesudah itu ditemukan jalur S → B → D → H yang lebih murah (g = 15), sehingga H harus dibuka kembali dari Closed dan nilai f-nya turun menjadi 21. Dengan heuristik yang konsisten, nilai f simpul yang diambil tidak pernah turun, dan simpul di Closed tidak perlu dibuka kembali.

Jika h konsisten:
  • Nilai f(n) tidak pernah menurun sepanjang lintasan yang dipilih A*.
  • Setiap simpul yang diekspansi A* pasti melalui lintasan optimal ke simpul tersebut.
  • A* pada graf pencarian (dengan explored set) tetap optimal — tidak perlu periksa ulang simpul yang sudah diekspansi.

Ide:

12. Hill Climbing (HC) 04 · Algoritma

Metode Hill Climbing

  • Hill climbing merupakan variasi dari depth-first search.
  • Eksplorasi dilakukan seperti DFS dengan mencari jalur yang menurunkan cost atau menaikkan benefit menuju tujuan. Mirip UCS, tetapi hanya memilih di antara anak simpul sekarang, dan anak itu baru diambil bila lebih menguntungkan daripada induknya.
  • Analoginya seperti mendaki Gunung Himalaya di tengah kabut tebal sambil terkena amnesia. Kabut tebal berarti hanya tetangga langsung yang dapat dinilai. Amnesia berarti tidak ingat jalan yang sudah dilewati, sehingga tidak dapat mundur.
  • Dengan cara ini kita berasumsi bahwa secara umum arah yang menanjak semakin dekat ke puncak.

Hill climbing hanya menyimpan satu keadaan, yaitu keadaan sekarang. Tidak ada antrean dan tidak ada daftar simpul yang sudah dikunjungi, sehingga hill climbing sangat hemat memori.

Algoritma Simple Hill Climbing

1
Evaluasi state awal

Jika state awal sama dengan tujuan, proses berhenti. Jika tidak, jadikan state awal sebagai state sekarang.

2
Ulangi sampai solusi ditemukan atau tidak ada lagi operator baru untuk state sekarang

a. Cari sebuah operator yang belum pernah digunakan pada state sekarang, lalu gunakan untuk membentuk state baru.
b. Evaluasi state baru:

  • Jika state baru adalah tujuan, proses berhenti.
  • Jika state baru bukan tujuan tetapi lebih baik daripada state sekarang, jadikan state baru sebagai state sekarang.
  • Jika state baru tidak lebih baik daripada state sekarang, lanjutkan iterasi dengan operator berikutnya.
function SIMPLE-HILL-CLIMBING(problem) returns state
    current ← problem.initial
    loop:
        if problem.is_goal(current): return current
        for next in successors(current):          # urutan operator berpengaruh!
            if value(next) lebih baik dari value(current):
                current ← next                      # tetangga PERTAMA yang lebih baik
                break
        else:
            return current                          # tak ada tetangga lebih baik → berhenti
Tiga masalah pada Simple HC:
  1. Berhenti di optimum lokal. Tidak ada tetangga yang lebih baik, sehingga HC berhenti di puncak kecil.
  2. Urutan penggunaan operator sangat berpengaruh pada solusi yang ditemukan, karena state lebih baik yang pertama ditemukan langsung diambil.
  3. Tidak diizinkan melihat satu langkah pun ke depan. Langkah yang sesaat tampak buruk tetapi membuka jalan ke solusi tidak akan pernah diambil.

13. Steepest-Ascent Hill Climbing (St-HC) 04 · Algoritma

Metode ini mirip dengan simple hill climbing. Perbedaannya:

  • Semua suksesor dibandingkan, dan yang paling dekat dengan solusi yang dipilih.
  • Pada simple HC, simpul pertama yang lebih baik yang dipilih. Pada St-HC, simpul anak yang paling menguntungkan yang dipilih.

Algoritma Steepest Hill Climbing

1
Evaluasi keadaan awal

Jika keadaan awal sama dengan tujuan, berhenti. Jika tidak, jadikan keadaan awal sebagai current state.

2
Bangkitkan dan nilai semua successor

Dapatkan semua pewaris (successor) yang dapat menjadi next state dari current state, lalu beri nilai pada setiap successor dengan fungsi evaluasi.

3
Pilih yang paling baik

Jika ada successor yang lebih baik dari current state, jadikan successor dengan nilai paling baik sebagai current state yang baru.

4
Ulangi

Lakukan terus sampai current state = goal state (berhasil), atau sampai current state tidak berubah lagi (gagal: terjebak di optimum lokal atau dataran).

Contoh St-HC pada Problem 8-Puzzle Animasi

Bagaimana langkah St-HC-nya? Heuristik yang dipakai adalah jumlah jarak Manhattan. Untuk setiap ubin, hitung langkah mendatar ditambah langkah tegak menuju posisi tujuannya. Pada Start: ubin 8 berjarak 1, ubin 6 berjarak 2, ubin 5 berjarak 2, ubin lain 0, sehingga h = 5. Tentukan dulu successor Start beserta nilai h-nya sebelum menjalankan animasi.

Langkah demi langkah, h turun 5 → 4 → 3 → 2 → 1 → 0. Gerakan yang kembali ke keadaan sebelumnya tidak digambar. Semua successor yang tidak terpilih bernilai lebih buruk, sehingga pada soal ini St-HC tidak pernah terjebak. Solusinya 5 gerakan.

  8.         return success

  11.     reject all paths in C having loops

Sumber: Chowdhary, K. R. (2020). Fundamentals of Artificial Intelligence. Springer.

Bandingkan dengan GBFS (Algorithm 9.2). Perbedaan kuncinya di baris 13–14: hanya anak-anak simpul terakhir (C) yang diurutkan menurut heuristik, lalu ditaruh di depan Open. Isi Open lainnya tidak ikut diurutkan ulang. Perilakunya menjadi seperti DFS yang dipandu heuristik, sesuai dengan "variasi dari depth-first search". Versi Chowdhary ini masih dapat mundur ke simpul lain di Open, sedangkan hill climbing klasik (simple dan steepest) tidak menyimpan alternatif apa pun.

Implementasi Python Coba Sendiri

# Steepest-Ascent Hill Climbing pada 8-puzzle (slide 54).
# h(n) = total jarak Manhattan setiap ubin ke posisi tujuannya.
AWAL = (1, 2, 3,
        4, 8, 0,
        7, 6, 5)
TUJUAN = (1, 2, 3,
          4, 5, 6,
          7, 8, 0)
ARAH = [('atas', -1, 0), ('bawah', 1, 0), ('kiri', 0, -1), ('kanan', 0, 1)]


def geser(s, dr, dc):
    i = s.index(0)
    r, c = divmod(i, 3)
    r2, c2 = r + dr, c + dc
    if not (0 <= r2 < 3 and 0 <= c2 < 3):
        return None
    j = r2 * 3 + c2
    t = list(s)
    t[i], t[j] = t[j], t[i]
    return tuple(t)


def manhattan(s):
    total = 0
    for i, v in enumerate(s):
        if v != 0:
            j = TUJUAN.index(v)
            total += abs(i // 3 - j // 3) + abs(i % 3 - j % 3)
    return total


def teks(s):
    return ' / '.join(' '.join(str(v) if v else '_' for v in s[r:r + 3]) for r in (0, 3, 6))


sekarang, dilalui = AWAL, {AWAL}
print('Start :', teks(sekarang), ' h =', manhattan(sekarang))
while sekarang != TUJUAN:
    suksesor = []
    for arah, dr, dc in ARAH:
        t = geser(sekarang, dr, dc)
        if t is not None and t not in dilalui:     # jangan kembali ke keadaan lama
            suksesor.append((manhattan(t), arah, t))
    for nilai, arah, t in suksesor:
        print('    blank {:5s} -> {}  h = {}'.format(arah, teks(t), nilai))
    nilai, arah, terbaik = min(suksesor)          # bandingkan SEMUA suksesor
    if nilai >= manhattan(sekarang):
        print('Terjebak: tidak ada suksesor yang lebih baik.')
        break
    print('  pilih blank', arah, '-> h =', nilai)
    sekarang = terbaik
    dilalui.add(sekarang)
else:
    print('Goal tercapai.')

Latihan 4 Latihan

Gunakan metode Steepest Hill Climbing untuk menentukan rute yang harus dilalui dari S ke G pada graf Latihan 1, dengan jarak garis lurus ke G sebagai heuristik. Tuliskan semua successor beserta nilai h-nya pada setiap langkah.

Pelengkap: Simulated Annealing dan Generate and Test

Simulated Annealing (SA):

Untuk lolos dari optimum lokal, SA sesekali mengizinkan langkah yang memperburuk keadaan, dengan probabilitas yang menurun seiring "suhu" T yang mendingin. Di awal (T tinggi) agen bebas menjelajah; menjelang akhir (T rendah) agen berperilaku seperti hill climbing biasa. Idenya dari proses annealing (pendinginan lambat) pada logam.

P(terima langkah buruk) = e−ΔE / T

Generate and Test adalah metode paling sederhana: bangkitkan sebuah kandidat solusi (acak atau sistematis), lalu uji apakah ia solusi. Jika bukan, ulangi. Setara DFS jika pembangkitannya sistematis; setara pencarian acak jika tidak. Praktis hanya untuk ruang solusi kecil.

Eksplorasi lanjutan: AIMA Visualizations — Bab 4, bagian Local Search & Optimization: hill climbing yang bisa terjebak di maksimum lokal, simulated annealing dengan jadwal suhu, dan algoritma genetika (dibahas lagi pada Pertemuan 14). Bahasa Inggris.

Kapan memakai hill climbing?

Saat lintasan menuju solusi tidak penting (misalnya penjadwalan, penempatan komponen, penyetelan parameter, N-Queens), ruang keadaan sangat besar, dan solusi "cukup baik" sudah memadai. Untuk solusi yang dijamin optimal beserta lintasannya, tetap gunakan A*.

14. Perbandingan: Greedy BFS vs A* vs UCS vs Hill Climbing Ringkasan

Greedy Best-First

Fungsi evaluasi: f(n) = h(n)

Strategi: Selalu ke yang terlihat paling dekat ke tujuan

Kelengkapan: Tidak terjamin

Optimalitas: Tidak terjamin

Kecepatan: Sangat cepat jika heuristik baik

Cocok untuk: Situasi real-time di mana kecepatan lebih penting dari optimalitas

A*

Fungsi evaluasi: f(n) = g(n) + h(n)

Strategi: Seimbangkan biaya aktual dan estimasi sisa

Kelengkapan: Ya (b terhingga, h admissible)

Optimalitas: Ya (h admissible/konsisten)

Kecepatan: Tergantung kualitas heuristik

Cocok untuk: Navigasi, perencanaan jalur, game AI — butuh optimal

UCS g(n) O(bC*/ε) O(bC*/ε)
Greedy BFS h(n) O(bm) praktis ↓ O(bm)
A* g(n)+h(n) * O(bd) dengan h baik O(bd)

15. Rangkuman Pertemuan 5 & 6

Poin-poin Kunci:
  • Heuristik (dari heuriskein, "menemukan") adalah cara menerka langkah berikutnya. Dalam pencarian, heuristik berupa fungsi h(n): estimasi biaya dari simpul n ke tujuan.
  • Contoh heuristik: pada 8-puzzle, h₁ (ubin benar), h₂ (ubin salah), h₃ (total gerakan / Manhattan); pada peta, jarak garis lurus (SLD).
  • Heuristik diterima jika tidak melebihi biaya sebenarnya (admissible); heuristik yang baik mendekati biaya sebenarnya.
  • Greedy BFS: f(n) = h(n). Cepat, tetapi tidak optimal (Arad → Bucharest 450 km).
  • A*: f(n) = g(n) + h(n). Optimal jika h admissible (Arad → Bucharest 418 km). Uji tujuan saat simpul diambil dari Open, dan simpul di Closed dibuka kembali bila ditemukan jalur lebih murah.
  • Konsisten: h(n) ≤ c(n,a,n') + h(n'). Heuristik yang konsisten tidak pernah memaksa A* membuka kembali simpul.
  • Teknik desain heuristik: masalah yang dilonggarkan, maksimum beberapa heuristik, pattern database. Dominasi: heuristik yang lebih tajam mengekspansi lebih sedikit simpul.
  • Hill climbing hanya menyimpan satu keadaan. Simple HC mengambil tetangga pertama yang lebih baik; Steepest-Ascent HC mengambil tetangga terbaik. Keduanya bisa terjebak di optimum lokal, dataran, atau shoulder.
