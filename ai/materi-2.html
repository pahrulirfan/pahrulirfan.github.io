1. Konsep Ruang Keadaan Dasar

Banyak masalah AI dapat dimodelkan sebagai pencarian dalam sebuah ruang keadaan (state space) — yaitu kumpulan semua keadaan yang mungkin dicapai dari keadaan awal melalui serangkaian aksi.

Intuisi:

Bayangkan Anda mencari rute dari kota A ke kota B di peta. Setiap kota adalah sebuah keadaan, jalan yang menghubungkannya adalah aksi, dan peta seluruhnya adalah ruang keadaan. Tugas agen adalah menemukan urutan aksi yang membawa dari keadaan awal ke keadaan tujuan.

Empat Langkah Membangun Sistem AI berbasis Pencarian

1
Definisikan masalah dengan tepat

Tentukan keadaan awal, keadaan tujuan, dan batasan yang berlaku.

2
Analisis masalah & cari beberapa teknik penyelesaian

Perhatikan sifat ruang keadaan (besar/kecil, ada biaya/tidak, ada heuristik/tidak).

3
Representasikan pengetahuan untuk penyelesaian

Pilih representasi keadaan (larik, tuple, graf) dan definisikan aksi/aturan.

4
Pilih teknik penyelesaian terbaik

Bandingkan kelengkapan, optimalitas, dan kompleksitas tiap algoritma untuk masalah tersebut.

2. Formulasi Masalah sebagai Ruang Keadaan Inti

Setiap masalah pencarian harus diformulasikan secara formal melalui lima komponen berikut sebelum algoritma dapat diterapkan.

1
Keadaan Awal — Initial State s₀

Keadaan tempat agen memulai. Contoh 8-puzzle: susunan awal ubin.

2
Aksi — Actions(s)

Himpunan aksi yang dapat dilakukan dari keadaan s. Contoh: geser ubin ke atas/bawah/kiri/kanan.

3
Model Transisi — Result(s, a)

Keadaan baru yang dihasilkan dari melakukan aksi a di keadaan s. Mendefinisikan sepenuhnya ruang keadaan.

4
Uji Tujuan — Goal-Test(s)

Fungsi yang mengembalikan true jika s adalah keadaan tujuan. Bisa berupa keadaan tunggal atau himpunan keadaan.

5
Biaya Lintasan — Path Cost

Fungsi yang memberikan nilai numerik pada setiap lintasan. Biasanya: jumlah biaya tiap langkah. Contoh: jarak tempuh, jumlah gerakan.

Implementasi Antarmuka Masalah (Python)

class Problem:
    """Antarmuka abstrak untuk masalah pencarian."""

    def __init__(self, initial, goal=None):
        self.initial = initial   # keadaan awal
        self.goal    = goal      # keadaan tujuan (tunggal atau himpunan)

    def actions(self, state):
        """Kembalikan daftar aksi yang dapat dilakukan di 'state'."""
        raise NotImplementedError

    def result(self, state, action):
        """Kembalikan keadaan baru setelah melakukan 'action' di 'state'."""
        raise NotImplementedError

    def is_goal(self, state):
        """Kembalikan True jika 'state' adalah tujuan."""
        return state == self.goal

    def step_cost(self, state, action, next_state):
        """Biaya satu langkah. Default = 1."""
        return 1


class Node:
    """Simpul dalam pohon pencarian."""

    def __init__(self, state, parent=None, action=None, path_cost=0):
        self.state     = state
        self.parent    = parent    # simpul induk
        self.action    = action    # aksi yang menghasilkan simpul ini
        self.path_cost = path_cost # biaya dari akar ke simpul ini
        self.depth     = 0 if parent is None else parent.depth + 1

    def expand(self, problem):
        """Bangkitkan semua simpul anak."""
        return [
            Node(
                state     = problem.result(self.state, a),
                parent    = self,
                action    = a,
                path_cost = self.path_cost + problem.step_cost(self.state, a, problem.result(self.state, a))
            )
            for a in problem.actions(self.state)
        ]

    def solution(self):
        """Kembalikan urutan aksi dari akar ke simpul ini."""
        path = []
        node = self
        while node.parent:
            path.append(node.action)
            node = node.parent
        return path[::-1]

3. Pohon Pencarian vs Graf Pencarian Konsep

Aspek Pohon Pencarian Graf Pencarian
Definisi Ekspansi keadaan tanpa melacak keadaan yang sudah dikunjungi Melacak semua keadaan yang sudah dikunjungi (explored set)
Siklus Bisa terjebak loop tak hingga Aman dari siklus, tidak mengekspansi ulang
Memori Lebih hemat (tidak simpan explored set) Butuh memori lebih untuk explored set
Kelengkapan Tidak terjamin jika ada siklus Lebih terjamin selama ruang keadaan terhingga
Digunakan oleh DFS naif BFS, UCS, A* (standar)
Siklus adalah musuh utama DFS!

Pada graf pencarian, DFS dapat masuk ke dalam siklus A→B→A→B→... tanpa batas. Solusinya: gunakan explored set (biasa disebut closed list) untuk mencatat keadaan yang sudah diekspansi.

Membentang Graf Keadaan menjadi Pohon Pelacakan

Sebuah graf keadaan menggambarkan seluruh keadaan dan transisinya. Ketika algoritma menelusurinya, ia membentuk pohon pelacakan (search tree) — sebuah keadaan yang dapat dicapai lewat beberapa lintasan akan muncul beberapa kali sebagai simpul berbeda.

Dari graf di atas (awal M, tujuan T), lintasan yang mungkin:

JenisLintasan
Sampai ke tujuanM-A-B-C-E-T · M-A-B-C-E-H-T · M-D-C-E-T · M-D-C-E-H-T
Jalan buntu (dead end)M-A-B-C-E-F-G · M-A-B-C-E-I-J · M-D-I-J

Perhatikan simpul C dan E muncul di banyak lintasan — pada pohon pelacakan keduanya diduplikasi. Inilah alasan explored set (graf pencarian) menghemat pekerjaan.

Pohon AND/OR (Reduksi Masalah)

Pada pohon pencarian biasa (pohon OR), sebuah simpul terpecahkan jika salah satu anaknya terpecahkan. Pada pohon AND, sebuah simpul terpecahkan hanya jika semua anaknya terpecahkan — dipakai saat sebuah masalah harus dipecah menjadi beberapa sub-masalah yang semuanya wajib diselesaikan.

Simpul OR

"M dapat dicapai lewat A atau B atau C." Cukup satu cabang berhasil.

Simpul AND

"Untuk menyelesaikan M, harus menyelesaikan A dan B dan C." Semua cabang wajib berhasil (ditandai busur melengkung antar-cabang).

Contoh:

"Membangun rumah" = AND(pondasi, dinding, atap). "Pergi ke kampus" = OR(naik motor, naik angkot, jalan kaki). Pohon AND/OR menjadi dasar problem reduction dan perencanaan hierarkis.

5. Breadth-First Search (BFS) Algoritma

BFS mengekspansi simpul secara melebar — semua simpul pada kedalaman d diekspansi sebelum simpul pada kedalaman d+1. BFS menggunakan struktur data antrian FIFO (First In First Out).

Intuisi:

Seperti gelombang air yang menyebar dari titik tengah — semua posisi berjarak 1 dicapai dulu, lalu jarak 2, dst. BFS menjamin solusi terpendek dalam hal jumlah langkah.

Pseudocode BFS

function BFS(problem) returns node | failure
    node     ← Node(problem.initial)
    if problem.is_goal(node.state): return node
    frontier ← Queue()          -- antrian FIFO
    frontier.enqueue(node)
    explored ← set()            -- explored set (closed list)

    loop:
        if frontier.is_empty(): return failure
        node ← frontier.dequeue()
        explored.add(node.state)

        for child in node.expand(problem):
            if child.state not in explored and child.state not in frontier:
                if problem.is_goal(child.state): return child
                frontier.enqueue(child)

6. Depth-First Search (DFS) & Depth-Limited Search (DLS) Algoritma

DFS mengekspansi simpul secara mendalam — selalu mengekspansi simpul paling dalam di frontier. DFS menggunakan struktur data tumpukan LIFO (Last In First Out), atau memanfaatkan rekursi.

Pseudocode DFS (Rekursif)

function DFS-RECURSIVE(problem, node) returns node | failure
    if problem.is_goal(node.state): return node
    for child in node.expand(problem):
        result ← DFS-RECURSIVE(problem, child)
        if result is not failure: return result
    return failure

-- Pemanggilan awal:
DFS-RECURSIVE(problem, Node(problem.initial))

Sifat DFS

Kelengkapan
Tidak

Bisa terjebak di cabang tak hingga atau siklus.

Optimalitas
Tidak

Solusi yang ditemukan bisa bukan yang terpendek.

Waktu
O(bm)

Bisa jauh lebih buruk dari BFS jika solusi dangkal.

Ruang
O(b·m)

Keunggulan utama DFS! Hanya menyimpan satu lintasan aktif + saudara.

Depth-Limited Search (DLS)

DLS adalah DFS dengan batas kedalaman ℓ yang eksplisit. Simpul pada kedalaman ℓ tidak diekspansi lebih lanjut (dianggap sebagai simpul daun).

function DLS(problem, limit) returns node | failure | cutoff
    return DLS-RECURSIVE(Node(problem.initial), problem, limit)

function DLS-RECURSIVE(node, problem, limit) returns node | failure | cutoff
    if problem.is_goal(node.state): return node
    if limit == 0:               return "cutoff"  -- batas kedalaman tercapai
    cutoff_occurred ← False
    for child in node.expand(problem):
        result ← DLS-RECURSIVE(child, problem, limit - 1)
        if result == "cutoff": cutoff_occurred ← True
        elif result is not failure: return result
    if cutoff_occurred: return "cutoff"
    return failure
Masalah DLS:

Pemilihan batas ℓ sangat kritis. Jika ℓ < d (terlalu dangkal), solusi tidak akan ditemukan. Jika ℓ ≫ d, boros komputasi. Solusi: gunakan IDS!

Backtracking — DFS sebagai Metode Pemecahan Masalah

Backtracking (runut-balik) adalah DFS yang dipakai sebagai strategi pemecahan masalah terstruktur: bangun solusi selangkah demi selangkah; begitu sebuah pilihan terbukti buntu, batalkan pilihan itu (unmove) dan coba pilihan lain.

Contoh: Mencari jalan keluar labirin (Maze Problem)

Pada tiap persimpangan ada tiga pilihan: lurus, belok kiri, belok kanan. Anda tidak punya cukup informasi untuk memilih yang benar — jadi coba satu, jika buntu mundur dan coba yang lain.

function SOLVE-MAZE(M) returns boolean
    if posisi sekarang == pintu keluar: return True
    for arah in [lurus, kiri, kanan]:
        MOVE(M, arah)                -- maju satu sel
        if SOLVE-MAZE(M): return True
        UNMOVE(M, arah)              -- backtrack: batalkan langkah
    return False                       -- semua arah buntu
Contoh lain: Sudoku

Isi sel kosong dengan angka 1. Periksa apakah melanggar aturan baris/kolom/kotak. Jika tidak, lanjut ke sel berikutnya; jika melanggar, coba 2, 3, dst. Bila 1–9 semua gagal, kosongkan sel dan mundur ke sel sebelumnya, naikkan nilainya. Ulangi hingga 81 sel terisi benar. Aturan pembentukan simpulnya adalah DFS.

7. Iterative Deepening Search (IDS) Algoritma

IDS menggabungkan keunggulan BFS (kelengkapan, optimalitas) dengan keunggulan DFS (hemat memori) dengan cara menjalankan DLS berulang kali dengan batas kedalaman yang terus meningkat: ℓ = 0, 1, 2, 3, …

Pseudocode IDS

function ITERATIVE-DEEPENING-SEARCH(problem) returns node | failure
    for depth in range(0, ∞):
        result ← DLS(problem, limit=depth)
        if result != "cutoff":
            return result  -- bisa berupa solusi atau failure

Kelengkapan
Ya

Optimalitas
Ya*

Optimal jika biaya langkah seragam (seperti BFS).

IDS adalah algoritma pencarian buta yang direkomendasikan secara umum karena menggabungkan kelengkapan dan optimalitas BFS dengan efisiensi memori DFS. Untuk ruang keadaan besar tanpa informasi heuristik, IDS adalah pilihan pertama.

8. Uniform Cost Search (UCS) Algoritma

UCS memperluas BFS untuk menangani biaya langkah yang berbeda-beda. UCS mengekspansi simpul berdasarkan biaya lintasan terendah g(n) menggunakan antrian prioritas.

Hubungan dengan BFS:

Jika semua biaya langkah bernilai 1, UCS identik dengan BFS. UCS adalah generalisasi BFS untuk biaya tidak seragam.

Pseudocode UCS

function UNIFORM-COST-SEARCH(problem) returns node | failure
    node     ← Node(problem.initial, path_cost=0)
    frontier ← PriorityQueue(key=lambda n: n.path_cost)
    frontier.insert(node)
    explored ← set()

    loop:
        if frontier.is_empty(): return failure
        node ← frontier.pop_min()       -- ambil simpul dengan g(n) terkecil
        if problem.is_goal(node.state): return node
        explored.add(node.state)

        for child in node.expand(problem):
            if child.state not in explored:
                if child.state not in frontier:
                    frontier.insert(child)
                elif frontier[child.state].path_cost > child.path_cost:
                    frontier.replace(child)  -- update jika lebih murah

Pada UCS, uji tujuan dilakukan saat simpul diekspansi (diambil dari frontier), bukan saat dibangkitkan. Ini penting untuk memastikan optimalitas — kita harus yakin tidak ada lintasan yang lebih murah.

Pencarian Dua Arah (Bidirectional Search / BDS)

BDS menjalankan dua pencarian sekaligus: satu maju dari keadaan awal, satu mundur dari keadaan tujuan. Pencarian berhenti ketika kedua frontier bertemu pada keadaan yang sama; solusi diperoleh dengan menyambung kedua lintasan.

Mengapa lebih cepat?

Dua pohon berkedalaman d/2 jauh lebih kecil daripada satu pohon berkedalaman d: O(bd/2) + O(bd/2) jauh lebih kecil dari O(bd). Syaratnya: aksi harus bisa dibalik (untuk pencarian mundur) dan keadaan tujuan harus diketahui secara eksplisit.

Kapan Menggunakan Apa?

Gunakan BFS

Solusi dangkal, semua biaya sama, memori tidak terbatas.

Gunakan DFS

Solusi dalam, memori sangat terbatas, tidak peduli optimalitas.

Gunakan IDS

Solusi dangkal, memori terbatas, butuh kelengkapan dan optimalitas.

Gunakan UCS

Biaya langkah berbeda-beda, butuh solusi biaya optimal.

10. Rangkuman Pertemuan 3 & 4

Poin-poin Kunci:
  • Masalah pencarian diformulasikan dengan 5 komponen: keadaan awal, aksi, model transisi, uji tujuan, biaya lintasan.
  • Pohon pencarian tidak melacak keadaan yang dikunjungi — rawan siklus. Graf pencarian menggunakan explored set.
  • Empat ukuran kinerja: kelengkapan, optimalitas, kompleksitas waktu, kompleksitas ruang.
  • BFS: lengkap + optimal (biaya sama), tapi boros memori O(bd+1).
  • DFS: hemat memori O(b·m), tapi tidak lengkap dan tidak optimal.
  • DLS: DFS berkedalaman terbatas — perlu memilih batas ℓ yang tepat.
  • IDS: menggabungkan terbaik BFS dan DFS — lengkap, optimal*, dan hemat memori O(b·d). Rekomendasi default.
  • UCS: menjamin solusi biaya terendah untuk biaya langkah yang berbeda-beda.
  • BDS (dua arah): mencari maju dari awal dan mundur dari tujuan sekaligus — O(bd/2), tapi butuh aksi yang dapat dibalik.
  • Backtracking adalah DFS sebagai strategi pemecahan masalah (labirin, Sudoku, N-Queen).
  • Pohon AND/OR: simpul OR butuh salah satu anak berhasil; simpul AND butuh semua anak berhasil (reduksi masalah).
